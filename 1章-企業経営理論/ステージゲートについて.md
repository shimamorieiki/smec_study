# ステージゲートについて

## 概要
ステージゲートとは、新製品開発やプロジェクト管理において、開発プロセスを複数のステージ（段階）に分割し、各ステージの終了時点でゲート（評価ポイント）を設けて、次のステージへの移行可否を判断する管理手法です。1980年代にロバート・G・クーパー博士によって体系化され、現在では多くの企業で採用されている標準的なイノベーション管理手法となっています。

## 1. ステージゲートの基本概念・定義

### ステージゲートプロセスの構造
- **定義**: 新製品開発プロセスを論理的に区切られた複数のステージと、各ステージ間の意思決定ポイントであるゲートから構成される体系的な管理手法
- **特徴**: リスクの段階的な低減、資源の効率的配分、開発の可視化と標準化
- **重要性**: 開発の成功率向上、市場投入までの時間短縮、投資対効果の最大化

### ステージ（Stage）
- **定義**: プロジェクトの実行段階であり、情報収集、分析、開発活動が行われる期間
- **特徴**: 並行して複数の活動が実施され、次のゲートで評価される成果物を作成
- **重要性**: 体系的な活動により、必要な情報と成果物を確実に生成

### ゲート（Gate）
- **定義**: 品質管理のチェックポイントであり、プロジェクトの継続・中止・修正を決定する意思決定会議
- **特徴**: 事前に定められた評価基準に基づく客観的な判断、経営層による承認
- **重要性**: 不適切なプロジェクトの早期中止により、資源の無駄遣いを防止

## 2. ステージゲートの分類・種類

### 標準的な5ステージモデル
ステージゲートプロセスは、企業や業界によってカスタマイズされますが、最も一般的な5ステージモデルは以下の通りです。

### ステージ0: 発見（Discovery）
| 項目 | 内容 |
|------|------|
| 特徴 | アイデア創出と機会の発見 |
| 適用範囲 | 市場調査、技術探索、顧客ニーズ分析 |
| 注意点 | 創造性を阻害しない柔軟な運用が必要 |

### ステージ1: スコーピング（Scoping）
| 項目 | 内容 |
|------|------|
| 特徴 | 初期的な市場・技術評価 |
| 適用範囲 | 簡易的な市場調査、技術的実現可能性の検討 |
| 注意点 | 限られた資源で効率的な情報収集が重要 |

### ステージ2: ビジネスケース構築（Build Business Case）
| 項目 | 内容 |
|------|------|
| 特徴 | 詳細な事業計画の作成 |
| 適用範囲 | 市場分析、競合分析、財務分析、リスク評価 |
| 注意点 | 客観的なデータに基づく現実的な計画策定 |

### ステージ3: 開発（Development）
| 項目 | 内容 |
|------|------|
| 特徴 | 実際の製品開発とテスト計画の策定 |
| 適用範囲 | 設計、プロトタイプ作成、生産準備 |
| 注意点 | 技術的課題の解決と品質確保 |

### ステージ4: テストと検証（Testing & Validation）
| 項目 | 内容 |
|------|------|
| 特徴 | 製品・市場・生産の検証 |
| 適用範囲 | 製品テスト、顧客テスト、試験販売、生産テスト |
| 注意点 | 客観的な評価と改善点の明確化 |

### ステージ5: 上市（Launch）
| 項目 | 内容 |
|------|------|
| 特徴 | 本格的な市場投入 |
| 適用範囲 | 生産開始、マーケティング展開、販売開始 |
| 注意点 | 市場反応の継続的モニタリング |

## 3. 具体的計算例・事例

### ケース1: 医薬品開発プロジェクトのステージゲート適用

#### 前提条件
- 新薬開発プロジェクト
- 初期投資額: 1億円
- 各ステージの成功確率と必要投資額

| ステージ | 成功確率 | 必要投資額 | 期待収益（成功時） |
|----------|----------|------------|------------------|
| 基礎研究 | 30% | 1億円 | - |
| 前臨床試験 | 50% | 3億円 | - |
| 臨床試験Phase1 | 70% | 5億円 | - |
| 臨床試験Phase2 | 60% | 10億円 | - |
| 臨床試験Phase3 | 80% | 20億円 | - |
| 承認・上市 | 90% | 5億円 | 500億円 |

#### パターンA: 全ステージ成功の場合
- **累積投資額**: 1 + 3 + 5 + 10 + 20 + 5 = 44億円
- **成功確率**: 0.3 × 0.5 × 0.7 × 0.6 × 0.8 × 0.9 = 0.045 (4.5%)
- **期待収益**: 500億円 × 0.045 = 22.5億円
- **期待利益**: 22.5億円 - 44億円 = -21.5億円

#### パターンB: ステージ2（前臨床試験）で中止の場合
- **累積投資額**: 1 + 3 = 4億円
- **損失額**: 4億円（ただし、以降の36億円の投資を回避）
- **判断の妥当性**: 早期中止により大きな損失を回避

### ケース2: IT システム開発プロジェクト

#### 前提条件
- ECサイト構築プロジェクト
- 予定期間: 12ヶ月
- 予算: 5,000万円

#### ゲート評価基準の例

**ゲート1（企画承認）**
- 市場規模: 100億円以上
- ROI: 3年以内に150%以上
- 技術的実現可能性: 既存技術で対応可能
- リスク評価: 中程度以下

**ゲート2（設計承認）**
- 要件定義完了度: 100%
- 設計レビュー合格: 指摘事項すべて対応済み
- 予算消化率: 計画の±10%以内
- スケジュール遵守率: 95%以上

**ゲート3（開発完了）**
- 機能実装率: 95%以上
- 品質基準達成: 重大バグ0件、中程度バグ5件以下
- 性能要件達成: レスポンスタイム3秒以内
- セキュリティ監査: 合格

## 4. ゲート評価プロセスの詳細

### ゲートミーティングの流れ
1. **プレゼンテーション（30分）**: 
   - プロジェクトチームによる成果報告
   - 必要な成果物の提示
   - 次ステージの計画説明

2. **質疑応答（20分）**: 
   - ゲートキーパーからの質問
   - 追加情報の要求
   - リスクや懸念事項の確認

3. **評価・討議（30分）**: 
   - 評価基準に基づく採点
   - メンバー間での意見交換
   - 総合的な判断

4. **意思決定（10分）**: 
   - Go（続行）/ Kill（中止）/ Hold（保留）/ Recycle（やり直し）の決定
   - 条件付き承認の場合は条件の明確化
   - 次回ゲートまでの指示事項

### ゲート評価基準の種類
- **Must Meet Criteria（必須基準）**: 一つでも満たさない場合は不合格
- **Should Meet Criteria（推奨基準）**: 総合的に判断
- **Scoring Model（スコアリングモデル）**: 重み付けされた点数による評価

## 5. 実務上の注意点

### ステージゲート導入時の重要ポイント
- **ポイント1**: 経営層の強いコミットメントと継続的な関与が不可欠
- **ポイント2**: 形式的な運用ではなく、実質的な意思決定の場として機能させる
- **ポイント3**: プロジェクトの特性に応じた柔軟なカスタマイズを行う
- **ポイント4**: ゲートキーパーの適切な選定と権限付与
- **ポイント5**: 明確で客観的な評価基準の設定と継続的な改善

### よくある誤解・トラブル
- **誤解1**: すべてのプロジェクトに同じステージゲートを適用すべき
  - **正しい理解**: プロジェクトの規模や性質に応じて、ステージ数や評価基準を調整する必要がある

- **誤解2**: ゲートは単なる進捗報告会議である
  - **正しい理解**: ゲートは重要な意思決定の場であり、プロジェクトの中止も含めた判断を行う

- **誤解3**: 一度Goの判断が出れば、次のゲートまで自由に進められる
  - **正しい理解**: 重大な環境変化があれば、臨時ゲートを設けて再評価する必要がある

## 6. よくある質問（Q&A）

### Q1. 小規模プロジェクトでもステージゲートは必要ですか？

**A1.** 小規模プロジェクトでは、簡略化されたステージゲート（ステージゲートライト）の適用が推奨されます。

#### 簡略化の例
- **フルモデル（5ステージ）** → **ライトモデル（3ステージ）**
  - ステージ1: アイデア評価と簡易事業計画
  - ステージ2: 開発とテスト
  - ステージ3: 市場投入
- **評価基準の簡素化**: 必須項目のみに絞る
- **ゲートミーティングの短縮**: 30分程度で実施
- **文書化の軽減**: 必要最小限の成果物のみ要求

### Q2. ゲートでKill判断をする際の基準は？

**A2.** Kill判断は以下の状況で検討されます。

#### Kill判断の主な基準
1. **市場環境の大幅な変化**: 競合他社の先行、市場規模の縮小
2. **技術的な実現困難**: 克服不可能な技術的課題の発覚
3. **財務的な理由**: ROIの大幅な悪化、予算の大幅超過
4. **戦略との不整合**: 企業戦略の変更によるプロジェクトの位置づけ変化
5. **リソースの制約**: より優先度の高いプロジェクトへの資源配分

### Q3. アジャイル開発とステージゲートは併用できますか？

**A3.** はい、併用可能です。ハイブリッドアプローチとして多くの企業で採用されています。

#### 併用方法の例
- **マクロレベル**: ステージゲートで全体管理
- **ミクロレベル**: 各ステージ内でアジャイル手法を適用
- **ゲートの柔軟化**: スプリントレビューをミニゲートとして活用
- **評価基準の調整**: 動作するソフトウェアのデモを重視

## 7. まとめ・今後の展望

ステージゲートは、新製品開発やプロジェクト管理において、リスクを管理しながら効率的に資源を配分するための重要な手法です。適切に運用することで、プロジェクトの成功率向上、開発期間の短縮、投資効率の改善が期待できます。

今後は、デジタルトランスフォーメーション（DX）の進展により、AIやビッグデータを活用したより高度な意思決定支援や、リアルタイムでのプロジェクト評価など、ステージゲートプロセス自体の進化が予想されます。また、アジャイル開発手法との融合により、より柔軟で迅速な製品開発プロセスの確立が進むでしょう。

- **意味**: ステージゲートにおけるゲートミーティングのこと。プロジェクトの継続可否を決定する重要な会議

### か行

**簡易事業計画（かんいじぎょうけいかく）**
- **読み方**: かんいじぎょうけいかく

- **関連用語**: スコーピング、ビジネスケース

**ゲート（げーと）**
- **読み方**: げーと
- **意味**: ステージゲートプロセスにおける評価・意思決定ポイント。各ステージの終了時に設けられ、次ステージへの移行可否を判断
- **関連用語**: ゲートミーティング、ゲートキーパー、評価基準

**ゲートキーパー（げーときーぱー）**
- **読み方**: げーときーぱー
- **意味**: ゲートでの意思決定権限を持つ経営層や上級管理職。客観的な評価基準に基づいてプロジェクトの継続可否を判断する責任者
- **関連用語**: ゲート、意思決定者

**ゲートミーティング（げーとみーてぃんぐ）**
- **読み方**: げーとみーてぃんぐ
- **意味**: 各ゲートで開催される評価会議。プロジェクトチームによるプレゼンテーション、質疑応答、評価、意思決定が行われる
- **関連用語**: ゲート、レビュー会議

### さ行

**スコーピング（すこーぴんぐ）**
- **読み方**: すこーぴんぐ
- **意味**: ステージ1で行われる初期評価活動。限られた資源で効率的に市場性と技術的実現可能性を評価する段階
- **関連用語**: 初期評価、簡易調査

**ステージ（すてーじ）**
- **読み方**: すてーじ
- **意味**: プロジェクトの実行段階。情報収集、分析、開発活動が並行して行われ、次のゲートで評価される成果物を作成する期間
- **関連用語**: フェーズ、開発段階

**ステージゲート（すてーじげーと）**
- **読み方**: すてーじげーと
- **意味**: 新製品開発プロセスを複数のステージに分割し、各ステージ間にゲート（評価ポイント）を設けて管理する体系的な手法
- **関連用語**: Stage-Gate®、フェーズゲート

**ステージゲートライト（すてーじげーとらいと）**
- **読み方**: すてーじげーとらいと
- **意味**: 小規模プロジェクト向けに簡略化されたステージゲートプロセス。ステージ数や評価基準を削減して効率化
- **関連用語**: 簡易版ステージゲート

**成功確率（せいこうかくりつ）**
- **読み方**: せいこうかくりつ
- **意味**: 各ステージを成功裏に完了できる確率。過去のデータや業界標準に基づいて設定され、投資判断の重要な指標
- **関連用語**: リスク評価、確率分析

### た行

**中止判断（ちゅうしはんだん）**
- **読み方**: ちゅうしはんだん
- **意味**: ゲートでプロジェクトを終了させる決定（Kill判断）。市場性の喪失、技術的困難、戦略との不整合などが理由

- **関連用語**: 評価指標、判断基準

- **意味**: Must Meet Criteriaのこと。ゲート通過のために必ず満たさなければならない評価基準

- **読み方**: ごーはんだん
- **意味**: ゲートでプロジェクトの次ステージへの移行を承認する決定

- **読み方**: ほーるどはんだん

- **関連用語**: 条件付き承認、保留

- **読み方**: きるはんだん
- **意味**: プロジェクトを中止する決定。投資の継続が正当化できない場合に下される
- **関連用語**: 中止、プロジェクト終了

- **読み方**: ますとみーとくらいてりあ

- **関連用語**: 投資対効果、収益性

- **関連用語**: 推奨基準、望ましい要件

- **関連用語**: ステージゲート、フェーズゲート
