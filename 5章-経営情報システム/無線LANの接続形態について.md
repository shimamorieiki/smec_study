# 無線LANの接続形態について

## 概要
無線LAN（Wireless Local Area Network）は、電波を使用してデバイス間でデータ通信を行うネットワーク技術です。ケーブルを使用せずにネットワークを構築できるため、柔軟性と利便性に優れています。無線LANには複数の接続形態があり、それぞれ異なる特徴と用途を持っています。

## 1. 基本概念・仕組み

### 無線LANの基本原理
- **定義**: IEEE 802.11規格に基づく無線通信技術を使用したローカルエリアネットワーク
- **動作原理**: 2.4GHzまたは5GHz（最新規格では6GHz）の電波を使用してデータを送受信
- **特徴**: 物理的なケーブル接続が不要で、一定範囲内での移動が可能

### 接続形態の重要性
- **ネットワーク設計**: 用途に応じた最適な構成の選択が可能
- **拡張性**: 将来的な拡張や変更に対応しやすい
- **コスト効率**: 適切な接続形態の選択により、コストを最適化

## 2. 種類・分類

### 主要な接続形態

### アドホックモード（Ad-hoc Mode）
**特徴:**
- デバイス同士が直接通信する方式
- アクセスポイント（AP）を必要としない
- ピア・ツー・ピア（P2P）接続とも呼ばれる

**📊 具体的な設定例**
**例: ノートPC2台の直接接続**
- PC1のIPアドレス: 192.168.1.1
- PC2のIPアドレス: 192.168.1.2
- サブネットマスク: 255.255.255.0

**ステップ1: ネットワークの作成**
```
PC1: ワイヤレスネットワークの作成
- SSID: AdHocNetwork
- セキュリティ: WPA2-PSK
- パスワード: SecurePass123
```

**ステップ2: 接続確認**
```
PC2: 利用可能なネットワークから「AdHocNetwork」を選択
- パスワード入力: SecurePass123
- 接続完了後、ping 192.168.1.1で疎通確認
```

**結果: 2台のPC間で直接ファイル共有や通信が可能**

💡 **実際の現場では**: 臨時の会議や現場作業で、インフラがない環境での一時的なファイル共有に使用

### インフラストラクチャモード（Infrastructure Mode）
**特徴:**
- アクセスポイント（AP）を中心とした星型構成
- 最も一般的な無線LAN接続形態
- 複数のクライアントが同時接続可能

**📊 具体的な構成例**
**例: オフィス環境での無線LAN構築**
- アクセスポイント: 192.168.1.1
- DHCPプール: 192.168.1.100～192.168.1.200
- 接続デバイス数: 最大50台

**ステップ1: APの設定**
```
アクセスポイント設定:
- SSID: OfficeWiFi
- チャンネル: 6（2.4GHz）
- 帯域幅: 20MHz
- セキュリティ: WPA3-Enterprise
```

**ステップ2: クライアント接続**
```
各デバイス:
- SSID選択: OfficeWiFi
- 認証方式: EAP-TLS
- 証明書による認証
```

**結果: 全デバイスがインターネットおよび社内リソースにアクセス可能**

💡 **実際の現場では**: オフィス、家庭、公共施設など、ほぼすべての無線LAN環境で採用

### WDS（Wireless Distribution System）
**特徴:**
- 複数のアクセスポイント間を無線で接続
- 有線LANの延長として機能
- ブリッジモードとも呼ばれる

**算出方法:**
```
カバレッジエリア = 基本AP範囲 + (リピーターAP数 × 拡張範囲)
例: 100㎡ + (3台 × 80㎡) = 340㎡
```

### メッシュネットワーク（Mesh Network）
**特徴:**
- 各ノードが相互に接続
- 自己修復機能を持つ
- 動的ルーティングによる最適経路選択

**📊 具体的な計算例**
**例: 3階建てビルのメッシュネットワーク設計**
- 各階面積: 200㎡
- 必要AP数の計算:

**ステップ1: カバレッジ計算**
```
1台のAPカバレッジ: 約100㎡（障害物考慮）
必要AP数 = 総面積 ÷ APカバレッジ
         = 600㎡ ÷ 100㎡
         = 6台（各階2台）
```

**ステップ2: バックホール帯域計算**
```
総帯域需要: 1Gbps
メッシュホップ数: 最大2ホップ
必要バックホール帯域 = 1Gbps × 1.5（オーバーヘッド）
                   = 1.5Gbps
```

**結果: 6台のメッシュAPで全館をカバー、冗長性も確保**

## 3. 詳細仕様・パラメータ

### 重要な設定パラメータ

#### SSIDの詳細
- **意味**: Service Set Identifierの略、ネットワーク識別子
- **設定範囲**: 最大32文字（ASCII）
- **影響**: ネットワークの識別と選択に使用
- **推奨値**: 意味のある名前だが、組織名や場所を特定されない文字列

#### チャンネル設定の詳細
- **意味**: 使用する周波数帯域の指定
- **設定範囲**: 
  - 2.4GHz: 1-14ch（日本では1-13ch）
  - 5GHz: 36-64ch, 100-140ch（W52, W53, W56）
- **影響**: 干渉回避と通信品質
- **推奨値**: 2.4GHzでは1, 6, 11ch（非重複チャンネル）

## 4. 実装例・適用事例

### 基本実装（Pythonでのアドホックネットワーク監視）
```python
import subprocess
import re

def check_adhoc_network():
    """アドホックネットワークの状態を確認"""
    try:
        # Windows用コマンド例
        result = subprocess.run(['netsh', 'wlan', 'show', 'networks'], 
                              capture_output=True, text=True)
        
        # アドホックネットワークを検索
        adhoc_pattern = r'SSID \d+ : (.+)\n.*Network type\s+:\s+Adhoc'
        matches = re.findall(adhoc_pattern, result.stdout, re.MULTILINE)
        
        if matches:
            print(f"検出されたアドホックネットワーク: {matches}")
        else:
            print("アドホックネットワークは検出されませんでした")
            
        return matches
        
    except Exception as e:
        print(f"エラー: {e}")
        return []

# 実行
adhoc_networks = check_adhoc_network()
```

### 応用実装（インフラストラクチャモードの帯域監視）
```python
import psutil
import time

class WiFiMonitor:
    def __init__(self, interface_name):
        self.interface = interface_name
        self.last_bytes = self.get_bytes()
        
    def get_bytes(self):
        """現在の送受信バイト数を取得"""
        stats = psutil.net_io_counters(pernic=True)
        if self.interface in stats:
            return stats[self.interface].bytes_sent + stats[self.interface].bytes_recv
        return 0
    
    def get_bandwidth(self, interval=1):
        """帯域使用量を計算（Mbps）"""
        current_bytes = self.get_bytes()
        bytes_diff = current_bytes - self.last_bytes
        bandwidth_mbps = (bytes_diff * 8) / (interval * 1000000)
        self.last_bytes = current_bytes
        return bandwidth_mbps
    
    def monitor(self, duration=60):
        """指定時間の帯域使用量を監視"""
        print(f"{self.interface}の帯域監視を開始...")
        start_time = time.time()
        
        while time.time() - start_time < duration:
            bandwidth = self.get_bandwidth()
            print(f"現在の帯域使用量: {bandwidth:.2f} Mbps")
            time.sleep(1)

# 使用例
monitor = WiFiMonitor("Wi-Fi")  # インターフェース名は環境に応じて変更
monitor.monitor(30)  # 30秒間監視
```

### 実際の適用事例

#### 事例1: 災害対策本部での臨時ネットワーク構築
- **課題**: 地震により有線インフラが損傷、緊急通信網が必要
- **適用方法**: アドホックモードで複数のノートPCを接続、臨時情報共有システムを構築
- **結果**: 15分以内に10台のPCで情報共有網を確立
- **効果**: 迅速な情報収集と対策指示が可能に

#### 事例2: 大規模イベント会場でのWiFi提供
- **課題**: 5,000人規模のイベントで安定したWiFi提供が必要
- **適用方法**: メッシュネットワークで20台のAPを設置、動的負荷分散を実装
- **結果**: 同時接続数3,000台で平均速度20Mbpsを維持
- **効果**: 参加者満足度95%以上、SNS投稿による宣伝効果も向上

## 5. メリット・デメリット

### メリット

**1. 柔軟性の向上**
- **理由**: 物理的な配線が不要で、レイアウト変更が容易
- **効果**: オフィスレイアウト変更時のコスト削減（平均70%削減）
- **具体例**: フリーアドレスオフィスでの座席変更が即座に対応可能

**2. 初期投資の削減**
- **理由**: ケーブル敷設工事が不要
- **効果**: 導入コスト30-50%削減
- **具体例**: 100席のオフィスで約200万円の配線工事費を削減

**3. スケーラビリティ**
- **理由**: APの追加により簡単に拡張可能
- **効果**: 段階的な投資で成長に対応
- **具体例**: スタートアップ企業が10人から100人規模に成長する際も柔軟に対応

### デメリット

**1. セキュリティリスク**
- **理由**: 電波の傍受が物理的に可能
- **影響**: 不正アクセスや情報漏洩のリスク
- **対策**: WPA3暗号化、VPN併用、定期的なセキュリティ監査

**2. 干渉と不安定性**
- **理由**: 他の電波源との干渉
- **影響**: 通信速度低下や接続断
- **対策**: 5GHz帯の活用、チャンネル設計の最適化、DFS機能の活用

**3. 有線LANと比較した速度制限**
- **理由**: 共有メディアであり、プロトコルオーバーヘッドが存在
- **影響**: 大容量データ転送時の処理時間増加
- **対策**: Wi-Fi 6/6Eの採用、有線LANとの併用

### 適用判断フローチャート

1. **インターネット接続が必要か？**
   - Yes → インフラストラクチャモードへ
   - No → 次の判断へ

2. **接続台数は3台以上か？**
   - Yes → インフラストラクチャモードを推奨
   - No → アドホックモードも検討可能

3. **広範囲のカバレッジが必要か？**
   - Yes → メッシュネットワークまたはWDSを検討
   - No → 単一APのインフラストラクチャモードで十分

4. **高い信頼性・冗長性が必要か？**
   - Yes → メッシュネットワークを推奨
   - No → 通常のインフラストラクチャモードまたはWDS

### 問題1
アドホックモードの特徴として正しいものはどれか？

- A) アクセスポイントを中心とした星型構成である
- B) デバイス同士が直接通信を行う
- C) インターネット接続が必須である
- D) 管理サーバーが必要である

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
アドホックモードは、アクセスポイントを介さずにデバイス同士が直接通信を行う接続形態です。<br>
<br>
Aが間違いの理由：星型構成はインフラストラクチャモードの特徴<br>
Cが間違いの理由：インターネット接続は不要で、ローカル通信のみ可能<br>
Dが間違いの理由：管理サーバーは不要で、各デバイスが対等な関係
</details>

- A) ルーター

- D) ファイアウォール

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
インフラストラクチャモードでは、アクセスポイント（AP）が中心となって各デバイスを接続するため、APが必須機器となります。<br>

</details>

- B) 1, 6, 11

Aが間違いの理由：連続したチャンネルは周波数が重複する<br>
Cが間違いの理由：4チャンネルの間隔では部分的に重複が発生<br>
Dが間違いの理由：5チャンネル間隔でも若干の重複が発生する
</details>

</details>

### 問題10
Wi-Fi 6（802.11ax）で新たに導入された技術として正しいものは？

- A) MIMO技術
- B) WPA3暗号化
- C) OFDMA技術
- D) 5GHz帯の利用

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
Wi-Fi 6では、OFDMA（Orthogonal Frequency Division Multiple Access）技術が新たに導入され、複数デバイスへの同時通信効率が大幅に向上しました。<br>

Aが間違いの理由：MIMO技術は802.11n（Wi-Fi 4）から導入済み<br>
Bが間違いの理由：WPA3は暗号化規格でWi-Fi 6固有ではない<br>
Dが間違いの理由：5GHz帯は802.11a/n/acで既に利用されている
</details>

### 問題11
100人が同時接続する会議室で、1人あたり5Mbpsの帯域を確保したい。必要な総帯域は？

- A) 100Mbps
- B) 250Mbps
- C) 500Mbps
- D) 1Gbps

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
計算過程：100人 × 5Mbps = 500Mbps<br>
これは理論値であり、実際にはプロトコルオーバーヘッドやその他の要因により、より大きな帯域が必要になります。<br>
<br>
Aが間違いの理由：計算ミス（100人×1Mbpsと誤計算）<br>
Bが間違いの理由：計算ミス（50人×5Mbpsと誤計算）<br>
Dが間違いの理由：必要以上に大きい値（安全率を見込んでも過大）
</details>

### 問題12
2台のAPでWDSを構成する際、スループットはどの程度低下するか？

- B) 約25%低下
- C) 約50%低下
- D) 約75%低下

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
WDSでは、APが「クライアントとの通信」と「AP間の通信」の両方を同じ無線インターフェースで行うため、理論上のスループットは約50%に低下します。<br>
<br>
Aが間違いの理由：必ず低下が発生する<br>
Bが間違いの理由：低下率が少なすぎる<br>
Dが間違いの理由：低下率が大きすぎる<br>
<br>
【補足】実環境では、干渉やその他の要因によりさらに低下する可能性があります。
</details>

### 問題13
メッシュネットワークで3ホップ先のノードと通信する場合、遅延の主な要因は？

- C) 電波の伝搬速度
- D) クライアント認証

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
メッシュネットワークでは、各ホップ（中継点）でパケットのルーティング処理が必要となり、これが累積して遅延の主要因となります。3ホップなら3回の処理遅延が発生します。<br>
<br>
Aが間違いの理由：暗号化は一定の処理時間で、ホップ数に比例しない<br>
Cが間違いの理由：電波の伝搬速度（光速）による遅延は無視できるレベル<br>
Dが間違いの理由：クライアント認証は接続時のみで、通信中は影響しない
</details>

## 9. 専門用語集

この資料で使用された無線LAN関連の専門用語について、アルファベット順・50音順で解説します。

### アルファベット

**AP (Access Point)**
- **読み方**: エーピー、アクセスポイント
- **意味**: 無線LANにおいて、有線LANと無線LANを中継する機器。無線LANの親機として機能し、複数の無線端末を収容する
- **関連用語**: 無線LANルーター、基地局

**DFS (Dynamic Frequency Selection)**
- **読み方**: ディーエフエス
- **意味**: 5GHz帯で気象レーダーなどとの干渉を避けるため、レーダー波を検出すると自動的に使用チャンネルを変更する機能
- **関連用語**: W53、W56、レーダー検出

**DHCP (Dynamic Host Configuration Protocol)**
- **読み方**: ディーエイチシーピー
- **意味**: ネットワーク上の機器に自動的にIPアドレスを割り当てるプロトコル
- **関連用語**: IPアドレス、自動設定

**IEEE 802.11**
- **読み方**: アイトリプルイー はちまるにーてんいちいち
- **意味**: 無線LANの国際標準規格群。802.11a/b/g/n/ac/ax/beなどの規格がある
- **関連用語**: Wi-Fi、無線LAN規格

**MIMO (Multiple Input Multiple Output)**
- **読み方**: マイモ
- **意味**: 複数のアンテナを使用して同時に複数のデータストリームを送受信する技術
- **関連用語**: ビームフォーミング、空間多重

**OFDMA (Orthogonal Frequency Division Multiple Access)**
- **読み方**: オーエフディーエムエー
- **意味**: Wi-Fi 6で導入された、周波数を細分化して複数端末に同時割り当てる技術
- **関連用語**: Wi-Fi 6、802.11ax

**SSID (Service Set Identifier)**
- **読み方**: エスエスアイディー
- **意味**: 無線LANネットワークを識別するための名前。最大32文字まで設定可能
- **関連用語**: ネットワーク名、ESSID

**WDS (Wireless Distribution System)**
- **読み方**: ダブリューディーエス
- **意味**: 複数のアクセスポイント間を無線で接続し、有線LANを拡張する技術
- **関連用語**: ワイヤレスブリッジ、リピーター

**Wi-Fi**
- **読み方**: ワイファイ
- **意味**: Wi-Fi Allianceが認定した無線LAN機器の相互接続性を示すブランド名
- **関連用語**: 無線LAN、IEEE 802.11

**WPA3 (Wi-Fi Protected Access 3)**
- **読み方**: ダブリューピーエースリー
- **意味**: 最新の無線LANセキュリティ規格。従来のWPA2より強力な暗号化を実現
- **関連用語**: 暗号化、セキュリティ

### あ行

**アクセスポイント**
- **読み方**: あくせすぽいんと
- **意味**: 無線端末を有線LANに接続するための基地局装置
- **関連用語**: AP、無線LANルーター

**アドホックモード**
- **読み方**: あどほっくもーど
- **意味**: アクセスポイントを介さず、端末同士が直接通信する接続形態
- **関連用語**: ピアツーピア、Ad-hoc

**暗号化**
- **読み方**: あんごうか
- **意味**: データを第三者に解読されないよう変換する技術
- **関連用語**: WPA3、セキュリティ

**インフラストラクチャモード**
- **読み方**: いんふらすとらくちゃもーど
- **意味**: アクセスポイントを中心とした一般的な無線LAN接続形態
- **関連用語**: Infrastructure、管理モード

### か行

**干渉**
- **読み方**: かんしょう
- **意味**: 複数の電波が重なることで通信品質が低下する現象
- **関連用語**: 電波干渉、ノイズ

**クライアント**
- **読み方**: くらいあんと
- **意味**: 無線LANに接続する端末機器（PC、スマートフォンなど）
- **関連用語**: 端末、子機

### さ行

**サイトサーベイ**
- **読み方**: さいとさーべい
- **意味**: 無線LAN導入前に行う電波環境の調査
- **関連用語**: 電波調査、事前調査

**周波数帯**
- **読み方**: しゅうはすうたい
- **意味**: 無線通信で使用する電波の周波数範囲。2.4GHz帯と5GHz帯が主流
- **関連用語**: 帯域、バンド

**スループット**
- **読み方**: するーぷっと
- **意味**: 実際のデータ転送速度。理論値より低くなる
- **関連用語**: 実効速度、転送速度

### た行

**チャンネル**
- **読み方**: ちゃんねる
- **意味**: 無線LANで使用する周波数を分割した単位
- **関連用語**: 周波数、ch

**電波強度**
- **読み方**: でんぱきょうど
- **意味**: 受信する電波の強さ。dBmやRSSIで表される
- **関連用語**: 信号強度、受信レベル

### な行

**認証**
- **読み方**: にんしょう
- **意味**: ネットワークに接続する際の本人確認プロセス
- **関連用語**: 認証方式、ログイン

**ノード**
- **読み方**: のーど
- **意味**: ネットワーク上の接続点。メッシュネットワークでは各中継点を指す
- **関連用語**: 接続点、端点

### は行

**バックホール**
- **読み方**: ばっくほーる
- **意味**: アクセスポイント間を接続する回線
- **関連用語**: 基幹回線、中継回線

**帯域幅**
- **読み方**: たいいきはば
- **意味**: 通信に使用する周波数の幅。20MHz、40MHz、80MHzなど
- **関連用語**: チャンネル幅、バンド幅

**ビームフォーミング**
- **読み方**: びーむふぉーみんぐ
- **意味**: 電波を特定の方向に集中させて通信品質を向上させる技術
- **関連用語**: 指向性制御、MIMO

**ブリッジ**
- **読み方**: ぶりっじ
- **意味**: 異なるネットワークセグメントを接続する機能や機器
- **関連用語**: 中継、WDS

### ま行

**メッシュネットワーク**
- **読み方**: めっしゅねっとわーく
- **意味**: 複数のノードが相互に接続し、網目状のネットワークを形成する方式
- **関連用語**: メッシュWi-Fi、自己修復ネットワーク

### や行

**有線LAN**
- **読み方**: ゆうせんらん
- **意味**: イーサネットケーブルを使用した物理的な接続によるネットワーク
- **関連用語**: Ethernet、有線接続

### ら行

**リピーター**
- **読み方**: りぴーたー
- **意味**: 電波を中継して通信範囲を拡張する機器
- **関連用語**: 中継器、エクステンダー

**ルーティング**
- **読み方**: るーてぃんぐ
- **意味**: データの最適な経路を選択して転送する処理
- **関連用語**: 経路制御、経路選択

**レイテンシ**
- **読み方**: れいてんし
- **意味**: データ送信から受信までの遅延時間
- **関連用語**: 遅延、応答時間

### わ行

**ワイヤレスブリッジ**
- **読み方**: わいやれすぶりっじ
- **意味**: 離れた場所の有線LANを無線で接続する機能
- **関連用語**: WDS、無線ブリッジ
