# EDI（Electronic Data Interchange）について

## 概要
EDI（Electronic Data Interchange：電子データ交換）は、企業間で取引に関する情報を、専用回線やインターネットを通じて、標準的な形式に基づいて電子的に交換する仕組みです。従来の紙の伝票（注文書、納品書、請求書など）による取引を電子化することで、業務の効率化、コスト削減、エラーの減少を実現します。1960年代から発展し、現在では様々な業界で標準的な取引手段として利用されています。

## 1. 基本概念・仕組み

### EDIの核となる概念
- **定義**: 異なる組織間で、取引に関するデータを、合意された標準フォーマットに従って電子的に交換するシステム
- **動作原理**: 送信側システムがデータを標準フォーマットに変換し、通信プロトコルに従って送信。受信側が自社システムに取り込み可能な形式に変換
- **特徴**: 
  - 人手を介さない自動処理
  - 標準化されたデータフォーマット
  - 高速かつ正確なデータ交換
  - 取引の履歴管理が容易

### 関連技術との関係
- **従来技術との違い**: 
  - FAXや郵送：物理的な紙の移動が不要
  - 電子メール：構造化されたデータで自動処理可能
  - 電話注文：音声認識エラーやメモミスがない
- **改善点**: 
  - データ入力の二重作業を排除
  - リアルタイムに近い情報共有
  - ペーパーレス化による環境負荷軽減
- **限界**: 
  - 初期導入コストが高い
  - 取引先との標準化調整が必要
  - システム障害時の対応策が必要

## 2. 種類・分類

### 通信手段による分類
EDIは使用する通信手段によって大きく分類されます。

### VAN型EDI（Value Added Network）
**特徴:**
- 専用の付加価値通信網を利用
- 高いセキュリティと信頼性
- 通信事業者が中継サービスを提供
- 従量課金制が一般的

**算出方法:**
```
月額費用 = 基本料金 + (データ量 × 単価) + (通信回数 × 単価)
```

**📊 具体的な計算例**
**例: 月間1,000件の受発注を行う製造業A社**
- 基本料金: 50,000円/月
- データ単価: 10円/KB
- 通信単価: 20円/回
- 平均データサイズ: 5KB/件
- 通信回数: 1,000回/月

**ステップ1: データ量料金の計算**
```
データ量料金 = 5KB × 1,000件 × 10円 = 50,000円
```

**ステップ2: 通信料金の計算**
```
通信料金 = 1,000回 × 20円 = 20,000円
```

**ステップ3: 総費用の計算**
```
総費用 = 50,000円 + 50,000円 + 20,000円 = 120,000円/月
```

**結果: 月額120,000円のVAN利用料**

💡 **実際の現場では**: 大手製造業や流通業では、取引の信頼性を重視してVAN型を選択することが多い。特に自動車業界では、JNX（Japanese automotive Network eXchange）というVANが標準的に使用されている。

### Web-EDI
**特徴:**
- インターネットのWebブラウザを利用
- 初期投資が少ない
- 中小企業でも導入しやすい
- リアルタイム性が高い

**導入コスト比較:**
```
初期費用 = システム構築費 + 教育費用 + 移行費用
VAN型: 500万円～2,000万円
Web型: 100万円～500万円
```

**📊 具体的な計算例**
**例: 月間200件の取引を行う中小企業B社**
- クラウドサービス利用料: 30,000円/月
- ユーザー数: 5名
- トランザクション料金: なし（定額制）

**年間コスト計算:**
```
年間費用 = 30,000円 × 12ヶ月 = 360,000円
```

💡 **実際の現場では**: 取引先が大企業の場合、相手企業のWeb-EDIシステムに接続して利用することが多い。複数の取引先がある場合、それぞれのシステムにログインする必要があり、運用が煩雑になることがある。

### 全銀協標準通信プロトコル（全銀EDI）
**特徴:**
- 金融業界で広く採用
- 高度なセキュリティ機能
- 大容量データの送受信に対応
- XML形式での情報交換が可能

**データフォーマット例:**
```xml
<支払依頼>
  <振込先>
    <金融機関コード>0001</金融機関コード>
    <支店コード>123</支店コード>
```

## 3. 詳細仕様・パラメータ

### 主要な標準規格
#### UN/EDIFACT（国連標準）
- **意味**: United Nations/Electronic Data Interchange for Administration, Commerce and Transport
- **設定範囲**: 国際取引全般
- **影響**: グローバル企業間取引の標準化
- **推奨値**: 貿易関連文書、国際物流

#### EIAJ標準（日本電子機械工業会）
- **意味**: 電子・電機業界向けEDI標準
- **設定範囲**: 電子部品・機器の受発注
- **影響**: 日本の電子産業のサプライチェーン効率化
- **推奨値**: 部品表、納期回答、検査成績書

#### 流通BMS（流通ビジネスメッセージ標準）
- **意味**: 日本の流通業界向け次世代EDI標準
- **設定範囲**: 小売業と卸売業・製造業間の取引
- **影響**: インターネット通信による高速化・低コスト化
- **推奨値**: 発注、出荷、受領、請求、支払

### 通信プロトコル
| プロトコル | 特徴 | 用途 | セキュリティ |
|-----------|------|------|------------|
| AS2 | HTTPSベース、リアルタイム | 一般的なB2B取引 | 暗号化、電子署名対応 |
| SFTP | ファイル転送特化 | 大容量データ | SSH暗号化 |
| ebMS | SOAP/XMLベース | 国際標準準拠 | WS-Security対応 |
| JX手順 | 日本独自、全銀協標準 | 国内金融取引 | 独自暗号化方式 |

## 4. 実装例・適用事例

### 基本実装（発注データの送信）
```python
# EDI発注データ送信の基本実装例
import xml.etree.ElementTree as ET
import requests
from datetime import datetime

class EDIOrder:
    def __init__(self, partner_id, endpoint_url):
        self.partner_id = partner_id
        self.endpoint_url = endpoint_url
    
    def create_order_xml(self, order_data):
        # XMLルート要素作成
        root = ET.Element("Order")
        
        # ヘッダー情報
        header = ET.SubElement(root, "Header")
        ET.SubElement(header, "MessageID").text = order_data['message_id']
        ET.SubElement(header, "Timestamp").text = datetime.now().isoformat()
        ET.SubElement(header, "SenderID").text = order_data['sender_id']
        ET.SubElement(header, "ReceiverID").text = self.partner_id
        
        # 発注明細
        details = ET.SubElement(root, "OrderDetails")
        for item in order_data['items']:
            item_elem = ET.SubElement(details, "Item")
            ET.SubElement(item_elem, "ItemCode").text = item['code']
            ET.SubElement(item_elem, "Quantity").text = str(item['quantity'])
            ET.SubElement(item_elem, "UnitPrice").text = str(item['price'])
            ET.SubElement(item_elem, "DeliveryDate").text = item['delivery_date']
        
        return ET.tostring(root, encoding='utf-8')
    
    def send_order(self, order_data):
        xml_data = self.create_order_xml(order_data)
        
        # HTTPSで送信
        headers = {
            'Content-Type': 'application/xml',
            'X-EDI-Partner-ID': self.partner_id
        }
        
        response = requests.post(
            self.endpoint_url,
            data=xml_data,
            headers=headers,
            cert=('client_cert.pem', 'client_key.pem')  # クライアント証明書
        )
        
        return response.status_code == 200
```

```python
class MultiFormatEDI:
    def __init__(self):
        self.format_handlers = {
            'EDIFACT': self.parse_edifact,
            'X12': self.parse_x12,
            'XML': self.parse_xml,
            'CSV': self.parse_csv
        }
    
    def parse_edifact(self, data):
        # UN/EDIFACT形式の解析
        segments = data.split("'")
        order = {}
        
        for segment in segments:
            if segment.startswith('UNH'):
                # メッセージヘッダー
                parts = segment.split('+')
                order['message_ref'] = parts[1]
            elif segment.startswith('BGM'):
                # 文書情報
                parts = segment.split('+')
                order['document_type'] = parts[1]
                order['document_number'] = parts[2]
            elif segment.startswith('LIN'):
                # 明細行
                parts = segment.split('+')
                if 'items' not in order:
                    order['items'] = []
                order['items'].append({
                    'line_number': parts[1],
                    'item_code': parts[3].split(':')[0],
                    'quantity': parts[4]
                })
        
        return order
    
    def convert_format(self, source_data, source_format, target_format):
        # フォーマット変換
        parsed_data = self.format_handlers[source_format](source_data)
        
        if target_format == 'XML':
            return self.to_xml(parsed_data)
        elif target_format == 'JSON':
            return self.to_json(parsed_data)
```

## 5. メリット・デメリット

### メリット
**1. 業務効率の大幅向上**
- **理由**: データの再入力が不要になり、処理時間が短縮
- **効果**: 受発注処理時間を平均80%削減
- **具体例**: A社では月間1,000件の注文処理が5人から1人で対応可能に

**2. エラーの削減**
- **理由**: 手作業によるミスがなくなる
- **効果**: データエラー率を99%以上削減
- **具体例**: B社では年間100件以上あった誤発注が5件以下に減少

**3. コスト削減**
- **理由**: 紙、印刷、郵送費用が不要
- **効果**: 事務処理コストを60-70%削減
- **具体例**: C社では年間500万円の郵送費と人件費2,000万円を削減

**4. リアルタイム性**
- **理由**: 即座にデータ交換が可能
- **効果**: 在庫回転率20%向上
- **具体例**: D社では需要変動への対応時間が3日から3時間に短縮

### デメリット
**1. 高額な初期投資**
- **理由**: システム構築、ソフトウェア購入、教育費用
- **影響**: 中小企業には負担が大きい
- **対策**: クラウド型サービスの利用、段階的導入

**2. 取引先との調整の複雑さ**
- **理由**: 標準規格、通信手順、運用ルールの統一が必要
- **影響**: 導入までに6ヶ月～1年かかることも
- **対策**: 業界標準の採用、EDI推進協議会への参加

**3. システム障害リスク**
- **理由**: 電子化により障害時の影響が大きい
- **影響**: 取引が完全に停止する可能性
- **対策**: バックアップ体制、BCP（事業継続計画）の策定

**4. セキュリティリスク**
- **理由**: 電子データの漏洩、改ざんの危険性
- **影響**: 機密情報流出、取引データの信頼性低下
- **対策**: 暗号化、電子署名、アクセス制御の徹底

### 適用判断フローチャート
1. **月間取引件数が1,000件以上？** 
   - Yes → VAN型またはクラウドEDIを検討
   - No → 次の判断へ

2. **取引先が10社以上？**
   - Yes → 標準規格対応のクラウドEDI推奨
   - No → 次の判断へ

3. **初期投資を抑えたい？**
   - Yes → Web-EDIまたはクラウドEDI
   - No → 最適な性能のVAN型

4. **業界標準への準拠が必須？**
   - Yes → 業界標準対応のVAN型またはクラウドEDI
   - No → 費用対効果で選択

1. **現状分析**（1-2ヶ月）

2. **要件定義**（1-2ヶ月）
   - 必要な機能、性能要件の明確化
   - 取引先との調整

3. **システム選定**（1ヶ月）
   - ベンダー比較、デモ確認
   - 費用対効果の評価

4. **導入・テスト**（2-3ヶ月）
   - システム構築、接続テスト
   - 並行稼働による検証

5. **本格運用**（継続的）
   - 段階的な取引先拡大
   - 効果測定と改善

### 問題1
EDI（Electronic Data Interchange）の日本語訳として最も適切なものはどれか？

- A) 電子データ保存
- B) 電子データ交換
- C) 電子データ暗号化
- D) 電子データ管理

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
EDIは「Electronic Data Interchange」の略で、日本語では「電子データ交換」と訳されます。企業間で取引データを電子的に交換するシステムを指します。<br>
<br>
Aが間違いの理由：保存（Storage）ではなく交換（Interchange）が正しい<br>
Cが間違いの理由：暗号化（Encryption）は機能の一部であり、主目的ではない<br>
Dが間違いの理由：管理（Management）ではなく交換が主目的
</details>

### 問題2
EDIの主な目的として適切でないものはどれか？

- A) 業務の効率化
- B) データ入力ミスの削減
- C) 社内の人事評価
- D) 取引コストの削減

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
EDIは企業間の取引データ交換を目的としたシステムであり、社内の人事評価は対象外です。<br>
<br>
Aが正しい理由：手作業を自動化し、業務効率を大幅に向上させる<br>
Bが正しい理由：人手によるデータ入力を排除し、ミスを削減<br>
Dが正しい理由：紙や郵送費、人件費などのコストを削減
</details>

## 9. 専門用語集

このドキュメントで使用された専門用語について、アルファベット順・50音順で解説します。

### アルファベット

**API (Application Programming Interface)**
- **読み方**: エーピーアイ
- **意味**: ソフトウェアやアプリケーション同士が相互に通信するための仕組み。EDIとAPIの融合により、よりリアルタイムで柔軟なデータ連携が可能になる
- **関連用語**: RESTful API、SOAP、Web API

**AS2 (Applicability Statement 2)**
- **読み方**: エーエスツー
- **意味**: EDIで使用される通信プロトコルの一つ。HTTPSをベースとし、暗号化と電子署名に対応
- **関連用語**: AS1、AS3、AS4

**B2B (Business to Business)**
- **読み方**: ビートゥービー
- **意味**: 企業間取引を指す用語。EDIは主にB2B取引で使用される
- **関連用語**: B2C、B2G

**BCP (Business Continuity Plan)**
- **読み方**: ビーシーピー
- **意味**: 事業継続計画。災害やシステム障害時でも事業を継続するための計画
- **関連用語**: BCM、災害復旧計画

**CSV (Comma Separated Values)**
- **読み方**: シーエスブイ
- **意味**: カンマ区切りのテキストファイル形式。簡易的なEDIでデータ交換に使用される
- **関連用語**: TSV、固定長ファイル

**ebMS (ebXML Messaging Service)**
- **読み方**: イービーエムエス
- **意味**: XML標準に基づくメッセージング仕様。国際的なEDI標準として使用
- **関連用語**: ebXML、SOAP

**EDI (Electronic Data Interchange)**
- **読み方**: イーディーアイ
- **意味**: 電子データ交換。企業間で商取引データを電子的に交換するシステム
- **関連用語**: VAN、Web-EDI

**EDIFACT (Electronic Data Interchange for Administration, Commerce and Transport)**
- **読み方**: エディファクト
- **意味**: 国連が定めたEDIの国際標準規格
- **関連用語**: UN/EDIFACT、ANSI X12

**EIAJ (Electronic Industries Association of Japan)**
- **読み方**: イーアイエージェー
- **意味**: 日本電子機械工業会。電子・電機業界向けのEDI標準を策定
- **関連用語**: JEITA

**ERP (Enterprise Resource Planning)**
- **読み方**: イーアールピー
- **意味**: 企業資源計画。企業の基幹業務を統合管理するシステム。EDIと連携することが多い
- **関連用語**: SAP、Oracle

**GS1 (Global Standards 1)**
- **読み方**: ジーエスワン
- **意味**: 国際的な流通標準化機関。バーコードやEDI標準を管理
- **関連用語**: JAN、EAN、GLN

**HTTPS (Hypertext Transfer Protocol Secure)**
- **読み方**: エイチティーティーピーエス
- **意味**: 暗号化されたHTTP通信。Web-EDIやAS2で使用
- **関連用語**: SSL/TLS、HTTP

**IoT (Internet of Things)**
- **読み方**: アイオーティー
- **意味**: モノのインターネット。センサーデータをEDIと連携させる新たな活用方法
- **関連用語**: M2M、スマートファクトリー

**JNX (Japanese automotive Network eXchange)**
- **読み方**: ジェーエヌエックス
- **意味**: 日本の自動車業界専用のVAN（付加価値通信網）
- **関連用語**: ANX（米国版）、ENX（欧州版）

**RPA (Robotic Process Automation)**
- **読み方**: アールピーエー
- **意味**: 定型業務を自動化する技術。EDIと組み合わせて更なる効率化を実現
- **関連用語**: AI-OCR、業務自動化

**SFTP (SSH File Transfer Protocol)**
- **読み方**: エスエフティーピー
- **意味**: SSHで暗号化されたファイル転送プロトコル。EDIでの安全なデータ送受信に使用
- **関連用語**: FTP、FTPS

**SOAP (Simple Object Access Protocol)**
- **読み方**: ソープ
- **意味**: XMLベースのメッセージ交換プロトコル。Web-EDIで使用されることがある
- **関連用語**: REST、Web Services

**SSL/TLS (Secure Sockets Layer/Transport Layer Security)**
- **読み方**: エスエスエル/ティーエルエス
- **意味**: インターネット上の通信を暗号化するプロトコル
- **関連用語**: 公開鍵暗号、電子証明書

**VAN (Value Added Network)**
- **読み方**: バン、ヴァン
- **意味**: 付加価値通信網。専用回線を使用したEDIサービス
- **関連用語**: 専用線、閉域網

**XML (eXtensible Markup Language)**
- **読み方**: エックスエムエル
- **意味**: 拡張可能なマークアップ言語。構造化データの記述に使用
- **関連用語**: JSON、HTML

### は行

**バックアップ（ばっくあっぷ）**
- **意味**: システム障害に備えてデータやシステムの複製を保管すること
- **関連用語**: リストア、冗長化

**標準化（ひょうじゅんか）**
- **意味**: 規格や仕様を統一すること。EDIでは相互接続性のために必須
- **関連用語**: 国際標準、業界標準

**ファイル転送（ふぁいるてんそう）**
- **意味**: ファイル単位でデータを送受信する方式
- **関連用語**: FTP、ファイルアップロード

**付加価値通信網（ふかかちつうしんもう）**
- **意味**: VAN。基本的な通信サービスに付加価値を加えたネットワーク
- **関連用語**: 専用線、インターネット

**ペーパーレス（ぺーぱーれす）**
- **意味**: 紙の書類を使わない業務形態。EDIの主要な効果の一つ
- **関連用語**: 電子化、デジタル化

### ま行

**マッピング（まっぴんぐ）**
- **意味**: 異なるデータ形式間の対応関係を定義すること
- **関連用語**: データ変換、フォーマット変換

**メッセージ（めっせーじ）**
- **意味**: EDIで交換される一つの意味を持つデータの単位
- **関連用語**: トランザクション、ドキュメント

### や行

**要件定義（ようけんていぎ）**
- **意味**: システムに必要な機能や性能を明確にすること
- **関連用語**: 基本設計、詳細設計

### ら行

**リアルタイム（りあるたいむ）**
- **意味**: 即座に、遅延なく処理すること
- **関連用語**: バッチ処理、非同期処理

**流通BMS（りゅうつうびーえむえす）**
- **意味**: 流通ビジネスメッセージ標準。日本の流通業界の次世代EDI標準
- **関連用語**: JCA手順、流通システム標準化

**レガシーシステム（れがしーしすてむ）**
- **意味**: 古い技術で構築され、現在も使用されているシステム
- **関連用語**: マイグレーション、システム更新

**ログ（ろぐ）**
- **意味**: システムの動作記録。EDIでは取引の証跡として重要
- **関連用語**: 監査証跡、アクセスログ

### わ行

**ワークフロー（わーくふろー）**
- **意味**: 業務の流れ。EDIデータの承認プロセスなどで使用
- **関連用語**: 承認フロー、業務プロセス
