# サブクォルについて

## 概要
サブクォル（サブクエリ、副問い合わせ）は、SQL文の中に別のSQL文を入れ子状に記述する技術です。データベースから複雑な条件でデータを抽出したり、複数のテーブルを関連付けて集計したりする際に使用されます。一つのクエリでは実現困難な複雑な処理を、段階的に実行することで可能にする重要な機能です。

## 1. 基本概念・仕組み

### サブクォルの定義
- **定義**: SQL文の中に括弧で囲まれた別のSELECT文を含む構造
- **動作原理**: 内側のクエリ（サブクォル）が先に実行され、その結果を外側のクエリ（メインクエリ）が利用する
- **特徴**: 複雑な条件を簡潔に記述でき、可読性を保ちながら高度な検索が可能

### サブクォルとJOINの関係
- **従来技術との違い**: JOINは複数テーブルを横に結合するが、サブクォルは縦方向の処理や条件指定に適している
- **改善点**: 段階的な処理により、複雑な条件を論理的に記述できる
- **限界**: パフォーマンスが低下する可能性があり、最適化が必要な場合がある

## 2. 種類・分類

### 返却値による分類
サブクォルは返却される値の形式により、以下のように分類されます。

### 単一行サブクォル
**特徴:**
- 1行1列の値を返す
- 比較演算子（=, >, <, >=, <=, <>）と共に使用
- 最も基本的なサブクォル形式

**算出方法:**
```sql
SELECT 列名
FROM テーブル名
WHERE 列名 = (SELECT 集計関数(列名) FROM テーブル名 WHERE 条件);
```

**📊 具体的な計算例**
**例: 社員の平均給与より高い給与を受け取っている社員を検索**
- 前提条件1: 社員テーブル（社員ID、氏名、給与）
- 前提条件2: 現在の平均給与が450,000円

**ステップ1: 平均給与を計算するサブクォル**
```sql
SELECT AVG(給与) FROM 社員;
-- 結果: 450000
```

**ステップ2: 平均より高い給与の社員を検索**
```sql
SELECT 社員ID, 氏名, 給与
FROM 社員
WHERE 給与 > (SELECT AVG(給与) FROM 社員);
```

**結果: 給与が450,000円より高い社員のリストが取得される**

💡 **実際の現場では**: 単一行サブクォルは集計値との比較で頻繁に使用されます。ただし、サブクォルが複数行を返すとエラーになるため注意が必要です。

### 複数行サブクォル
**特徴:**
- 複数行の値を返す（1列のみ）
- IN、ANY、ALL、EXISTSなどの演算子と使用
- リスト形式での条件指定に適している

**算出方法:**
```sql
SELECT 列名
FROM テーブル名
WHERE 列名 IN (SELECT 列名 FROM テーブル名 WHERE 条件);
```

**📊 具体的な計算例**
**例: 東京支店または大阪支店に所属する社員を検索**
- 前提条件1: 支店テーブル（支店ID、支店名）
- 前提条件2: 社員テーブル（社員ID、氏名、支店ID）

**ステップ1: 対象支店のIDを取得**
```sql
SELECT 支店ID FROM 支店 WHERE 支店名 IN ('東京支店', '大阪支店');
-- 結果: 101, 102
```

**ステップ2: 該当する社員を検索**
```sql
SELECT 社員ID, 氏名
FROM 社員
WHERE 支店ID IN (SELECT 支店ID FROM 支店 WHERE 支店名 IN ('東京支店', '大阪支店'));
```

**結果: 東京支店（ID:101）と大阪支店（ID:102）の社員リストが取得される**

💡 **実際の現場では**: 複数条件での絞り込みや、動的なリストとの照合に活用されます。

### 相関サブクォル
**特徴:**
- メインクエリの各行に対してサブクォルが実行される
- 外部クエリの値を参照できる
- 行ごとの条件判定に適している

**算出方法:**
```sql
SELECT 列名
FROM テーブル名 AS T1
WHERE 条件 (SELECT 列名 FROM テーブル名 AS T2 WHERE T1.列名 = T2.列名);
```

**📊 具体的な計算例**
**例: 各部署で平均給与以上の社員を検索**
- 前提条件1: 社員テーブル（社員ID、氏名、部署ID、給与）
- 前提条件2: 営業部（平均450,000円）、開発部（平均500,000円）

**実行クエリ:**
```sql
SELECT 社員ID, 氏名, 部署ID, 給与
FROM 社員 AS S1
WHERE 給与 >= (
    SELECT AVG(給与)
    FROM 社員 AS S2
    WHERE S1.部署ID = S2.部署ID
);
```

**結果: 各部署で部署平均以上の給与の社員が取得される**

💡 **実際の現場では**: 部署別、地域別など、グループごとの相対的な条件判定で使用されます。

## 3. 詳細仕様・パラメータ

### サブクォルの配置場所
#### WHERE句でのサブクォル
- **意味**: 行の絞り込み条件として使用
- **設定範囲**: 単一値、複数値、相関サブクォル
- **影響**: 検索結果の行数に直接影響
- **推奨値**: 単純な条件では単一行サブクォル、複雑な条件では相関サブクォル

#### FROM句でのサブクォル（インラインビュー）
- **意味**: 仮想的なテーブルとして使用
- **設定範囲**: SELECT文全般
- **影響**: メモリ使用量とパフォーマンスに影響
- **推奨値**: 集計結果を再利用する場合に使用

#### SELECT句でのサブクォル
- **意味**: 列の値として使用
- **設定範囲**: 単一値を返すサブクォルのみ
- **影響**: 各行に対してサブクォルが実行されるため処理時間に影響
- **推奨値**: 関連データの取得時に限定的に使用

## 4. 実装例・適用事例

### 基本実装
```sql
-- 最高給与の社員を検索
SELECT 社員ID, 氏名, 給与
FROM 社員
WHERE 給与 = (SELECT MAX(給与) FROM 社員);
```

### 応用実装
```sql
-- 各部署の最新の売上データを取得
SELECT 
    D.部署名,
    S.売上金額,
    S.売上日
FROM 部署 D
INNER JOIN (
    SELECT 
        部署ID,
        売上金額,
        売上日,
        ROW_NUMBER() OVER (PARTITION BY 部署ID ORDER BY 売上日 DESC) AS rn
    FROM 売上
) S ON D.部署ID = S.部署ID AND S.rn = 1;
```

### 実際の適用事例
#### 事例1: ECサイトでの商品推奨システム
- **課題**: ユーザーの購買履歴に基づいた商品推奨
- **適用方法**: 相関サブクォルで同じカテゴリの人気商品を抽出
- **結果**: 購買率が15%向上
- **効果**: パーソナライズされた推奨により顧客満足度が向上

#### 事例2: 人事システムでの昇進候補者選定
- **課題**: 各部署で成績上位20%の社員を自動選定
- **適用方法**: 相関サブクォルとPERCENTILE関数を組み合わせて実装
- **結果**: 選定作業時間を80%削減
- **効果**: 公平で透明性の高い評価システムを実現

## 5. メリット・デメリット

### メリット
**1. 複雑な条件の簡潔な記述**
- **理由**: 段階的な処理により論理構造が明確
- **効果**: コードの可読性と保守性が向上
- **具体例**: 3段階の条件判定を1つのクエリで実現

**2. 動的な条件設定**
- **理由**: 実行時の値に基づいた条件設定が可能
- **効果**: 柔軟なデータ抽出が可能
- **具体例**: 日々変動する平均値との比較

**3. 一時テーブル不要**
- **理由**: メモリ上で処理が完結
- **効果**: データベースの負荷軽減
- **具体例**: 集計結果を直接利用できる

### デメリット
**1. パフォーマンスの低下**
- **理由**: 各行に対してサブクォルが実行される場合がある
- **影響**: 大量データでは処理時間が増大
- **対策**: インデックスの適切な設定、JOINへの書き換え

**2. デバッグの困難さ**
- **理由**: 入れ子構造により実行順序が複雑
- **影響**: エラー箇所の特定が困難
- **対策**: 段階的にテストし、部分的に実行して確認

**3. データベース依存性**
- **理由**: DBMSによって最適化方法が異なる
- **影響**: 移植性が低下する可能性
- **対策**: 標準SQLに準拠した記述を心がける

## 6. 選択・導入の指針

### サブクォルとJOINの選択基準
| 観点 | サブクォル | JOIN | 相関サブクォル |
|------|-----------|------|----------------|
| 処理速度 | ○ | ◎ | △ |
| 可読性 | ◎ | ○ | △ |
| 柔軟性 | ○ | △ | ◎ |
| メモリ使用 | ○ | △ | △ |

### 適用判断フローチャート
1. **単一の集計値との比較が必要？** 
   - Yes → 単一行サブクォル
   - No → 次の判断へ

2. **複数の値のリストとの照合？**
   - Yes → 複数行サブクォル（IN句）
   - No → 次の判断へ

3. **行ごとに異なる条件での判定？**
   - Yes → 相関サブクォル
   - No → JOINを検討

- D) UPDATE文では使用できない

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>

### 問題2

- A) IN
- B) =
- C) EXISTS
- D) ANY

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
単一行サブクォルは1行1列の値を返すため、比較演算子（=, >, <など）と使用します。<br>
<br>
Aが間違いの理由：INは複数行サブクォルで使用する演算子<br>
Cが間違いの理由：EXISTSは相関サブクォルで主に使用<br>
Dが間違いの理由：ANYは複数行サブクォルで使用する演算子
</details>

### 問題3
次のSQL文の結果として正しいものはどれか？
```sql
SELECT 社員名 FROM 社員 
WHERE 給与 > (SELECT AVG(給与) FROM 社員);
```

- A) 全社員の名前が表示される
- B) 平均給与と同じ給与の社員名が表示される
- C) 平均給与より高い給与の社員名が表示される
- D) 平均給与より低い給与の社員名が表示される

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
サブクォルで全社員の平均給与を計算し、それより高い（>）給与の社員を抽出しています。<br>
<br>
Aが間違いの理由：WHERE句で条件指定しているため全員ではない<br>
Bが間違いの理由：「>」は「より大きい」を意味し、同じ値は含まない<br>
Dが間違いの理由：「>」は「より大きい」を意味するため、低い給与は対象外
</details>

### 問題4
複数行サブクォルで使用する演算子として不適切なものはどれか？

- A) IN
- B) ANY
- C) ALL
- D) BETWEEN

<details>
<summary>解答</summary>
<strong>正解: D</strong><br>
BETWEENは範囲を指定する演算子で、複数行サブクォル専用の演算子ではありません。<br>
<br>
Aが正しい理由：INは複数の値のリストと照合する際に使用<br>
Bが正しい理由：ANYはサブクォルの結果のいずれかと比較<br>
Cが正しい理由：ALLはサブクォルの結果のすべてと比較
</details>

<summary>解答</summary>

</details>

### 問題8
EXISTS演算子の特徴として正しいものはどれか？

- A) サブクォルの結果の値を返す
- B) サブクォルに行が存在するかを判定する
- C) 必ず単一行サブクォルと使用する
- D) IN演算子より必ず処理が遅い

<details>
<summary>解答</summary>

<br>
Aが間違いの理由：EXISTSは真偽値（TRUE/FALSE）を返すのみで値は返さない<br>
Cが間違いの理由：EXISTSは主に相関サブクォルと使用される<br>
Dが間違いの理由：大量データの場合、EXISTSの方がINより高速な場合が多い
</details>

### 問題14
パフォーマンスを考慮した場合、次のうち最も避けるべき実装はどれか？

- A) WHERE句での単一行サブクォル
- B) FROM句でのインラインビュー
- C) SELECT句での相関サブクォル

Aが問題ない理由：単一行サブクォルは1回のみ実行<br>
Bが問題ない理由：適切に使用すればパフォーマンス向上に寄与<br>

Aが不適切な理由：記述の簡単さは状況による<br>

## 9. 専門用語集

このスライドで使用された専門用語について、50音順で解説します。

### アルファベット
**ALL演算子**
- **読み方**: オールえんざんし
- **意味**: 複数行サブクォルで使用され、サブクォルの結果のすべての値に対して条件が成立する場合にTRUEを返す演算子
- **関連用語**: ANY演算子、複数行サブクォル

**ANY演算子**
- **読み方**: エニーえんざんし
- **意味**: 複数行サブクォルで使用され、サブクォルの結果のいずれかの値に対して条件が成立する場合にTRUEを返す演算子
- **関連用語**: ALL演算子、SOME演算子（同義）

**CTE (Common Table Expression)**
- **読み方**: シーティーイー
- **意味**: WITH句を使用して定義される一時的な名前付き結果セット。サブクォルの代替として使用可能
- **関連用語**: WITH句、再帰クエリ

**EXISTS演算子**
- **読み方**: イグジスツえんざんし
- **意味**: サブクォルの結果に1行でも存在すればTRUE、存在しなければFALSEを返す演算子
- **関連用語**: NOT EXISTS、相関サブクォル

**FROM句**
- **読み方**: フロムく
- **意味**: SQL文でデータの取得元となるテーブルを指定する句。サブクォルを配置してインラインビューとして使用可能
- **関連用語**: インラインビュー、派生テーブル

**IN演算子**
- **読み方**: インえんざんし
- **意味**: 値がリストまたはサブクォルの結果に含まれているかを判定する演算子
- **関連用語**: NOT IN、複数行サブクォル

**JOIN**
- **読み方**: ジョイン
- **意味**: 複数のテーブルを結合してデータを取得するSQL操作
- **関連用語**: INNER JOIN、LEFT JOIN、サブクォル

**SELECT句**
- **読み方**: セレクトく
- **意味**: SQL文で取得する列を指定する句。スカラーサブクォルを配置可能
- **関連用語**: スカラーサブクォル

**SQL**
- **読み方**: エスキューエル（またはシークェル）
- **意味**: Structured Query Languageの略。リレーショナルデータベースを操作するための標準的な言語
- **関連用語**: DDL、DML、DCL

**WHERE句**
- **読み方**: ウェアく（ホエアく）
- **意味**: SQL文で行の抽出条件を指定する句。サブクォルを最も頻繁に配置する場所
- **関連用語**: HAVING句、条件式

### あ行
**インラインビュー**
- **読み方**: いんらいんびゅー
- **意味**: FROM句に記述されたサブクォル。一時的な仮想テーブルとして機能する
- **関連用語**: 派生テーブル、サブクォル

**ウィンドウ関数**
- **読み方**: うぃんどうかんすう
- **意味**: 行のグループに対して集計や順位付けを行う関数。ROW_NUMBER、RANKなど
- **関連用語**: OVER句、PARTITION BY

**演算子**
- **読み方**: えんざんし
- **意味**: 値の比較や計算を行うための記号や予約語。=、>、<、IN、EXISTSなど
- **関連用語**: 比較演算子、論理演算子

### か行
**外部クエリ**
- **読み方**: がいぶくえり
- **意味**: サブクォルを含む側のメインとなるSQL文
- **関連用語**: メインクエリ、内部クエリ

**括弧**
- **読み方**: かっこ
- **意味**: サブクォルを囲むために使用する記号（）。サブクォルは必ず括弧で囲む必要がある
- **関連用語**: サブクォル

**クエリ**
- **読み方**: くえり
- **意味**: データベースに対する問い合わせ文。主にSELECT文を指すことが多い
- **関連用語**: SQL、サブクォル

### さ行
**サブクォル**
- **読み方**: さぶくぉる
- **意味**: SQL文の中に入れ子状に記述される別のSQL文。副問い合わせとも呼ばれる
- **関連用語**: サブクエリ、副問い合わせ

**自己結合**
- **読み方**: じこけつごう
- **意味**: 同一テーブルを別名を付けて結合する手法。セルフJOINとも呼ばれる
- **関連用語**: セルフJOIN、エイリアス

**スカラーサブクォル**
- **読み方**: すからーさぶくぉる
- **意味**: 必ず1行1列（単一値）を返すサブクォル
- **関連用語**: 単一行サブクォル

**相関サブクォル**
- **読み方**: そうかんさぶくぉる
- **意味**: 外部クエリの値を参照するサブクォル。各行に対して実行される
- **関連用語**: 相関副問い合わせ

### た行
**単一行サブクォル**
- **読み方**: たんいつぎょうさぶくぉる
- **意味**: 1行1列の結果を返すサブクォル。比較演算子と共に使用
- **関連用語**: スカラーサブクォル

### な行
**内部クエリ**
- **読み方**: ないぶくえり
- **意味**: サブクォル自体を指す。外部クエリに対して内側にあるクエリ
- **関連用語**: サブクォル、外部クエリ

**入れ子**
- **読み方**: いれこ
- **意味**: ある構造の中に同じ構造が含まれること。サブクォルはSQL文の入れ子構造
- **関連用語**: ネスト、階層

### は行
**派生テーブル**
- **読み方**: はせいてーぶる
- **意味**: FROM句のサブクォルによって作成される一時的なテーブル
- **関連用語**: インラインビュー

**パフォーマンス**
- **読み方**: ぱふぉーまんす
- **意味**: SQLの実行速度や効率性。サブクォルは使い方によってパフォーマンスに影響する
- **関連用語**: 最適化、実行計画

**比較演算子**
- **読み方**: ひかくえんざんし
- **意味**: 値の大小や等価を比較する演算子。=、>、<、>=、<=、<>など
- **関連用語**: 演算子、条件式

**副問い合わせ**
- **読み方**: ふくといあわせ
- **意味**: サブクォルの日本語名。SQL文の中に含まれる別のSQL文
- **関連用語**: サブクォル、サブクエリ

**複数行サブクォル**
- **読み方**: ふくすうぎょうさぶくぉる
- **意味**: 複数行（0行以上）の結果を返すサブクォル。IN、ANY、ALLなどと使用
- **関連用語**: 単一行サブクォル

### ま行
**メインクエリ**
- **読み方**: めいんくえり
- **意味**: サブクォルを含む側の主となるSQL文
- **関連用語**: 外部クエリ、サブクォル

### ら行
**リレーショナルデータベース**
- **読み方**: りれーしょなるでーたべーす
- **意味**: 表形式でデータを管理し、表同士の関係を定義できるデータベース
- **関連用語**: RDBMS、SQL
