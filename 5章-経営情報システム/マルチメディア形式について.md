# マルチメディア形式について

## 概要
マルチメディアとは、文字・画像・音声・動画などの複数のメディア形式を統合的に扱う技術やコンテンツを指します。デジタル化の進展により、これらの異なるメディアを統一的に処理・保存・伝送することが可能になりました。本資料では、代表的なマルチメディア形式とその特徴、拡張子について詳しく解説します。

## 1. 画像形式の詳細

### 画像形式の分類
画像形式は大きく「ラスター形式」と「ベクター形式」に分類されます。

#### ラスター形式（ビットマップ形式）
ピクセル（画素）の集合として画像を表現する形式です。

#### ベクター形式
数式や座標情報として画像を表現する形式です。

### 主要な画像形式

#### JPEG（Joint Photographic Experts Group）
**拡張子:** .jpg, .jpeg, .jpe, .jfif

**特徴:**
- 非可逆圧縮方式を採用
- フルカラー（約1,677万色）に対応
- 写真や自然画像に適している
- 圧縮率を調整可能（品質と容量のトレードオフ）

**圧縮の仕組み:**
```
1. RGB色空間からYCbCr色空間への変換
2. 離散コサイン変換（DCT）による周波数領域への変換
3. 量子化による情報の削減
4. ハフマン符号化による圧縮
```

**📊 具体的な圧縮例**
**例: 3000×2000ピクセルの写真画像**
- 無圧縮時: 約18MB（3000×2000×3バイト）
- JPEG品質100%: 約2.5MB（圧縮率 約7:1）
- JPEG品質80%: 約800KB（圧縮率 約23:1）
- JPEG品質60%: 約400KB（圧縮率 約45:1）

💡 **実際の現場では**: Web掲載用画像は品質70-80%、印刷用画像は品質90%以上が推奨されます。

#### PNG（Portable Network Graphics）
**拡張子:** .png

**特徴:**
- 可逆圧縮方式を採用
- 透過（アルファチャンネル）に対応
- ガンマ補正情報を保持
- インターレース表示に対応

**圧縮の仕組み:**
```
1. フィルタリング（隣接ピクセルとの差分を計算）
2. Deflate圧縮（LZ77とハフマン符号化の組み合わせ）
```

**圧縮効率の比較**
| 画像の種類 | PNG圧縮率 | 適性 |
|-----------|----------|------|
| イラスト・ロゴ | 高（10:1以上） | ◎ |
| スクリーンショット | 中（5:1程度） | ○ |
| 写真 | 低（2:1程度） | △ |

#### GIF（Graphics Interchange Format）
**拡張子:** .gif

**特徴:**
- 最大256色のインデックスカラー
- アニメーション機能
- 透過色の指定が可能
- LZW圧縮を使用（可逆圧縮）

**アニメーションGIFの構造:**
```
ヘッダー部
├─ 論理スクリーンディスクリプタ
├─ グローバルカラーテーブル
└─ 画像データブロック（複数）
    ├─ グラフィック制御拡張（遅延時間等）
    ├─ 画像ディスクリプタ
    └─ 画像データ
```

#### WebP
**拡張子:** .webp

**特徴:**
- Googleが開発した新しい画像形式
- 可逆・非可逆両方の圧縮に対応
- JPEGより25-35%小さいファイルサイズ
- アニメーションにも対応

**圧縮効率の実例:**
| 元画像 | JPEG | PNG | WebP（非可逆） | WebP（可逆） |
|-------|------|-----|---------------|-------------|
| 写真（1MB） | 150KB | 800KB | 100KB | 600KB |
| イラスト（500KB） | 200KB | 100KB | 80KB | 70KB |

#### BMP（Bitmap）
**拡張子:** .bmp, .dib

**特徴:**
- Windows標準の画像形式
- 基本的に無圧縮（RLE圧縮も可能）
- ヘッダー情報がシンプル
- ファイルサイズが大きい

#### TIFF（Tagged Image File Format）
**拡張子:** .tif, .tiff

**特徴:**
- 高品質な画像保存に適している
- 複数の圧縮方式に対応（無圧縮、LZW、JPEG等）
- マルチページに対応
- メタデータを豊富に保存可能

### ベクター形式

#### SVG（Scalable Vector Graphics）
**拡張子:** .svg

**特徴:**
- XML形式で記述
- 拡大縮小しても劣化しない
- テキストエディタで編集可能
- JavaScriptによる動的制御が可能

**SVGの記述例:**
```xml
<svg width="100" height="100">
  <circle cx="50" cy="50" r="40" fill="red" />
  <text x="50" y="55" text-anchor="middle">SVG</text>
</svg>
```

## 2. 動画形式の詳細

### 動画の基本概念
動画は連続した静止画（フレーム）の集合体として表現されます。

**重要なパラメータ:**
- **フレームレート**: 1秒間のフレーム数（fps）
- **解像度**: 画面のピクセル数（横×縦）
- **ビットレート**: 1秒間のデータ量（bps）
- **アスペクト比**: 画面の縦横比

### 主要な動画形式

#### MP4（MPEG-4 Part 14）
**拡張子:** .mp4, .m4v

**特徴:**
- 最も汎用的な動画形式
- H.264/H.265コーデックに対応
- ストリーミング配信に適している
- メタデータの埋め込みが可能

**コンテナ構造:**
```
MP4ファイル
├─ ftyp（ファイルタイプ）
├─ moov（メタデータ）
│   ├─ mvhd（ムービーヘッダー）
│   └─ trak（トラック情報）
└─ mdat（メディアデータ）
```

**📊 圧縮効率の実例**
**例: フルHD（1920×1080）30fps、10分の動画**
- 無圧縮: 約37GB
- H.264高品質: 約1.5GB（圧縮率 約25:1）
- H.264標準品質: 約500MB（圧縮率 約75:1）
- H.265標準品質: 約250MB（圧縮率 約150:1）

💡 **実際の現場では**: YouTube推奨設定は1080p動画で8Mbps、4K動画で35-45Mbpsのビットレートです。

#### AVI（Audio Video Interleave）
**拡張子:** .avi

**特徴:**
- Microsoft開発の古典的な形式
- 様々なコーデックに対応
- インデックス情報により高速シーク可能
- ファイルサイズが大きくなりやすい

#### MOV（QuickTime Movie）
**拡張子:** .mov, .qt

**特徴:**
- Apple開発の動画形式
- MP4の基になった形式
- ProRes等の高品質コーデックに対応
- Mac環境での編集に適している

#### WMV（Windows Media Video）
**拡張子:** .wmv

**特徴:**
- Microsoft開発の動画形式
- DRM（デジタル著作権管理）に対応
- Windows環境での再生に最適化
- ストリーミング配信に対応

#### MKV（Matroska Video）
**拡張子:** .mkv

**特徴:**
- オープンソースのコンテナ形式
- 複数の音声・字幕トラックを格納可能
- チャプター機能に対応
- あらゆるコーデックに対応

**MKVの多重化構造:**
```
MKVファイル
├─ ビデオトラック（H.264/H.265/VP9等）
├─ 音声トラック1（日本語）
├─ 音声トラック2（英語）
├─ 字幕トラック1（日本語）
├─ 字幕トラック2（英語）
└─ チャプター情報
```

#### WebM
**拡張子:** .webm

**特徴:**
- Web配信に特化した形式
- VP8/VP9/AV1コーデックを使用
- ロイヤリティフリー
- HTML5で標準サポート

### コーデックの詳細

#### 映像コーデック
**H.264（AVC）**
- 現在最も普及している映像コーデック
- ハードウェアエンコード/デコードに広く対応
- 圧縮効率と品質のバランスが良い

**H.265（HEVC）**
- H.264の後継規格
- 同品質でH.264の約半分のデータ量
- 4K/8K動画に適している
- ライセンス料が複雑

**VP9**
- Googleが開発したオープンソースコーデック
- YouTubeで広く使用
- H.265相当の圧縮効率

**AV1**
- 次世代のオープンソースコーデック
- VP9より30%高い圧縮効率
- Netflix、YouTube等が採用開始

## 3. 音声形式の詳細

### 音声のデジタル化
アナログ音声をデジタル化する際の重要なパラメータ：

**サンプリング周波数**
- 1秒間にサンプリングする回数
- CD品質: 44.1kHz
- ハイレゾ: 96kHz、192kHz

**量子化ビット数**
- 音の強弱を表現するビット数
- CD品質: 16bit
- ハイレゾ: 24bit、32bit

**チャンネル数**
- モノラル: 1ch
- ステレオ: 2ch
- サラウンド: 5.1ch、7.1ch

### 主要な音声形式

#### MP3（MPEG-1 Audio Layer 3）
**拡張子:** .mp3

**特徴:**
- 最も普及した音声圧縮形式
- 心理音響モデルを使用した非可逆圧縮
- 可変ビットレート（VBR）に対応
- ID3タグによるメタデータ保存

**圧縮の仕組み:**
```
1. 周波数領域への変換（MDCT）
2. 心理音響モデルによる聴覚マスキング
3. 量子化とハフマン符号化
```

**📊 ビットレートと音質の関係**
| ビットレート | 音質 | 用途 | 1分あたりの容量 |
|------------|------|------|----------------|
| 64kbps | 低 | 音声通話 | 約480KB |
| 128kbps | 標準 | Web配信 | 約960KB |
| 192kbps | 良 | 音楽配信 | 約1.4MB |
| 320kbps | 高 | 高品質配信 | 約2.4MB |

💡 **実際の現場では**: SpotifyやApple Musicは256-320kbpsで配信しています。

#### AAC（Advanced Audio Coding）
**拡張子:** .aac, .m4a

**特徴:**
- MP3の後継として開発
- 同ビットレートでMP3より高音質
- Apple製品で標準採用
- 複数のプロファイルに対応

**AACプロファイル:**
- **AAC-LC**: 低複雑度、最も一般的
- **HE-AAC**: 低ビットレート向け
- **HE-AAC v2**: さらに低ビットレート向け

#### WAV（Waveform Audio Format）
**拡張子:** .wav

**特徴:**
- 基本的に無圧縮（PCM）
- Windows標準の音声形式
- 音質劣化なし
- ファイルサイズが大きい

**WAVファイル構造:**
```
RIFFヘッダー
├─ fmt チャンク（フォーマット情報）
│   ├─ サンプリング周波数
│   ├─ ビット深度
│   └─ チャンネル数
└─ data チャンク（音声データ）
```

#### FLAC（Free Lossless Audio Codec）
**拡張子:** .flac

**特徴:**
- 可逆圧縮形式
- 元の音質を完全に保持
- 約50-60%のサイズに圧縮
- オープンソース

**圧縮効率の実例:**
| 元ファイル（WAV） | FLAC圧縮後 | 圧縮率 |
|-----------------|------------|--------|
| 50MB（5分） | 25-30MB | 約50% |
| 600MB（CD1枚） | 300-350MB | 約55% |

#### OGG Vorbis
**拡張子:** .ogg, .oga

**特徴:**
- オープンソースの音声形式
- MP3相当以上の音質
- 可変ビットレート標準対応
- ゲーム業界で広く採用

#### WMA（Windows Media Audio）
**拡張子:** .wma

**特徴:**
- Microsoft開発の音声形式
- DRM対応
- 可逆圧縮版（WMA Lossless）も存在
- Windows環境に最適化

### ハイレゾ音源形式

#### DSD（Direct Stream Digital）
**拡張子:** .dsf, .dff

**特徴:**
- 1ビット方式のデジタル音声
- SACD（Super Audio CD）で使用
- サンプリング周波数: 2.8MHz、5.6MHz等

#### MQA（Master Quality Authenticated）
**拡張子:** .mqa（通常はFLACコンテナ）

**特徴:**
- スタジオマスター品質を圧縮
- 通常のFLACプレイヤーでも再生可能
- 認証済みデバイスで完全展開

## 4. 形式選択の指針

### 用途別推奨形式

#### Web掲載用
| メディア | 推奨形式 | 理由 |
|---------|---------|------|
| 写真 | JPEG, WebP | 圧縮効率が高い |
| イラスト・ロゴ | PNG, SVG | 透過対応、劣化なし |
| 動画 | MP4（H.264） | 互換性が高い |
| 音声 | MP3, AAC | 広くサポート |

#### アーカイブ・保存用
| メディア | 推奨形式 | 理由 |
|---------|---------|------|
| 写真 | TIFF, RAW | 最高品質を保持 |
| イラスト | SVG, AI | 編集可能性を維持 |
| 動画 | ProRes, DNxHD | 編集用中間形式 |
| 音声 | WAV, FLAC | 無劣化保存 |

#### モバイル配信用
| メディア | 推奨形式 | 理由 |
|---------|---------|------|
| 画像 | WebP, JPEG | データ量削減 |
| 動画 | MP4（H.265） | 高圧縮効率 |
| 音声 | AAC, Opus | 低ビットレートで高品質 |

### 変換時の注意点

**非可逆圧縮の連続適用を避ける**
```
悪い例: JPEG → JPEG → JPEG（品質が累積的に劣化）
良い例: RAW/TIFF → JPEG（マスターから都度生成）
```

**解像度とビットレートのバランス**
- 高解像度には高ビットレートが必要
- 低解像度で高ビットレートは無駄
- 配信先のデバイスを考慮

## 5. 最新動向と今後の展望

### 新しいコーデックの登場
- **画像**: AVIF（AV1ベースの静止画形式）

## 6. 理解度確認クイズ（4択問題20問）

### 問題1
JPEGの圧縮方式として正しいものはどれか？

- A) 可逆圧縮方式
- B) 非可逆圧縮方式
- C) 無圧縮方式
- D) 適応的圧縮方式

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
JPEGは非可逆圧縮方式を採用しています。離散コサイン変換（DCT）と量子化により、人間の視覚特性を利用して認識しにくい情報を削減することで高い圧縮率を実現しています。<br>
<br>
Aが間違いの理由：可逆圧縮は元のデータを完全に復元できる方式で、PNGやFLACが該当します<br>
Cが間違いの理由：無圧縮はBMPやWAVのような形式で、JPEGは圧縮を行います<br>
Dが間違いの理由：適応的圧縮という一般的な圧縮方式の分類はありません
</details>

### 問題2
透過（アルファチャンネル）に対応している画像形式の組み合わせとして正しいものはどれか？

- A) JPEG、BMP
- B) PNG、GIF
- C) JPEG、TIFF
- D) BMP、TIFF

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
PNGは完全なアルファチャンネル（256段階の透明度）に対応し、GIFは単一の透過色指定に対応しています。どちらも透過画像の作成が可能です。<br>
<br>
Aが間違いの理由：JPEGもBMPも透過に対応していません<br>
Cが間違いの理由：JPEGは透過に対応していません（TIFFは対応可能）<br>
Dが間違いの理由：標準的なBMPは透過に対応していません
</details>

### 問題3
フルHD（1920×1080）30fpsの10分間の動画を無圧縮で保存した場合、おおよそのファイルサイズはどれか？

- A) 約3.7GB
- B) 約37GB
- C) 約370GB
- D) 約3.7TB

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
計算過程：<br>
1920×1080×3バイト（RGB）×30fps×600秒 = 約37GB<br>
<br>
詳細計算：<br>
- 1フレーム: 1920×1080×3 = 6,220,800バイト<br>
- 1秒間: 6,220,800×30 = 186,624,000バイト<br>
- 10分間: 186,624,000×600 = 111,974,400,000バイト ≈ 37GB<br>
<br>
Aが間違いの理由：1桁計算を間違えています<br>
Cが間違いの理由：1桁大きすぎます<br>
Dが間違いの理由：2桁大きすぎます
</details>

### 問題4
MP3の圧縮で使用される心理音響モデルが利用する現象はどれか？

- A) 視覚マスキング
- B) 聴覚マスキング
- C) 時間マスキング
- D) 空間マスキング

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
MP3は聴覚マスキング現象を利用しています。大きな音の近くにある小さな音は聞こえなくなるという人間の聴覚特性を利用して、聞こえない音の情報を削減することで圧縮率を高めています。<br>
<br>
Aが間違いの理由：視覚マスキングは画像圧縮で使用される概念です<br>
Cが間違いの理由：時間マスキングは聴覚マスキングの一種ですが、より包括的な答えはBです<br>
Dが間違いの理由：空間マスキングは主に画像処理で使用される用語です
</details>

### 問題5
SVGファイルの特徴として誤っているものはどれか？

- A) XML形式で記述される
- B) 拡大縮小しても画質が劣化しない
- C) ビットマップ形式である
- D) JavaScriptで動的に制御できる

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
SVGはベクター形式であり、ビットマップ形式ではありません。数式や座標情報で図形を表現するため、拡大縮小しても画質が劣化しません。<br>
<br>
Aは正しい：SVGはXML形式で記述されます<br>
Bは正しい：ベクター形式なので拡大縮小しても劣化しません<br>
Dは正しい：SVG内にJavaScriptを埋め込んで動的制御が可能です
</details>

### 問題6
H.264とH.265の圧縮効率の関係として正しいものはどれか？

- A) H.265はH.264の約2倍のデータ量になる
- B) H.265はH.264の約半分のデータ量で同等品質を実現
- C) H.265とH.264のデータ量は同じ
- D) H.265はH.264の約10分の1のデータ量になる

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
H.265（HEVC）はH.264（AVC）の後継規格で、同じ画質を約半分のビットレートで実現できます。これにより、4K/8K動画の配信が現実的になりました。<br>
<br>
Aが間違いの理由：逆の関係です。H.265の方が効率的です<br>
Cが間違いの理由：H.265の方が圧縮効率が高いです<br>
Dが間違いの理由：10分の1は過大評価で、実際は約半分です
</details>

### 問題7
FLACの特徴として正しいものはどれか？

- A) 非可逆圧縮で音質が劣化する
- B) 可逆圧縮で元の音質を完全に保持する
- C) 無圧縮でファイルサイズが大きい

## 7. 専門用語集

このスライドで使用された専門用語について、アルファベット順・50音順で解説します。

### アルファベット

**AAC (Advanced Audio Coding)**
- **読み方**: エーエーシー
- **意味**: MP3の後継として開発された音声圧縮形式。同じビットレートでMP3より高音質を実現
- **関連用語**: MP3、HE-AAC、音声コーデック

**API (Application Programming Interface)**
- **読み方**: エーピーアイ
- **意味**: プログラムから特定の機能を利用するためのインターフェース
- **関連用語**: SDK、WebCodecs API

**AV1**
- **読み方**: エーブイワン
- **意味**: Alliance for Open Mediaが開発した次世代動画コーデック。ロイヤリティフリー
- **関連用語**: VP9、H.265、動画コーデック

**AVI (Audio Video Interleave)**
- **読み方**: エーブイアイ
- **意味**: Microsoftが開発した動画コンテナ形式。様々なコーデックに対応
- **関連用語**: コンテナ形式、動画ファイル

**BMP (Bitmap)**
- **読み方**: ビーエムピー、ビットマップ
- **意味**: Windows標準の無圧縮画像形式
- **関連用語**: ラスター形式、画像ファイル

**DRM (Digital Rights Management)**
- **読み方**: ディーアールエム
- **意味**: デジタル著作権管理。コンテンツの不正コピーを防ぐ技術
- **関連用語**: 著作権保護、コピープロテクト

**DSD (Direct Stream Digital)**
- **読み方**: ディーエスディー
- **意味**: 1ビット方式のデジタル音声記録方式。SACDで使用
- **関連用語**: SACD、ハイレゾ音源

**FLAC (Free Lossless Audio Codec)**
- **読み方**: フラック
- **意味**: オープンソースの可逆圧縮音声形式
- **関連用語**: 可逆圧縮、ロスレス音源

**FPS (Frames Per Second)**
- **読み方**: エフピーエス
- **意味**: 1秒間に表示されるフレーム数。動画の滑らかさを表す
- **関連用語**: フレームレート、動画品質

**GIF (Graphics Interchange Format)**
- **読み方**: ジフ（またはギフ）
- **意味**: 256色までの画像を扱える形式。アニメーション対応
- **関連用語**: インデックスカラー、アニメーション画像

**H.264 (AVC)**
- **読み方**: エイチドットニーロクヨン
- **意味**: 現在最も普及している動画圧縮規格
- **関連用語**: AVC、動画コーデック、MPEG-4 Part 10

**H.265 (HEVC)**
- **読み方**: エイチドットニーロクゴ
- **意味**: H.264の後継規格。同品質で約半分のデータ量を実現
- **関連用語**: HEVC、4K動画、次世代コーデック

**HDR (High Dynamic Range)**
- **読み方**: エイチディーアール
- **意味**: 従来より広い明暗の幅を表現できる技術
- **関連用語**: ダイナミックレンジ、画質向上技術

**JPEG (Joint Photographic Experts Group)**
- **読み方**: ジェイペグ
- **意味**: 最も普及した非可逆圧縮の画像形式
- **関連用語**: 非可逆圧縮、DCT、写真画像

**MKV (Matroska Video)**
- **読み方**: エムケーブイ、マトリョーシカ
- **意味**: オープンソースの動画コンテナ形式。多機能で柔軟
- **関連用語**: コンテナ形式、マルチトラック

**MOV (QuickTime Movie)**
- **読み方**: エムオーブイ、ムーブ
- **意味**: Apple開発の動画形式。MP4の基になった
- **関連用語**: QuickTime、Apple、動画形式

**MP3 (MPEG-1 Audio Layer 3)**
- **読み方**: エムピースリー
- **意味**: 最も普及した音声圧縮形式。心理音響モデルを使用
- **関連用語**: 非可逆圧縮、音声コーデック、心理音響

**MP4 (MPEG-4 Part 14)**
- **読み方**: エムピーフォー
- **意味**: 最も汎用的な動画コンテナ形式
- **関連用語**: コンテナ形式、H.264、ストリーミング

**PCM (Pulse Code Modulation)**
- **読み方**: ピーシーエム
- **意味**: アナログ信号をデジタル化する基本的な方式
- **関連用語**: デジタル音声、サンプリング、量子化

**PNG (Portable Network Graphics)**
- **読み方**: ピング、ピーエヌジー
- **意味**: 可逆圧縮でアルファチャンネル対応の画像形式
- **関連用語**: 可逆圧縮、透過画像、Web画像

**SVG (Scalable Vector Graphics)**
- **読み方**: エスブイジー
- **意味**: XML形式で記述されるベクター画像形式
- **関連用語**: ベクター形式、XML、スケーラブル

**TIFF (Tagged Image File Format)**
- **読み方**: ティフ
- **意味**: 高品質な画像保存に適した形式。メタデータ保存可能
- **関連用語**: 高品質画像、メタデータ、アーカイブ

**VP9**
- **読み方**: ブイピーナイン
- **意味**: Googleが開発したオープンソースの動画コーデック
- **関連用語**: WebM、YouTube、オープンソース

**WAV (Waveform Audio Format)**
- **読み方**: ワブ、ウェーブ
- **意味**: Windows標準の無圧縮音声形式
- **関連用語**: PCM、無圧縮音声、高音質

**WebM**
- **読み方**: ウェブエム
- **意味**: Web配信に特化した動画形式。VP8/VP9/AV1使用
- **関連用語**: Web動画、HTML5、オープンフォーマット

**WebP**
- **読み方**: ウェッピー
- **意味**: Googleが開発した新しい画像形式。高圧縮効率
- **関連用語**: 次世代画像形式、Google、Web最適化

**WMA (Windows Media Audio)**
- **読み方**: ダブリューエムエー
- **意味**: Microsoft開発の音声形式。DRM対応
- **関連用語**: Windows Media、DRM、音声圧縮

**WMV (Windows Media Video)**
- **読み方**: ダブリューエムブイ
- **意味**: Microsoft開発の動画形式
- **関連用語**: Windows Media、動画形式、ストリーミング

### あ行

**アスペクト比（あすぺくとひ）**
- **意味**: 画面や画像の横と縦の比率。16:9、4:3など
- **関連用語**: 画面比率、解像度

**アルファチャンネル（あるふぁちゃんねる）**
- **意味**: 画像の透明度情報を保存するチャンネル
- **関連用語**: 透過、PNG、RGBA

**インターレース（いんたーれーす）**
- **意味**: 走査線を奇数と偶数に分けて交互に表示する方式
- **関連用語**: プログレッシブ、走査方式

**インデックスカラー（いんでっくすからー）**
- **意味**: 限られた色数（通常256色以下）で画像を表現する方式
- **関連用語**: パレット、GIF、色数制限

### か行

**可逆圧縮（かぎゃくあっしゅく）**
- **意味**: 圧縮しても元のデータを完全に復元できる圧縮方式
- **関連用語**: ロスレス、PNG、FLAC

**画素（がそ）**
- **意味**: デジタル画像を構成する最小単位。ピクセルとも呼ぶ
- **関連用語**: ピクセル、解像度、ラスター

**コーデック（こーでっく）**
- **意味**: データの圧縮・展開を行うプログラムや方式
- **関連用語**: エンコード、デコード、圧縮方式

**コンテナ形式（こんてなけいしき）**
- **意味**: 映像、音声、字幕などを格納するファイル形式
- **関連用語**: MP4、MKV、マルチメディアファイル

### さ行

**サンプリング周波数（さんぷりんぐしゅうはすう）**
- **意味**: 1秒間にアナログ信号をデジタル化する回数
- **関連用語**: Hz、音質、デジタル音声

**心理音響モデル（しんりおんきょうもでる）**
- **意味**: 人間の聴覚特性を利用した音声圧縮技術
- **関連用語**: 聴覚マスキング、MP3、AAC

### た行

**透過（とうか）**
- **意味**: 画像の一部を透明にする機能
- **関連用語**: アルファチャンネル、PNG、GIF

### な行

**ノンリニア編集（のんりにあへんしゅう）**
- **意味**: デジタルデータを自由な順序で編集できる方式
- **関連用語**: 動画編集、タイムライン

### は行

**ハイレゾ音源（はいれぞおんげん）**
- **意味**: CD品質を超える高解像度の音源
- **関連用語**: 高音質、サンプリング周波数、量子化ビット数

**ビットレート（びっとれーと）**
- **意味**: 1秒間に処理されるデータ量。bpsで表記
- **関連用語**: データ転送速度、品質、圧縮率

**非可逆圧縮（ひかぎゃくあっしゅく）**
- **意味**: 圧縮により一部の情報が失われる圧縮方式
- **関連用語**: ロッシー、JPEG、MP3

**フレームレート（ふれーむれーと）**
- **意味**: 1秒間に表示される画像の枚数。fpsで表記
- **関連用語**: fps、動画の滑らかさ、60fps

**ベクター形式（べくたーけいしき）**
- **意味**: 数式や座標で図形を表現する画像形式
- **関連用語**: SVG、拡大縮小、ベクトルグラフィックス

### ま行

**マルチトラック（まるちとらっく）**
- **意味**: 複数の映像・音声・字幕を1つのファイルに格納する機能
- **関連用語**: MKV、多重音声、多言語対応

**メタデータ（めたでーた）**
- **意味**: ファイルに関する付加情報（作成日、著作権等）
- **関連用語**: タグ情報、EXIF、ID3

### や行

**量子化（りょうしか）**
- **意味**: 連続的なアナログ値を離散的なデジタル値に変換すること
- **関連用語**: A/D変換、ビット深度、デジタル化

**量子化ビット数（りょうしかびっとすう）**
- **意味**: 音の強弱を表現するために使用するビット数
- **関連用語**: ビット深度、音質、16bit/24bit

### ら行

**ラスター形式（らすたーけいしき）**
- **意味**: ピクセルの集合として画像を表現する形式
- **関連用語**: ビットマップ、JPEG、PNG

**ロスレス（ろすれす）**
- **意味**: データの損失がない圧縮方式。可逆圧縮と同義
- **関連用語**: 可逆圧縮、FLAC、PNG

**ロッシー（ろっしー）**
- **意味**: データの一部が失われる圧縮方式。非可逆圧縮と同義
- **関連用語**: 非可逆圧縮、JPEG、MP3

### わ行

**ワークフロー（わーくふろー）**
- **意味**: 作業の流れや手順。マルチメディア制作の工程
- **関連用語**: 制作プロセス、パイプライン
