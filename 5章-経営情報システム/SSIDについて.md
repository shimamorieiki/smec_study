# SSIDについて

## 概要
SSID（Service Set Identifier）は、無線LANにおけるアクセスポイントやネットワークを識別するための名前です。無線LAN環境では、複数のネットワークが同じ場所で運用されることがあるため、各ネットワークを一意に識別し、ユーザーが接続したいネットワークを選択できるようにする仕組みが必要です。SSIDはこの識別子として機能し、最大32バイトの英数字で構成されます。現代のオフィスや公共空間では、Wi-Fi接続が不可欠となっており、SSIDの適切な設定と管理は、ネットワークセキュリティとユーザビリティの両面で重要な役割を果たしています。

## 1. 基本概念・仕組み

### SSIDの定義
- **定義**: IEEE 802.11規格で定められた無線LANネットワークの識別子
- **動作原理**: アクセスポイントが定期的にビーコンフレームを送信し、SSIDを含むネットワーク情報をブロードキャストする
- **特徴**: 人間が読める形式の文字列で、ネットワークの目的や所有者を示すことが一般的

### 技術的仕組み
- **ビーコンフレーム**: 通常100ミリ秒間隔で送信される管理フレーム
- **プローブ要求/応答**: クライアントが特定のSSIDを検索する際に使用
- **アソシエーション**: クライアントがSSIDを指定してネットワークに参加するプロセス

### 関連プロトコルとの関係
- **従来技術との違い**: 有線LANでは物理的な接続で識別されるが、無線LANではSSIDによる論理的な識別が必要
- **改善点**: 複数のネットワークを同一空間で運用可能にし、柔軟なネットワーク構成を実現
- **限界**: SSIDだけではセキュリティを確保できず、追加の認証・暗号化が必要

## 2. 種類・分類

### SSIDの運用方式による分類
SSIDは、その公開方法や運用形態によって以下のように分類されます。

### ブロードキャストSSID
**特徴:**
- アクセスポイントが定期的にSSIDを含むビーコンを送信
- クライアントデバイスの利用可能なネットワーク一覧に表示される
- 一般的な運用方式で、ユーザビリティが高い

**設定方法:**
```
# Cisco IOSの例
interface Dot11Radio0
 ssid PUBLIC_WIFI
  authentication open
  guest-mode
```

**📊 具体的な設定例**
**例: カフェの公衆Wi-Fi設定**
- SSID名: CAFE_GUEST_WIFI
- ブロードキャスト: 有効
- 認証方式: WPA2-PSK

**ステップ1: アクセスポイントの基本設定**
```
SSID設定: "CAFE_GUEST_WIFI"
ブロードキャスト: Enable
セキュリティ: WPA2-Personal
```

**ステップ2: ゲスト用ネットワークの分離**
```
VLAN ID: 100 (ゲスト用)
IPアドレス範囲: 192.168.100.0/24
インターネットアクセスのみ許可
```

**結果: ユーザーは簡単に接続でき、内部ネットワークから隔離される**

💡 **実際の現場では**: 多くの公共施設や商業施設では、この方式を採用してユーザーの利便性を優先しています。

### ステルスSSID（非公開SSID）
**特徴:**
- ビーコンフレームにSSIDを含めない
- クライアントが明示的にSSIDを指定して接続する必要がある
- セキュリティの観点では限定的な効果

**設定方法:**
```
# Windows Server DHCPの例
netsh wlan set hostednetwork mode=allow ssid=HIDDEN_NETWORK key=password
netsh wlan set broadcast ssid=HIDDEN_NETWORK disable
```

**📊 具体的な設定例**
**例: 企業の管理用ネットワーク**
- SSID名: CORP_ADMIN_NET
- ブロードキャスト: 無効
- 認証方式: WPA3-Enterprise

**ステップ1: SSIDの非公開設定**
```
SSIDブロードキャスト: Disable
プローブ応答: 特定のMACアドレスのみ
```

**ステップ2: 追加のセキュリティ層**
```
MACアドレスフィルタリング: 有効
RADIUS認証: 必須
証明書ベース認証: 実装
```

**結果: 一般ユーザーからは見えず、許可されたデバイスのみ接続可能**

💡 **実際の現場では**: ステルスSSIDだけでセキュリティを確保することはできません。必ず他のセキュリティ対策と組み合わせて使用します。

### マルチSSID
**特徴:**
- 1つのアクセスポイントで複数のSSIDを同時に運用
- 各SSIDに異なるセキュリティポリシーやVLANを適用可能
- リソースの効率的な利用が可能

**設定方法:**
```
# Cisco Aironetの例
dot11 ssid EMPLOYEE
 vlan 10
 authentication open eap eap_methods
 
dot11 ssid GUEST
 vlan 20
 authentication open
 guest-mode
```

## 3. 詳細仕様・パラメータ

### SSIDの技術仕様
#### 文字数と形式
- **意味**: ネットワーク識別子の長さと使用可能文字
- **設定範囲**: 1〜32バイト（ASCII文字）
- **影響**: 長すぎると一部のデバイスで表示問題が発生する可能性
- **推奨値**: 8〜20文字程度で意味のある名前

#### ビーコン間隔
- **意味**: SSIDを含むビーコンフレームの送信間隔
- **設定範囲**: 20〜1000ミリ秒（通常100ms）
- **影響**: 短いと発見が早いが、帯域を消費する
- **推奨値**: 100ミリ秒（デフォルト値）

#### DTIM（Delivery Traffic Indication Message）
- **意味**: 省電力モードのクライアントへのデータ配信タイミング
- **設定範囲**: 1〜255（ビーコン間隔の倍数）
- **影響**: バッテリー寿命とレスポンスのトレードオフ
- **推奨値**: 1〜3（モバイルデバイスが多い環境）

## 4. 実装例・適用事例

### 基本実装
```bash
# Linux (hostapd)での基本的なSSID設定
# /etc/hostapd/hostapd.conf

interface=wlan0
driver=nl80211
ssid=MyNetwork
hw_mode=g
channel=6
auth_algs=1
wpa=2
wpa_passphrase=MySecurePassword
wpa_key_mgmt=WPA-PSK
rsn_pairwise=CCMP
```

### 応用実装
```python
# PythonでのSSIDスキャンと接続
import subprocess
import re

def scan_wifi_networks():
    """利用可能なWi-Fiネットワークをスキャン"""
    try:
        # nmcliを使用してネットワークをスキャン
        result = subprocess.run(['nmcli', 'dev', 'wifi'], 
                              capture_output=True, 
                              text=True)
        
        # SSIDを抽出
        lines = result.stdout.strip().split('\n')[1:]  # ヘッダーをスキップ
        networks = []
        
        for line in lines:
            parts = line.split()
            if len(parts) >= 2:
                ssid = parts[1]
                signal = parts[7] if len(parts) > 7 else 'N/A'
                security = parts[8] if len(parts) > 8 else 'Open'
                
                networks.append({
                    'ssid': ssid,
                    'signal': signal,
                    'security': security
                })
        
        return networks
        
    except Exception as e:
        print(f"エラー: {e}")
        return []

def connect_to_network(ssid, password=None):
    """指定したSSIDに接続"""
    try:
        if password:
            cmd = ['nmcli', 'dev', 'wifi', 'connect', ssid, 'password', password]
        else:
            cmd = ['nmcli', 'dev', 'wifi', 'connect', ssid]
            
        result = subprocess.run(cmd, capture_output=True, text=True)
        
        if result.returncode == 0:
            print(f"'{ssid}'に正常に接続しました")
            return True
        else:
            print(f"接続エラー: {result.stderr}")
            return False
            
    except Exception as e:
        print(f"エラー: {e}")
        return False

# 使用例
if __name__ == "__main__":
    # 利用可能なネットワークをスキャン
    networks = scan_wifi_networks()
    
    print("利用可能なネットワーク:")
    for i, network in enumerate(networks):
        print(f"{i+1}. SSID: {network['ssid']}, "
              f"信号強度: {network['signal']}, "
              f"セキュリティ: {network['security']}")
```

### 実際の適用事例

#### 事例1: 大手小売チェーンの統合Wi-Fi環境
- **課題**: 全国500店舗で統一的なWi-Fi環境を提供
- **適用方法**: 
  - 従業員用SSID: CORP_STAFF（WPA3-Enterprise）
  - 顧客用SSID: STORE_GUEST（キャプティブポータル付き）
  - IoTデバイス用SSID: IOT_DEVICES（MACアドレス認証）
- **結果**: ネットワークの分離により、セキュリティを確保しながら各用途に最適化されたサービスを提供
- **効果**: インシデント発生率80%削減、顧客満足度15%向上

#### 事例2: 大学キャンパスのeduroam実装
- **課題**: 国際的な教育機関間でのシームレスなWi-Fi接続
- **適用方法**:
  - SSID: eduroam（世界共通）
  - 認証: IEEE 802.1X（RADIUS連携）
  - ローミング: 各機関のRADIUSサーバー間で認証情報を相互参照
- **結果**: 世界106カ国、10,000以上の機関で相互接続可能
- **効果**: 研究者・学生の国際的な移動時の利便性が大幅に向上

## 5. メリット・デメリット

### メリット
**1. ネットワークの識別と選択の容易性**
- **理由**: 人間が読める形式でネットワークを表示
- **効果**: ユーザーが目的のネットワークを簡単に見つけて接続可能
- **具体例**: 空港で"AIRPORT_FREE_WIFI"を簡単に識別

**2. 複数ネットワークの同時運用**
- **理由**: 同一エリアで複数のSSIDを使い分け可能
- **効果**: 用途別にネットワークを分離してセキュリティを向上
- **具体例**: オフィスビルで階層ごと、部門ごとに異なるSSIDを設定

**3. 柔軟なアクセス制御**
- **理由**: SSID単位でセキュリティポリシーを設定可能
- **効果**: ユーザーグループごとに適切なアクセス権限を付与
- **具体例**: ゲスト用は制限付き、従業員用はフルアクセス

### デメリット
**1. SSIDの露出によるセキュリティリスク**
- **理由**: ブロードキャストSSIDは誰でも確認可能
- **影響**: 悪意のある第三者による標的型攻撃のリスク
- **対策**: 重要なネットワークではSSIDに企業名を含めない

**2. なりすましアクセスポイントの脅威**
- **理由**: SSIDは簡単に複製可能
- **影響**: Evil Twin攻撃による情報漏洩のリスク
- **対策**: 証明書ベースの認証（WPA3-Enterprise）の導入

**3. 管理の複雑性**
- **理由**: マルチSSID環境では設定と運用が複雑化
- **影響**: 設定ミスによるセキュリティホールの発生
- **対策**: 統合管理ツールの導入と定期的な監査

### SSID設計の基準
| 観点 | ブロードキャストSSID | ステルスSSID | マルチSSID |
|------|---------------------|--------------|------------|
| 利便性 | ◎ | △ | ○ |
| セキュリティ | ○ | ○ | ◎ |
| 管理コスト | ◎ | ○ | △ |
| 拡張性 | ○ | △ | ◎ |

### 適用判断フローチャート
1. **公共/ゲストアクセスが必要か？** 
   - Yes → ブロードキャストSSID（キャプティブポータル付き）
   - No → 次の判断へ

2. **複数のユーザーグループが存在するか？**
   - Yes → マルチSSID（グループごとに設定）
   - No → 次の判断へ

3. **高度なセキュリティが必要か？**
   - Yes → ステルスSSID + WPA3-Enterprise
   - No → ブロードキャストSSID + WPA2/WPA3-PSK

## 8. 理解度確認クイズ（4択問題20問）

### 問題1
SSIDの最大文字数として正しいものはどれか？

- A) 16バイト
- B) 32バイト
- C) 64バイト
- D) 128バイト

<details>
<summary>解答</summary>
<strong>正解: B) 32バイト</strong><br>
SSIDはIEEE 802.11規格で最大32バイトと定められています。これはASCII文字で32文字まで設定可能ということを意味します。<br>
<br>
Aが間違いの理由：16バイトは一部の古いシステムでの制限であり、規格上の最大値ではありません。<br>
Cが間違いの理由：64バイトはSSIDではなく、WPA2のパスフレーズの最大長です。<br>
Dが間違いの理由：128バイトはSSIDの規格を大きく超えています。
</details>

### 問題2
ビーコンフレームのデフォルト送信間隔として一般的な値はどれか？

- A) 10ミリ秒
- B) 100ミリ秒
- C) 1000ミリ秒
- D) 10000ミリ秒

<details>
<summary>解答</summary>
<strong>正解: B) 100ミリ秒</strong><br>
多くの無線LANアクセスポイントでは、ビーコンフレームのデフォルト送信間隔は100ミリ秒（0.1秒）に設定されています。<br>
<br>
Aが間違いの理由：10ミリ秒は短すぎて、無線帯域を過度に消費してしまいます。<br>
Cが間違いの理由：1000ミリ秒（1秒）は長すぎて、クライアントの接続に時間がかかります。<br>
Dが間違いの理由：10000ミリ秒（10秒）は実用的ではなく、ネットワーク検出が困難になります。
</details>

### 問題3
ステルスSSID（非公開SSID）について正しい説明はどれか？

- A) 完全にセキュアで、ハッカーから見えなくなる
- B) ビーコンフレームにSSIDを含めないが、プローブ応答では送信される
- C) 通信速度が向上する
- D) 電波の到達距離が短くなる

<details>
<summary>解答</summary>
<strong>正解: B) ビーコンフレームにSSIDを含めないが、プローブ応答では送信される</strong><br>
ステルスSSIDは定期的なビーコンフレームではSSIDを空欄にしますが、クライアントからのプローブ要求に対しては応答でSSIDを返すため、完全に隠蔽されるわけではありません。<br>
<br>
Aが間違いの理由：パケットキャプチャツールを使えば、通信を監視してSSIDを発見できます。<br>
Cが間違いの理由：SSIDの公開/非公開は通信速度に影響しません。<br>
Dが間違いの理由：電波の物理的特性は変わらないため、到達距離も変わりません。
</details>

### 問題4
マルチSSID機能の主な利点として適切でないものはどれか？

- A) 1つのアクセスポイントで複数のネットワークを運用できる
- B) SSIDごとに異なるセキュリティポリシーを適用できる
- C) 無線の通信速度が向上する
- D) VLANと連携してネットワークを論理的に分離できる

<details>
<summary>解答</summary>
<strong>正解: C) 無線の通信速度が向上する</strong><br>
マルチSSIDは複数のネットワークを効率的に運用するための機能であり、通信速度の向上には寄与しません。むしろ、複数のSSIDで帯域を共有するため、個々の速度は低下する可能性があります。<br>
<br>
Aは正しい：1台のAPで最大16個程度のSSIDを同時運用可能です。<br>
Bは正しい：各SSIDに個別のセキュリティ設定（WPA2/WPA3、認証方式等）を適用できます。<br>
Dは正しい：各SSIDを異なるVLANにマッピングして、トラフィックを分離できます。
</details>

### 問題5
SSIDに使用できない文字として正しいものはどれか？

- A) 英数字
- B) スペース
- C) ハイフン（-）
- D) 制御文字（NULL文字など）

<details>
<summary>解答</summary>
<strong>正解: D) 制御文字（NULL文字など）</strong><br>
SSIDは印刷可能なASCII文字を使用する必要があり、NULL文字やタブなどの制御文字は使用できません。<br>
<br>
Aが間違いの理由：英数字は最も一般的に使用される文字です。<br>

Cが間違いの理由：ハイフンは問題なく使用できる記号です。
</details>

### 問題6
企業でゲスト用Wi-Fiを提供する際、最も適切なSSID設計はどれか？

- A) 企業名をそのまま使用（例：TOYOTA_WIFI）
- B) 用途が分かる汎用的な名前（例：GUEST_WIFI）
- C) ランダムな文字列（例：X9K2M5P8）
- D) 部署名と階数の組み合わせ（例：SALES_3F）

<details>
<summary>解答</summary>
<strong>正解: B) 用途が分かる汎用的な名前（例：GUEST_WIFI）</strong><br>
ゲスト用Wi-Fiでは、訪問者が容易に識別できる名前を使用しつつ、企業の詳細情報を含めないことがセキュリティ上推奨されます。<br>
<br>
Aが間違いの理由：企業名を含めると、標的型攻撃の対象になりやすくなります。<br>
Cが間違いの理由：ランダムな文字列では、正規のゲストが接続先を識別できません。<br>
Dが間違いの理由：内部組織の情報を露出させることはセキュリティリスクとなります。
</details>

### 問題7
WPA3-Enterpriseと組み合わせて使用する認証プロトコルはどれか？

- A) WEP
- B) IEEE 802.1X
- C) PPPoE
- D) DHCP

<details>
<summary>解答</summary>
<strong>正解: B) IEEE 802.1X</strong><br>
WPA3-Enterpriseは、IEEE 802.1X認証フレームワークを使用して、RADIUSサーバーと連携した強固な認証を実現します。<br>
<br>
Aが間違いの理由：WEPは古い暗号化方式で、認証プロトコルではありません。<br>
Cが間違いの理由：PPPoEは主に有線接続で使用されるプロトコルです。<br>
Dが間違いの理由：DHCPはIPアドレス自動割り当てのプロトコルで、認証には使用しません。
</details>

### 問題8
Evil Twin攻撃を防ぐ最も効果的な対策はどれか？

- A) SSIDを非公開にする
- B) MACアドレスフィルタリングを使用する
- C) 証明書ベースの相互認証を実装する
- D) 短いパスワードを頻繁に変更する

<details>
<summary>解答</summary>
<strong>正解: C) 証明書ベースの相互認証を実装する</strong><br>
証明書ベースの相互認証により、クライアントはアクセスポイントの正当性を検証でき、偽のアクセスポイントへの接続を防げます。<br>
<br>
Aが間違いの理由：SSIDを非公開にしても、攻撃者は通信を監視してSSIDを知ることができます。<br>
Bが間違いの理由：MACアドレスは簡単に偽装可能です。<br>
Dが間違いの理由：パスワードの強度や変更頻度は、なりすましAPの検出には役立ちません。
</details>

### 問題9
大規模イベント会場で臨時Wi-Fiを設置する際、最も考慮すべき設定はどれか？

- A) SSIDを会場名にする
- B) 同時接続数の上限を適切に設定する
- C) 最高速度に設定する
- D) 1つのSSIDで全てをカバーする

<details>
<summary>解答</summary>

## 9. 専門用語集

このドキュメントで使用された技術用語について、アルファベット順・50音順で解説します。

### アルファベット

**AP (Access Point)**
- **読み方**: エーピー、アクセスポイント
- **意味**: 無線LANにおいて、有線ネットワークと無線デバイスを中継する機器。無線基地局とも呼ばれる
- **関連用語**: WAP (Wireless Access Point)

**BSS (Basic Service Set)**
- **読み方**: ビーエスエス
- **意味**: 1つのアクセスポイントとそれに接続するクライアントで構成される無線LANの基本単位
- **関連用語**: BSSID, ESS, IBSS

**BSSID (Basic Service Set Identifier)**
- **読み方**: ビーエスエスアイディー
- **意味**: アクセスポイントのMACアドレス。同じSSIDでも異なるAPを識別するために使用
- **関連用語**: SSID, BSS

**DHCP (Dynamic Host Configuration Protocol)**
- **読み方**: ディーエイチシーピー
- **意味**: ネットワーク機器にIPアドレスを自動的に割り当てるプロトコル
- **関連用語**: IPアドレス, DNS

**DFS (Dynamic Frequency Selection)**
- **読み方**: ディーエフエス
- **意味**: 5GHz帯でレーダーとの干渉を避けるため、使用チャンネルを動的に変更する機能
- **関連用語**: 5GHz帯, チャンネル

**DTIM (Delivery Traffic Indication Message)**
- **読み方**: ディーティーアイエム
- **意味**: 省電力モードのクライアントに対して、バッファされたブロードキャスト/マルチキャストデータの存在を通知するメッセージ
- **関連用語**: ビーコン, TIM

**EAP (Extensible Authentication Protocol)**
- **読み方**: イーエーピー
- **意味**: IEEE 802.1Xで使用される拡張可能な認証プロトコル
- **関連用語**: 802.1X, RADIUS, WPA-Enterprise

**ESS (Extended Service Set)**
- **読み方**: イーエスエス
- **意味**: 複数のBSSが同じSSIDで連携して構成する拡張無線LANサービス
- **関連用語**: BSS, SSID, ローミング

**Evil Twin**
- **読み方**: イーブルツイン
- **意味**: 正規のアクセスポイントになりすました悪意のあるAP。同じSSIDを使用して利用者を欺く
- **関連用語**: なりすましAP, セキュリティ脅威

**IEEE 802.11**
- **読み方**: アイトリプルイー はちまるに てん いちいち
- **意味**: 無線LANの国際標準規格。Wi-Fiの技術仕様を定義
- **関連用語**: Wi-Fi, 無線LAN

**IEEE 802.1X**
- **読み方**: アイトリプルイー はちまるに てん いちエックス
- **意味**: ポートベースのネットワークアクセス制御規格。企業向け無線LAN認証で使用
- **関連用語**: EAP, RADIUS, WPA-Enterprise

**MAC Address (Media Access Control Address)**
- **読み方**: マックアドレス
- **意味**: ネットワーク機器に割り当てられた固有の物理アドレス。48ビットで表現
- **関連用語**: MACアドレスフィルタリング, BSSID

**NAN (Neighbor Awareness Networking)**
- **読み方**: ナン
- **意味**: Wi-Fi Awareの技術基盤。近隣デバイスの発見と通信を可能にする
- **関連用語**: Wi-Fi Aware, P2P

**PSK (Pre-Shared Key)**
- **読み方**: ピーエスケー
- **意味**: 事前共有鍵。WPA-PersonalやWPA2-Personalで使用するパスワード方式
- **関連用語**: WPA, パスフレーズ

**RADIUS (Remote Authentication Dial In User Service)**
- **読み方**: ラディウス
- **意味**: ネットワークアクセスの認証、認可、アカウンティングを提供するプロトコル
- **関連用語**: 802.1X, AAA, WPA-Enterprise

**SSID (Service Set Identifier)**
- **読み方**: エスエスアイディー
- **意味**: 無線LANネットワークを識別するための名前。最大32バイトのASCII文字列
- **関連用語**: BSSID, ESS

**VLAN (Virtual Local Area Network)**
- **読み方**: ブイラン
- **意味**: 物理的な接続に依存せず、論理的にネットワークを分割する技術
- **関連用語**: ネットワーク分離, マルチSSID

**WEP (Wired Equivalent Privacy)**
- **読み方**: ウェップ
- **意味**: 初期の無線LAN暗号化規格。現在は脆弱性があり使用非推奨
- **関連用語**: WPA, セキュリティ

**Wi-Fi**
- **読み方**: ワイファイ
- **意味**: Wi-Fi Allianceが定めた無線LAN製品の相互接続性を保証するブランド名
- **関連用語**: IEEE 802.11, 無線LAN

**WPA (Wi-Fi Protected Access)**
- **読み方**: ダブリューピーエー
- **意味**: WEPの脆弱性を改善した無線LANセキュリティ規格
- **関連用語**: WPA2, WPA3, 暗号化

**WPS (Wi-Fi Protected Setup)**
- **読み方**: ダブリューピーエス
- **意味**: 簡単な操作で無線LAN機器を接続するための規格
- **関連用語**: PINコード, プッシュボタン

### あ行
