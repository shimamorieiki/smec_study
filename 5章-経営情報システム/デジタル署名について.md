# デジタル署名について

## 概要
デジタル署名は、電子文書の真正性（本人が作成したこと）と完全性（改ざんされていないこと）を保証する暗号技術です。紙の文書における印鑑や手書き署名に相当する役割を電子的に実現し、電子商取引や電子政府サービスなど、デジタル社会における信頼性の基盤となっています。公開鍵暗号方式を基礎として、数学的に検証可能な形で文書の正当性を証明します。

## 1. 基本概念・仕組み

### デジタル署名の核となる概念
- **定義**: 電子文書に対して、作成者の本人性と文書の非改ざん性を暗号技術によって保証する仕組み
- **動作原理**: 公開鍵暗号方式を利用し、秘密鍵で署名を生成し、公開鍵で検証する非対称暗号技術
- **特徴**: 
  - 署名者の認証（本人性の保証）
  - 文書の完全性保証（改ざん検知）
  - 否認防止（署名の事実を否定できない）

### 関連技術との関係
- **従来技術との違い**: 
  - 電子印鑑：単なる画像データで偽造が容易
  - パスワード認証：共有秘密に基づき、否認防止機能がない
  - デジタル署名：数学的に検証可能で偽造が困難
- **改善点**: 
  - 物理的な印鑑管理が不要
  - 遠隔地からの署名が可能
  - 自動検証により大量処理が可能
- **限界**: 
  - 秘密鍵の安全な管理が必要
  - 証明書の有効期限管理が必要
  - 量子コンピュータによる脅威への対応が今後必要

## 2. 種類・分類

### 暗号アルゴリズムによる分類
デジタル署名は使用する暗号アルゴリズムによって分類されます。

### RSA署名
**特徴:**
- 素因数分解問題の困難性に基づく安全性
- 最も広く普及している署名方式
- 署名生成・検証の処理が比較的高速

**算出方法:**
```
署名生成：s = m^d mod n
署名検証：m' = s^e mod n
（m: メッセージのハッシュ値、d: 秘密鍵、e: 公開鍵、n: 法）
```

**📊 具体的な計算例**
**例: 小さな数値でのRSA署名の動作確認**
- p = 61, q = 53（素数）
- n = p × q = 3233
- φ(n) = (p-1)(q-1) = 3120
- e = 17（公開鍵）
- d = 2753（秘密鍵：e×d ≡ 1 mod φ(n)）

**ステップ1: メッセージのハッシュ値計算**
```
メッセージ: "契約書A"
ハッシュ値: H = 1234（簡略化した例）
```

**ステップ2: 署名生成**
```
s = 1234^2753 mod 3233 = 2468
```

**結果: 署名値 = 2468**

💡 **実際の現場では**: RSA-2048やRSA-4096といった大きな鍵長を使用し、SHA-256などの暗号学的ハッシュ関数と組み合わせて利用します。

### DSA（Digital Signature Algorithm）署名
**特徴:**
- 離散対数問題の困難性に基づく
- 米国政府標準（FIPS 186）として採用
- 署名専用アルゴリズム（暗号化には使用不可）

**算出方法:**
```
署名生成：
  k: ランダムな整数
  r = (g^k mod p) mod q
  s = k^(-1)(H(m) + xr) mod q
  署名 = (r, s)
```

### ECDSA（楕円曲線DSA）署名
**特徴:**
- 楕円曲線上の離散対数問題に基づく
- 短い鍵長で高い安全性を実現
- モバイル機器やIoTデバイスに適している

**利点:**
- RSA-2048と同等の安全性を256ビット鍵で実現
- 処理速度が高速
- 通信量・保存容量が少ない

## 3. 実装仕様・重要なパラメータ

### セキュリティパラメータ
#### 鍵長の選択
- **意味**: 暗号の強度を決定する主要パラメータ
- **設定範囲**: 
  - RSA: 2048ビット以上（推奨：3072ビット以上）
  - ECDSA: 256ビット以上（推奨：384ビット以上）
- **影響**: 鍵長が長いほど安全性は高いが、処理時間も増加
- **推奨値**: 2030年まではRSA-3072、ECDSA-256で十分

#### ハッシュ関数の選択
- **意味**: メッセージを固定長の値に変換する関数
- **設定範囲**: SHA-256、SHA-384、SHA-512、SHA-3
- **影響**: 衝突耐性と処理速度のバランス
- **推奨値**: SHA-256（一般用途）、SHA-512（高セキュリティ用途）

## 4. 実装例・適用事例

### 基本実装（Python）
```python
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.backends import default_backend

# 鍵ペアの生成
private_key = rsa.generate_private_key(
    public_exponent=65537,
    key_size=3072,
    backend=default_backend()
)
public_key = private_key.public_key()

# 署名の生成
message = b"重要な契約書の内容"
signature = private_key.sign(
    message,
    padding.PSS(
        mgf=padding.MGF1(hashes.SHA256()),
        salt_length=padding.PSS.MAX_LENGTH
    ),
    hashes.SHA256()
)

# 署名の検証
try:
    public_key.verify(
        signature,
        message,
        padding.PSS(
            mgf=padding.MGF1(hashes.SHA256()),
            salt_length=padding.PSS.MAX_LENGTH
        ),
        hashes.SHA256()
    )
    print("署名検証成功：文書は改ざんされていません")
except:
    print("署名検証失敗：文書が改ざんされている可能性があります")
```

### 応用実装（タイムスタンプ付き署名）
```python
import datetime
import json
from cryptography.hazmat.primitives import serialization

class TimestampedSignature:
    def __init__(self, private_key):
        self.private_key = private_key
        
    def sign_with_timestamp(self, document):
        # タイムスタンプを含むメタデータ作成
        metadata = {
            "timestamp": datetime.datetime.utcnow().isoformat(),
            "document_hash": self.calculate_hash(document),
            "signer_id": "user123"
        }
        
        # メタデータとドキュメントを結合
        combined_data = json.dumps(metadata) + document
        
        # 署名生成
        signature = self.private_key.sign(
            combined_data.encode(),
            padding.PSS(
                mgf=padding.MGF1(hashes.SHA256()),
                salt_length=padding.PSS.MAX_LENGTH
            ),
            hashes.SHA256()
        )
        
        return {
            "document": document,
            "metadata": metadata,
            "signature": signature.hex()
        }
```

## 5. メリット・デメリット

### メリット
**1. 高度なセキュリティ**
- **理由**: 現代の計算能力では解読が事実上不可能な暗号技術を使用
- **効果**: なりすましや改ざんのリスクを極小化
- **具体例**: 2020年の日本の電子契約における改ざん事例は報告ゼロ

**2. 業務効率の大幅改善**
- **理由**: 物理的な押印・郵送プロセスが不要
- **効果**: 契約締結時間を数週間から数分に短縮
- **具体例**: 大手商社では年間10万件の契約処理時間を80%削減

**3. コスト削減**
- **理由**: 印紙税、郵送費、保管費用が不要
- **効果**: 契約1件あたり平均3,000円のコスト削減
- **具体例**: 不動産取引では印紙税だけで数万円の削減

### デメリット
**1. 鍵管理の複雑性**
- **理由**: 秘密鍵の紛失は署名能力の永久喪失を意味
- **影響**: 厳格な鍵管理体制の構築が必要
- **対策**: HSM（Hardware Security Module）の導入、鍵のバックアップ体制構築

**2. 法的整備の地域差**
- **理由**: 国によってデジタル署名の法的効力が異なる
- **影響**: 国際取引での利用に制限
- **対策**: 各国法制度の事前確認、紙との併用運用

**3. 技術的な導入障壁**
- **理由**: PKI基盤の構築・運用には専門知識が必要
- **影響**: 中小企業での導入が遅れる
- **対策**: クラウド型署名サービスの利用、段階的導入

### デジタル署名方式の選択基準
| 観点 | RSA | DSA | ECDSA |
|------|-----|-----|-------|
| 安全性 | ◎ | ○ | ◎ |
| 処理速度 | ○ | △ | ◎ |
| 鍵サイズ | △ | △ | ◎ |
| 互換性 | ◎ | ○ | ○ |

### 適用判断フローチャート
1. **高い互換性が必要か？** 
   - Yes → RSA-3072以上を推奨
   - No → 次の判断へ

2. **モバイル・IoT環境での利用か？**
   - Yes → ECDSA-P256以上を推奨
   - No → 用途に応じてRSAまたはECDSAを選択

3. **長期保存が必要か？**
   - Yes → 長期署名フォーマット（PAdES、XAdES）の採用
   - No → 標準的なPKCS#7形式で十分

### 問題1
デジタル署名が保証する性質として、正しくないものはどれか？

- A) 署名者の本人性（認証）
- B) 文書の機密性（暗号化）
- C) 文書の完全性（改ざん検知）
- D) 否認防止

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
デジタル署名は文書の機密性（暗号化）を保証しません。デジタル署名は署名者の認証、文書の完全性、否認防止を保証しますが、文書の内容を秘匿する機能はありません。<br>
<br>
Aが間違いの理由：署名者の本人性は秘密鍵の所有によって保証される基本機能です<br>
Cが間違いの理由：文書の完全性はハッシュ値の比較によって保証されます<br>
Dが間違いの理由：否認防止は秘密鍵が本人のみ所有することで実現されます<br>
<br>
【補足】文書の機密性が必要な場合は、デジタル署名とは別に暗号化を行う必要があります。
</details>

### 問題2
RSA署名において、署名の生成に使用する鍵はどれか？

- A) 公開鍵
- B) 秘密鍵
- C) 共通鍵
- D) セッション鍵

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
RSA署名では秘密鍵を使用して署名を生成します。これにより、秘密鍵の所有者のみが有効な署名を作成でき、本人性が保証されます。<br>
<br>
Aが間違いの理由：公開鍵は署名の検証に使用されます<br>
Cが間違いの理由：共通鍵は対称暗号方式で使用され、デジタル署名では使用しません<br>
Dが間違いの理由：セッション鍵は通信の暗号化に使用される一時的な鍵です<br>
<br>
【補足】公開鍵暗号の特徴として、秘密鍵で暗号化（署名）したものは対応する公開鍵でのみ復号（検証）できます。
</details>

### 問題3
2048ビットのRSA鍵と同等の安全性を持つECDSA鍵のビット数はどれか？

- A) 128ビット
- B) 224ビット
- C) 256ビット
- D) 512ビット

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
RSA-2048と同等の安全性は、ECDSA-224で実現できます。楕円曲線暗号は短い鍵長で高い安全性を実現できるという特徴があります。<br>
<br>
Aが間違いの理由：128ビットは現在の基準では安全性が不十分です<br>
Cが間違いの理由：256ビットはRSA-3072相当でより高い安全性です<br>
Dが間違いの理由：512ビットは過剰であり、一般的に使用されません<br>
<br>
【補足】NISTの推奨では、RSA-2048はECDSA-224、RSA-3072はECDSA-256と同等とされています。
</details>

### 問題4
デジタル署名の検証に失敗する原因として、考えられないものはどれか？

- A) 文書が改ざんされている
- B) 間違った公開鍵を使用している
- C) ネットワークが遅い
- D) 署名アルゴリズムが異なる

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
ネットワークの速度は署名検証の成否に影響しません。署名検証は受信したデータに対してローカルで実行される処理だからです。<br>
<br>
Aが間違いの理由：改ざんによりハッシュ値が変わると検証は失敗します<br>

Dが間違いの理由：生成時と異なるアルゴリズムでは検証できません<br>
<br>
【補足】ネットワークは公開鍵の取得時には必要ですが、検証処理自体には影響しません。
</details>

ハッシュ関数の役割として正しいものはどれか？

- A) 任意長のデータを固定長の値に変換する
- B) データを暗号化する
- C) 鍵を生成する
- D) 署名を検証する

<details>
<summary>解答</summary>
<strong>正解: A</strong><br>
ハッシュ関数は任意の長さのデータを固定長のハッシュ値に変換します。デジタル署名では、長い文書全体ではなくハッシュ値に対して署名を行います。<br>

Dが間違いの理由：署名検証は公開鍵暗号アルゴリズムが行います<br>

### 問題6

<details>
<summary>解答</summary>

## 9. 専門用語集

このドキュメントで使用された専門用語について、アルファベット順・50音順で解説します。

### アルファベット

**CA (Certificate Authority)**
- **読み方**: シーエー（認証局）
- **意味**: デジタル証明書を発行する信頼できる第三者機関。公開鍵とその所有者の身元を結びつける証明書を発行し、PKIの信頼の起点となる
- **関連用語**: PKI、デジタル証明書、ルートCA

**CRL (Certificate Revocation List)**
- **読み方**: シーアールエル
- **意味**: 有効期限前に失効した証明書のリスト。秘密鍵の漏洩や証明書の不正使用があった場合に証明書を無効化するために使用
- **関連用語**: OCSP、証明書失効

**DSA (Digital Signature Algorithm)**
- **読み方**: ディーエスエー
- **意味**: 米国政府標準の署名専用アルゴリズム。離散対数問題の困難性に基づき、署名生成と検証のみが可能（暗号化は不可）
- **関連用語**: ECDSA、離散対数問題

**ECDSA (Elliptic Curve Digital Signature Algorithm)**
- **読み方**: イーシーディーエスエー
- **意味**: 楕円曲線暗号を用いたデジタル署名アルゴリズム。短い鍵長で高い安全性を実現し、モバイル機器やIoTに適している
- **関連用語**: 楕円曲線暗号、DSA

**HSM (Hardware Security Module)**
- **読み方**: エイチエスエム
- **意味**: 暗号鍵を安全に保管・処理する専用ハードウェア。耐タンパー性を持ち、物理的攻撃からも鍵を保護する
- **関連用語**: 鍵管理、耐タンパー性

**OCSP (Online Certificate Status Protocol)**
- **読み方**: オーシーエスピー
- **意味**: 証明書の有効性をリアルタイムで確認するプロトコル。CRLよりも最新の失効情報を取得できる
- **関連用語**: CRL、証明書検証

**PAdES (PDF Advanced Electronic Signatures)**
- **読み方**: パデス
- **意味**: PDF文書に長期保存可能なデジタル署名を埋め込むための欧州標準規格。タイムスタンプや検証情報を含む
- **関連用語**: XAdES、CAdES、長期署名

**PKI (Public Key Infrastructure)**
- **読み方**: ピーケーアイ（公開鍵基盤）
- **意味**: 公開鍵暗号を用いた認証システムの基盤。証明書の発行・管理・失効を行う仕組み全体を指す
- **関連用語**: CA、デジタル証明書

**RSA**
- **読み方**: アールエスエー
- **意味**: Rivest-Shamir-Adleman の頭文字。素因数分解の困難性に基づく公開鍵暗号アルゴリズム。署名と暗号化の両方に使用可能
- **関連用語**: 公開鍵暗号、素因数分解問題

**SHA (Secure Hash Algorithm)**
- **読み方**: シャー（エスエイチエー）
- **意味**: 安全なハッシュアルゴリズムの総称。SHA-256、SHA-512などがあり、任意長のデータを固定長のハッシュ値に変換
- **関連用語**: ハッシュ関数、メッセージダイジェスト

**XAdES (XML Advanced Electronic Signatures)**
- **読み方**: エックスアデス
- **意味**: XML文書に対する長期署名フォーマット。欧州で標準化され、構造化データの署名に適している
- **関連用語**: PAdES、CAdES、XML署名

### あ行

**暗号学的ハッシュ関数（あんごうがくてきハッシュかんすう）**
- **読み方**: あんごうがくてきハッシュかんすう
- **意味**: 一方向性と衝突困難性を持つハッシュ関数。デジタル署名では文書の要約値（フィンガープリント）生成に使用
- **関連用語**: SHA、MD5、ハッシュ値

**一方向性（いっぽうこうせい）**
- **読み方**: いっぽうこうせい
- **意味**: ハッシュ値から元のデータを復元することが計算上困難な性質。ハッシュ関数の重要な特性
- **関連用語**: ハッシュ関数、不可逆性

### か行

**鍵長（かぎちょう）**
- **読み方**: かぎちょう
- **意味**: 暗号鍵のビット数。一般に長いほど安全性が高いが、処理時間も増加する。RSAでは2048ビット以上が推奨
- **関連用語**: ビット強度、暗号強度

**鍵ペア（かぎペア）**
- **読み方**: かぎペア
- **意味**: 公開鍵暗号で使用する公開鍵と秘密鍵の組み合わせ。数学的に関連があり、一方で暗号化したものは他方でのみ復号可能
- **関連用語**: 公開鍵、秘密鍵

**改ざん検知（かいざんけんち）**
- **読み方**: かいざんけんち
- **意味**: データが不正に変更されていないことを確認する機能。デジタル署名により実現される重要な機能の一つ
- **関連用語**: 完全性、ハッシュ値

**完全性（かんぜんせい）**
- **読み方**: かんぜんせい
- **意味**: データが改ざんされていない状態。デジタル署名により保証される性質の一つ
- **関連用語**: 改ざん検知、真正性

**公開鍵（こうかいかぎ）**
- **読み方**: こうかいかぎ
- **意味**: 鍵ペアのうち公開される鍵。署名検証や暗号化に使用。秘密にする必要がない
- **関連用語**: 秘密鍵、鍵ペア

**公開鍵証明書（こうかいかぎしょうめいしょ）**
- **読み方**: こうかいかぎしょうめいしょ
- **意味**: 公開鍵とその所有者の情報を結びつけ、CAが署名した電子的な証明書
- **関連用語**: CA、PKI、X.509

### さ行

**失効（しっこう）**
- **読み方**: しっこう
- **意味**: 有効期限前に証明書を無効にすること。秘密鍵の漏洩や不正使用時に実施
- **関連用語**: CRL、OCSP、証明書

**署名検証（しょめいけんしょう）**
- **読み方**: しょめいけんしょう
- **意味**: デジタル署名の正当性を確認する処理。公開鍵を用いて署名が正しいことを数学的に確認
- **関連用語**: 公開鍵、検証アルゴリズム

**真正性（しんせいせい）**
- **読み方**: しんせいせい
- **意味**: 文書や署名が本物であり、偽造されていないこと。デジタル署名により保証される
- **関連用語**: 完全性、否認防止

### た行

**耐タンパー性（たいタンパーせい）**
- **読み方**: たいタンパーせい
- **意味**: 不正な物理的アクセスや解析に対する耐性。HSMなどのセキュリティデバイスが持つ特性
- **関連用語**: HSM、物理的セキュリティ

**タイムスタンプ（タイムスタンプ）**
- **読み方**: タイムスタンプ
- **意味**: ある時刻にデータが存在したことを証明する仕組み。長期署名で重要な役割を果たす
- **関連用語**: TSA、長期署名

**長期署名（ちょうきしょめい）**
- **読み方**: ちょうきしょめい
- **意味**: 証明書の有効期限を超えて署名の有効性を維持する技術。タイムスタンプと検証情報を含む
- **関連用語**: PAdES、XAdES、アーカイブタイムスタンプ

**電子署名法（でんししょめいほう）**
- **読み方**: でんししょめいほう
- **意味**: 日本の法律で、一定の要件を満たす電子署名に手書き署名と同等の法的効力を認める法律
- **関連用語**: 電子帳簿保存法、法的効力

### な行

**認証局（にんしょうきょく）**
- **読み方**: にんしょうきょく
- **意味**: CAの日本語訳。デジタル証明書を発行する信頼できる第三者機関
- **関連用語**: CA、PKI、ルート認証局

### は行

**ハッシュ値（ハッシュち）**
- **読み方**: ハッシュち
- **意味**: ハッシュ関数により生成される固定長のデータ。元データの「指紋」として機能
- **関連用語**: ハッシュ関数、メッセージダイジェスト

**否認防止（ひにんぼうし）**
- **読み方**: ひにんぼうし
- **意味**: 署名者が後から署名の事実を否定できないようにする性質。デジタル署名の重要な機能
- **関連用語**: 真正性、秘密鍵管理

**秘密鍵（ひみつかぎ）**
- **読み方**: ひみつかぎ
- **意味**: 鍵ペアのうち秘密に保管する鍵。署名生成や復号に使用。漏洩すると安全性が損なわれる
- **関連用語**: 公開鍵、鍵ペア

### ま行

**メッセージダイジェスト（メッセージダイジェスト）**
- **読み方**: メッセージダイジェスト
- **意味**: ハッシュ関数によって生成されるメッセージの要約値。ハッシュ値と同義
- **関連用語**: ハッシュ値、ハッシュ関数

### ら行

**離散対数問題（りさんたいすうもんだい）**
- **読み方**: りさんたいすうもんだい
- **意味**: DSAやECDSAの安全性の基礎となる数学的問題。大きな素数を法とする離散対数の計算困難性
- **関連用語**: DSA、ECDSA、計算量的安全性
