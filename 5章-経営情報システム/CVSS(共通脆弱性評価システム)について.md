# CVSS(共通脆弱性評価システム)について

## 概要
CVSS（Common Vulnerability Scoring System：共通脆弱性評価システム）は、情報システムの脆弱性の深刻度を数値化して評価するための標準的なフレームワークです。2005年にFIRST（Forum of Incident Response and Security Teams）によって開発され、現在は世界中のセキュリティ専門家や組織で広く利用されています。脆弱性の影響度や悪用の容易さを客観的に評価することで、脆弱性対応の優先順位付けやリスク管理に活用されています。

## 1. 基本概念・仕組み

### CVSSの核となる概念
- **定義**: 脆弱性の技術的な特性と時間的な要因、環境要因を考慮して、0.0から10.0までのスコアで脆弱性の深刻度を表現するシステム
- **動作原理**: 複数の評価指標（メトリクス）を組み合わせて計算式に基づいてスコアを算出
- **特徴**: 
  - 標準化された評価基準により客観的な評価が可能
  - 3つの評価基準群（基本評価基準、現状評価基準、環境評価基準）による多面的評価
  - バージョンアップによる継続的な改善

### 従来の脆弱性評価との違い
- **従来技術との違い**: 
  - 主観的な「高・中・低」評価から数値による客観的評価へ
  - ベンダー独自の評価基準から業界標準へ
  - 静的な評価から時間的・環境的要因を含む動的評価へ
- **改善点**: 
  - 評価の一貫性と再現性の向上
  - 異なる組織間での評価結果の比較が可能
  - 自動化ツールとの連携が容易
- **限界**: 
  - ビジネスへの影響は直接評価されない
  - 複数の脆弱性の組み合わせによる影響は考慮されない
  - 評価者の知識や経験による差異は完全には排除できない

## 2. バージョンと分類

### CVSSのバージョン進化
CVSSは継続的に改善されており、現在までに3つの主要バージョンがリリースされています。

### CVSS v2.0 (2007年リリース)
**特徴:**
- 基本評価基準（Base Metrics）の確立
- 時間的評価基準（Temporal Metrics）の導入
- 環境評価基準（Environmental Metrics）の追加

**算出方法:**
```
基本スコア = (0.6 × 影響度 + 0.4 × 悪用可能性 - 1.5) × f(影響度)
ここで、f(影響度) = 0 (影響度が0の場合)、1.176 (それ以外)
```

**📊 具体的な計算例**
**例: SQLインジェクション脆弱性の評価**
- 攻撃元区分(AV): ネットワーク = 1.0
- 攻撃条件の複雑さ(AC): 低 = 0.71
- 認証(Au): 不要 = 0.704

**ステップ1: 悪用可能性の計算**
```
悪用可能性 = 20 × AV × AC × Au
         = 20 × 1.0 × 0.71 × 0.704
         = 9.997
```

**ステップ2: 影響度の計算**
```
影響度 = 10.41 × (1 - (1-C)×(1-I)×(1-A))
      = 10.41 × (1 - (1-0.66)×(1-0.66)×(1-0.66))
      = 10.41 × 0.961
      = 10.004
```

**結果: 基本スコア = 9.0 (重大)**

💡 **実際の現場では**: CVSS v2は現在でも多くのレガシーシステムで使用されており、過去の脆弱性データベースとの互換性維持のため参照されることがあります。

### CVSS v3.1 (2019年リリース)
**特徴:**
- スコープ（Scope）の概念を導入
- ユーザ操作（User Interaction）の明確化
- 権限レベル（Privileges Required）の詳細化

**算出方法:**
```
基本スコア = 
  スコープ未変更の場合: Min(10, (影響度 + 悪用可能性) × 1.08)
  スコープ変更の場合: Min(10, 1.08 × (影響度 + 悪用可能性) × 1.13)
```

**📊 具体的な計算例**
**例: クロスサイトスクリプティング(XSS)脆弱性の評価**
- 攻撃元区分(AV): ネットワーク = 0.85
- 攻撃条件の複雑さ(AC): 低 = 0.77
- 必要な権限(PR): なし = 0.85
- ユーザ操作(UI): 必要 = 0.62
- スコープ(S): 変更

**ステップ1: 悪用可能性サブスコアの計算**
```
悪用可能性 = 8.22 × AV × AC × PR × UI
         = 8.22 × 0.85 × 0.77 × 0.85 × 0.62
         = 2.84
```

**ステップ2: 影響度サブスコアの計算**
```
影響度 = 7.52 × (ISCBase - 0.029) - 3.25 × (ISCBase - 0.02)^15
ISCBase = 1 - ((1-0.22) × (1-0.22) × (1-0.22)) = 0.53
影響度 = 3.7
```

**結果: 基本スコア = 6.1 (中程度)**

### CVSS v4.0 (2023年リリース)
**特徴:**
- 補足評価基準群の追加
- 自動化可能性（Automatable）の評価
- より細かい環境要因の考慮

**新しい評価要素:**
- 脆弱性応答努力（Vulnerability Response Effort）
- プロバイダの緊急度（Provider Urgency）
- 復旧能力（Recovery）

## 3. 詳細仕様・パラメータ

### 基本評価基準（Base Metrics）の詳細
#### 攻撃元区分（Attack Vector: AV）
- **意味**: 脆弱性を悪用するために攻撃者がどこから攻撃可能か
- **設定範囲**: 
  - Network (N): ネットワーク経由でリモートから攻撃可能
  - Adjacent (A): 隣接ネットワークから攻撃可能
  - Local (L): ローカルアクセスが必要
  - Physical (P): 物理的アクセスが必要
- **影響**: 値が大きいほど（Nに近いほど）スコアが高くなる
- **推奨値**: 実際の脆弱性の特性に基づいて選択

#### 攻撃条件の複雑さ（Attack Complexity: AC）
- **意味**: 攻撃を成功させるために必要な条件の複雑さ
- **設定範囲**: 
  - Low (L): 特別な条件なしに攻撃可能
  - High (H): 特定の条件が揃わないと攻撃不可能
- **影響**: Lowの方がスコアが高くなる
- **推奨値**: 攻撃の再現性を基準に判断

#### 必要な権限（Privileges Required: PR）
- **意味**: 攻撃実行に必要な権限レベル
- **設定範囲**: 
  - None (N): 権限不要
  - Low (L): 一般ユーザ権限
  - High (H): 管理者権限
- **影響**: 必要な権限が少ないほどスコアが高くなる
- **推奨値**: 実際に必要な最小権限を選択

## 4. 実装例・適用事例

### 基本実装
```python
# CVSS v3.1 基本スコア計算の実装例
class CVSSv3Calculator:
    def __init__(self):
        # 各メトリクスの重み付け値
        self.metrics_values = {
            'AV': {'N': 0.85, 'A': 0.62, 'L': 0.55, 'P': 0.2},
            'AC': {'L': 0.77, 'H': 0.44},
            'PR': {'N': {'U': 0.85, 'C': 0.85}, 
                   'L': {'U': 0.62, 'C': 0.68},
                   'H': {'U': 0.27, 'C': 0.5}},
            'UI': {'N': 0.85, 'R': 0.62},
            'C': {'N': 0, 'L': 0.22, 'H': 0.56},
            'I': {'N': 0, 'L': 0.22, 'H': 0.56},
            'A': {'N': 0, 'L': 0.22, 'H': 0.56}
        }
    
    def calculate_base_score(self, av, ac, pr, ui, s, c, i, a):
        # 悪用可能性サブスコアの計算
        exploitability = 8.22 * self.metrics_values['AV'][av]
        exploitability *= self.metrics_values['AC'][ac]
        exploitability *= self.metrics_values['PR'][pr][s]
        exploitability *= self.metrics_values['UI'][ui]
        
        # 影響度サブスコアの計算
        isc_base = 1 - ((1 - self.metrics_values['C'][c]) *
                       (1 - self.metrics_values['I'][i]) *
                       (1 - self.metrics_values['A'][a]))
        
        if s == 'U':  # スコープ未変更
            impact = 6.42 * isc_base
        else:  # スコープ変更
            impact = 7.52 * (isc_base - 0.029) - 3.25 * pow(isc_base - 0.02, 15)
        
        # 基本スコアの計算
        if impact <= 0:
            return 0
        elif s == 'U':
            return min(10, (impact + exploitability))
        else:
            return min(10, 1.08 * (impact + exploitability))
```

### 応用実装
```python
# 脆弱性管理システムとの統合例
class VulnerabilityManagementSystem:
    def __init__(self):
        self.cvss_calculator = CVSSv3Calculator()
        self.vulnerability_db = []
    
    def add_vulnerability(self, vuln_id, description, cvss_vector):
        """脆弱性情報を追加し、CVSSスコアを自動計算"""
        # CVSSベクトル文字列をパース
        metrics = self.parse_cvss_vector(cvss_vector)
        
        # スコア計算
        base_score = self.cvss_calculator.calculate_base_score(**metrics)
        
        # 深刻度の判定
        severity = self.get_severity_rating(base_score)
        
        # データベースに保存
        vuln_entry = {
            'id': vuln_id,
            'description': description,
            'cvss_vector': cvss_vector,
            'base_score': round(base_score, 1),
            'severity': severity,
            'created_at': datetime.now()
        }
        
        self.vulnerability_db.append(vuln_entry)
        return vuln_entry
    
    def get_severity_rating(self, score):
        """スコアから深刻度を判定"""
        if score == 0:
            return 'None'
        elif score < 4.0:
            return 'Low'
        elif score < 7.0:
            return 'Medium'
        elif score < 9.0:
            return 'High'
        else:
            return 'Critical'
    
    def prioritize_patches(self):
        """パッチ適用の優先順位を決定"""
        return sorted(self.vulnerability_db, 
                     key=lambda x: x['base_score'], 
                     reverse=True)
```

## 5. メリット・デメリット

### メリット
**1. 標準化された評価基準**
- **理由**: 業界標準として確立されており、共通言語として機能
- **効果**: 
  - 異なる組織間でも同じ基準で脆弱性を評価可能
  - セキュリティベンダー間の情報共有が円滑化
- **具体例**: NVD（National Vulnerability Database）では全ての脆弱性にCVSSスコアを付与

**2. 定量的なリスク評価**
- **理由**: 0.0〜10.0の数値スコアによる客観的評価
- **効果**: 
  - 優先順位付けの自動化が可能
  - KPIとしての活用が容易
- **具体例**: 「CVSS 9.0以上は24時間以内に対応」といったSLA設定

**3. 多面的な評価**
- **理由**: 基本・現状・環境の3つの観点から評価
- **効果**: 
  - 組織固有の状況を反映した評価が可能
  - 時間経過による変化を追跡可能
- **具体例**: パッチ提供後は現状評価基準でスコアを調整

### デメリット
**1. ビジネスインパクトの未考慮**
- **理由**: 技術的な脆弱性のみを評価対象とする
- **影響**: 
  - 事業継続性への影響は別途評価が必要
  - 資産価値による重み付けができない
- **対策**: リスクアセスメントツールとの併用

**2. 複合的な攻撃の評価困難**
- **理由**: 単一の脆弱性のみを評価対象とする設計
- **影響**: 
  - 攻撃チェーンの評価ができない
  - 複数の低スコア脆弱性の組み合わせリスクを見逃す可能性
- **対策**: 脅威モデリングやペネトレーションテストとの組み合わせ

**3. 評価の専門性要求**
- **理由**: 正確な評価には技術的知識が必要
- **影響**: 
  - 評価者によるばらつきが発生
  - 誤った評価による対応遅延のリスク
- **対策**: 評価ガイドラインの整備と教育の実施

### 問題1
CVSSの正式名称として正しいものはどれか？

- A) Common Vulnerability Security System
- B) Common Vulnerability Scoring System
- C) Computer Vulnerability Scoring System
- D) Critical Vulnerability Scoring System

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。CVSSはCommon Vulnerability Scoring Systemの略称で、「共通脆弱性評価システム」を意味します。<br>
<br>
Aが間違いの理由：SecurityではなくScoringが正しい<br>
Cが間違いの理由：ComputerではなくCommonが正しい<br>
Dが間違いの理由：CriticalではなくCommonが正しい<br>
<br>
【補足】Commonという言葉が使われているのは、様々な組織で共通して使える標準的な評価システムであることを示しています。
</details>

### 問題2
CVSS v3.1で新たに導入された概念はどれか？

- A) 基本評価基準（Base Metrics）
- B) スコープ（Scope）
- C) 環境評価基準（Environmental Metrics）
- D) 時間的評価基準（Temporal Metrics）

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。スコープ（Scope）はCVSS v3.0から導入された新しい概念で、脆弱性の影響が当該コンポーネントを超えて他のコンポーネントに及ぶかどうかを評価します。<br>
<br>
Aが間違いの理由：基本評価基準はv2.0から存在<br>
Cが間違いの理由：環境評価基準はv2.0から存在<br>
Dが間違いの理由：時間的評価基準はv2.0から存在<br>
<br>
【補足】スコープの導入により、仮想化環境やコンテナ環境での脆弱性評価がより正確になりました。
</details>

### 問題7

- A) 脆弱性の技術的な深刻度を評価する
- B) 組織固有の環境や対策状況を反映する
- C) 攻撃コードの成熟度を評価する
- D) 脆弱性の一般的な影響度を測定する

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。環境評価基準は、組織固有のセキュリティ要件や既存の対策を考慮して、基本スコアを調整するために使用されます。<br>
<br>
Aが間違いの理由：技術的深刻度は基本評価基準で評価<br>

Dが間違いの理由：一般的な影響度は基本評価基準で評価<br>

## 9. 専門用語集

このドキュメントで使用された専門用語について、アルファベット順・50音順で解説します。

### アルファベット

**AC (Attack Complexity)**
- **読み方**: アタック・コンプレキシティ
- **意味**: 脆弱性を悪用するために必要な条件の複雑さを表す評価指標。Low（低）またはHigh（高）で評価される
- **関連用語**: Base Metrics, CVSS Score

**AV (Attack Vector)**
- **読み方**: アタック・ベクター
- **意味**: 脆弱性を悪用可能な攻撃経路を示す評価指標。Network、Adjacent、Local、Physicalの4段階で評価
- **関連用語**: Attack Surface, Remote Exploit

**Base Metrics**
- **読み方**: ベース・メトリクス
- **意味**: CVSS評価の基本となる評価基準群。脆弱性の本質的な特性を評価し、時間や環境に依存しない
- **関連用語**: Temporal Metrics, Environmental Metrics

**CIA Triad**
- **読み方**: シーアイエー・トライアド
- **意味**: 情報セキュリティの3要素（機密性・完全性・可用性）を指す概念
- **関連用語**: Confidentiality, Integrity, Availability

**CVSS (Common Vulnerability Scoring System)**
- **読み方**: シーブイエスエス
- **意味**: 脆弱性の深刻度を0.0から10.0のスコアで評価する業界標準のフレームワーク
- **関連用語**: NVD, CVE, Risk Assessment

**Environmental Metrics**
- **読み方**: エンバイロメンタル・メトリクス
- **意味**: 組織固有の環境や要件を反映するための評価基準群
- **関連用語**: Modified Base Metrics, Security Requirements

**FIRST (Forum of Incident Response and Security Teams)**
- **読み方**: ファースト
- **意味**: CVSSを管理・開発している国際的なセキュリティ組織
- **関連用語**: CVSS SIG, Incident Response

**NVD (National Vulnerability Database)**
- **読み方**: エヌブイディー
- **意味**: 米国NISTが管理する脆弱性データベース。全ての脆弱性にCVSSスコアを付与
- **関連用語**: CVE, NIST, Vulnerability Database

**PR (Privileges Required)**
- **読み方**: プリビレッジズ・リクワイアード
- **意味**: 脆弱性を悪用するために必要な権限レベルを示す評価指標
- **関連用語**: Authentication, Authorization, Access Control

**Scope**
- **読み方**: スコープ
- **意味**: 脆弱性の影響が元のセキュリティ境界を越えるかどうかを示す指標
- **関連用語**: Security Boundary, Impact Propagation

**Temporal Metrics**
- **読み方**: テンポラル・メトリクス
- **意味**: 時間の経過とともに変化する要因を評価する基準群
- **関連用語**: Exploit Code Maturity, Remediation Level

**UI (User Interaction)**
- **読み方**: ユーザー・インタラクション
- **意味**: 脆弱性の悪用にユーザーの操作が必要かどうかを示す評価指標
- **関連用語**: Social Engineering, Phishing

**Vector String**
- **読み方**: ベクター・ストリング
- **意味**: CVSS評価値を文字列形式で表現したもの。例：CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H
- **関連用語**: CVSS Calculator, Score Representation

### あ行

**悪用可能性（Exploitability）**
- **読み方**: あくようかのうせい
- **意味**: 脆弱性がどの程度容易に悪用できるかを示す指標。攻撃元区分、攻撃条件の複雑さ、必要な権限、ユーザ操作の要否から算出される
- **関連用語**: 攻撃容易性、エクスプロイト

### か行

**環境スコア（Environmental Score）**
- **読み方**: かんきょうすこあ
- **意味**: 組織固有の環境や対策状況を反映した最終的なCVSSスコア
- **関連用語**: 基本スコア、現状スコア

**基本スコア（Base Score）**
- **読み方**: きほんすこあ
- **意味**: 脆弱性の本質的な特性のみを評価した、時間や環境に依存しないスコア
- **関連用語**: 基本評価基準、脆弱性評価

**攻撃元区分（Attack Vector）**
- **読み方**: こうげきもとくぶん
- **意味**: 脆弱性を悪用するための攻撃者の位置を示す指標
- **関連用語**: リモート攻撃、ローカル攻撃

**攻撃条件の複雑さ（Attack Complexity）**
- **読み方**: こうげきじょうけんのふくざつさ
- **意味**: 脆弱性を悪用するために必要な条件の複雑度を表す指標
- **関連用語**: 悪用の難易度、攻撃成功率

### さ行

**深刻度（Severity）**
- **読み方**: しんこくど
- **意味**: CVSSスコアに基づく脆弱性の危険度レベル。None、Low、Medium、High、Criticalの5段階
- **関連用語**: リスクレベル、優先度

**スコープ（Scope）**
- **読み方**: すこーぷ
- **意味**: 脆弱性の影響が当該コンポーネントを超えて他に及ぶかを示す指標
- **関連用語**: 影響範囲、セキュリティ境界

**脆弱性（Vulnerability）**
- **読み方**: ぜいじゃくせい
- **意味**: システムやソフトウェアに存在する、セキュリティ上の弱点や欠陥
- **関連用語**: セキュリティホール、バグ

### た行

**対策レベル（Remediation Level）**
- **読み方**: たいさくれべる
- **意味**: 脆弱性に対する修正プログラムや回避策の利用可能性を示す現状評価基準の指標
- **関連用語**: パッチ、ワークアラウンド

### は行

**評価基準（Metrics）**
- **読み方**: ひょうかきじゅん
- **意味**: CVSSスコアを算出するための個別の評価項目
- **関連用語**: メトリクス、評価指標

### ま行

**メトリクス（Metrics）**
- **読み方**: めとりくす
- **意味**: CVSSにおける個別の評価項目や測定基準
- **関連用語**: 評価基準、測定指標

### や行

**ユーザ操作（User Interaction）**
- **読み方**: ゆーざそうさ
- **意味**: 脆弱性の悪用に被害者の何らかの操作が必要かどうかを示す指標
- **関連用語**: ソーシャルエンジニアリング、フィッシング

### ら行

**リスク評価（Risk Assessment）**
- **読み方**: りすくひょうか
- **意味**: 脆弱性がもたらす潜在的な損害や影響を分析・評価すること
- **関連用語**: リスク分析、脅威評価
