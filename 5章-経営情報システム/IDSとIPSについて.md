# IDSとIPSについて

## 概要
IDS（Intrusion Detection System：侵入検知システム）とIPS（Intrusion Prevention System：侵入防止システム）は、ネットワークセキュリティにおける重要な防御技術です。サイバー攻撃の高度化・多様化に伴い、ファイアウォールだけでは防ぎきれない脅威に対処するための必須技術として、企業や組織のセキュリティインフラストラクチャの中核を担っています。

これらのシステムは、ネットワークトラフィックやシステムの動作を監視し、不正アクセスや異常な振る舞いを検出・防止することで、組織の情報資産を保護します。特に、ゼロデイ攻撃や内部脅威など、従来のセキュリティ対策では対応困難な脅威に対する防御手段として重要性が増しています。

## 1. 基本概念・仕組み

### IDSの基本概念
- **定義**: ネットワークやホスト上の活動を監視し、セキュリティポリシーに違反する行為や不正な活動を検出するシステム
- **動作原理**: リアルタイムでネットワークトラフィックやシステムログを分析し、異常を検出した場合にアラートを発生させる
- **特徴**: 検出に特化し、通信を妨げることなくパッシブに監視を行う

### IPSの基本概念
- **定義**: IDSの機能に加え、検出した脅威に対して自動的に防御アクションを実行するシステム
- **動作原理**: ネットワーク経路上にインラインで配置され、悪意のあるトラフィックをリアルタイムでブロックする
- **特徴**: アクティブな防御機能を持ち、脅威を自動的に無効化する

### IDS/IPSの関連技術との関係
- **従来技術との違い**: ファイアウォールがポートやIPアドレスベースでの制御に対し、IDS/IPSはパケットの内容まで詳細に分析
- **改善点**: より高度な脅威検出能力、アプリケーション層での防御、未知の攻撃への対応
- **限界**: 暗号化通信の検査困難性、誤検知（False Positive）の発生、処理性能への影響

## 2. 種類・分類

### 配置場所による分類
IDS/IPSは配置場所により、大きく2つに分類されます。

### ネットワーク型（NIDS/NIPS）
**特徴:**
- ネットワーク上の特定ポイントに配置
- ネットワーク全体のトラフィックを監視
- 複数のホストを同時に保護可能

**検出方法:**
```
1. ネットワークインターフェースをプロミスキャスモードに設定
2. 通過する全パケットをキャプチャ
3. パケットヘッダとペイロードを分析
4. シグネチャまたは異常検知アルゴリズムで判定
```

**📊 具体的な配置例**
**例: 企業ネットワークでのNIDS配置**
- DMZセグメント: Webサーバー群の前段に配置
- 内部ネットワーク境界: ファイアウォールの内側に配置

**ステップ1: トラフィック監視設定**
```
監視対象トラフィック: 80/tcp, 443/tcp, 3306/tcp
監視ルール数: 約15,000ルール
処理能力: 10Gbps
```

**ステップ2: アラート設定**
```
重要度レベル:
- Critical: 即時対応（5分以内）
- High: 30分以内対応
- Medium: 24時間以内対応
- Low: 週次レビューで確認
```

**結果: 月間平均で重要インシデント15件を検出**

💡 **実際の現場では**: 大量のアラートから真の脅威を見極めるため、SOC（Security Operation Center）との連携が必須となります。

### ホスト型（HIDS/HIPS）
**特徴:**
- 個別のサーバーやエンドポイントに直接インストール
- システムコール、ファイルアクセス、レジストリ変更を監視
- より詳細な動作監視が可能

**監視項目:**
```
- ファイルの完全性チェック（FIM）
- プロセスの起動・終了
- ユーザーのログイン・ログアウト
- 権限昇格の試み
- システム設定の変更
```

## 3. 検出手法の詳細

### シグネチャベース検出
#### 仕組みの詳細
- **意味**: 既知の攻撃パターン（シグネチャ）と照合して脅威を検出
- **設定範囲**: 数千から数万のシグネチャルールを保持
- **影響**: 高い検出精度だが、未知の攻撃には無力
- **推奨値**: 毎日のシグネチャ更新、週次でのルール見直し

#### シグネチャ例
```
alert tcp $EXTERNAL_NET any -> $HOME_NET 3389 
(msg:"RDP Brute Force Attack"; 
flow:to_server,established; 
content:"|03 00 00|"; offset:0; depth:3; 
threshold:type limit, track by_src, count 5, seconds 60; 
classtype:attempted-admin; sid:1000001; rev:1;)
```

### アノマリベース検出
#### 仕組みの詳細
- **意味**: 正常な動作パターンを学習し、逸脱を異常として検出
- **設定範囲**: 学習期間は通常2-4週間
- **影響**: 未知の攻撃も検出可能だが、誤検知率が高い
- **推奨値**: 閾値は環境により調整、定期的な再学習が必要

## 4. 実装例・適用事例

### 基本実装（Snort使用例）
```bash
# Snortの基本設定
# /etc/snort/snort.conf

# ネットワーク変数の定義
ipvar HOME_NET 192.168.1.0/24
ipvar EXTERNAL_NET !$HOME_NET
ipvar DNS_SERVERS 192.168.1.10
ipvar SMTP_SERVERS 192.168.1.20
ipvar HTTP_SERVERS 192.168.1.30

# ポート変数の定義
portvar HTTP_PORTS [80,8080,443]
portvar SHELLCODE_PORTS !80
portvar ORACLE_PORTS 1521

# プリプロセッサの設定
preprocessor stream5_global: track_tcp yes, track_udp yes
preprocessor http_inspect: global iis_unicode_map unicode.map 1252
```


### 実際の適用事例
#### 事例1: 大手金融機関でのハイブリッド構成
- **課題**: 年間数億件のトランザクションを処理しながら、リアルタイムで不正を検出
- **適用方法**: 
  - 外部境界にNIPS（10Gbps×2台、冗長構成）
  - 重要サーバー50台にHIPSを導入
  - SIEMとの連携で相関分析
- **結果**: 検出時間を平均15分から30秒に短縮
- **効果**: 年間推定被害額を3億円から2000万円に削減

#### 事例2: 製造業でのOTネットワーク保護
- **課題**: レガシーシステムが多く、パッチ適用が困難な環境での防御
- **適用方法**: 
  - 産業用プロトコル対応のNIDSを導入
  - パッシブ監視に特化した構成
  - ホワイトリスト方式の異常検知
- **結果**: ダウンタイムゼロで導入完了
- **効果**: 3件の標的型攻撃を早期発見・対処

## 5. メリット・デメリット

### メリット
**1. リアルタイム脅威検出**
- **理由**: 24時間365日の継続的な監視により、攻撃の初期段階で検出可能
- **効果**: 被害の最小化、インシデント対応時間の短縮
- **具体例**: SQLインジェクション攻撃を実行前に検出し、データ漏洩を防止

**2. 多層防御の実現**
- **理由**: ファイアウォールでは防げない、アプリケーション層の攻撃も検出
- **効果**: セキュリティの防御力が大幅に向上
- **具体例**: HTTPSトラフィック内のマルウェア通信を検出

**3. コンプライアンス対応**
- **理由**: PCI DSS、ISMS等の要求事項に対応
- **効果**: 監査対応の効率化、規制要件の充足
- **具体例**: ログの長期保存により、フォレンジック調査が可能

### デメリット
**1. 誤検知による業務影響**
- **理由**: 正常な通信を攻撃と誤認識することがある
- **影響**: 業務システムの停止、生産性の低下
- **対策**: 
  - チューニング期間を十分に確保（最低1ヶ月）
  - ホワイトリストの適切な管理
  - 段階的な防御モードへの移行

**2. 運用負荷の増大**
- **理由**: 大量のアラート処理、継続的なルール更新が必要
- **影響**: 専門人材の確保、運用コストの増加
- **対策**: 
  - SOCへのアウトソーシング検討
  - 自動化ツールの活用
  - AIを活用したアラート優先順位付け

**3. 暗号化通信への対応困難**
- **理由**: SSL/TLS通信の内容を検査できない
- **影響**: 暗号化された攻撃を見逃す可能性
- **対策**: 
  - SSL/TLSインスペクション機能の導入
  - エンドポイントでの検査強化
  - 証明書管理の適切な実施

## 6. 選択・導入の指針

### IDS/IPS選択の基準
| 観点 | IDS | IPS | ハイブリッド |
|------|-----|-----|-------------|
| 検出精度 | ◎ | ○ | ◎ |
| 誤検知時の影響 | ○ | × | △ |
| 導入コスト | ○ | △ | × |
| 運用難易度 | △ | × | × |
| リアルタイム防御 | × | ◎ | ◎ |

### 適用判断フローチャート
1. **可用性要求は極めて高いか？** 
   - Yes → IDSから開始し、段階的にIPSへ移行
   - No → 次の判断へ

2. **専門的な運用体制があるか？**
   - Yes → IPSを積極的に導入
   - No → マネージドサービスの利用、またはIDSから開始

3. **予算規模は十分か？**
   - Yes → ハイブリッド構成で最適な防御
   - No → 重要システムに限定してIDS導入

## 7. 最新動向・今後の展望
- **現在の課題**: 
  - IoT/OTデバイスの増加による監視対象の爆発的増加
  - 5G導入による通信量増大への対応
  - クラウド環境での実装の複雑化
- **研究動向**: 
  - AI/機械学習を活用した高度な異常検知
  - XDR（Extended Detection and Response）への統合
  - SOAR（Security Orchestration, Automation and Response）との連携
- **将来予測**: 
  - 2025年までに、企業の80%がAI搭載IPS/IDSを導入
  - ゼロトラストアーキテクチャとの統合が標準化
- **関連技術**: 
  - EDR（Endpoint Detection and Response）
  - NDR（Network Detection and Response）
  - SIEM（Security Information and Event Management）

## 8. 理解度確認クイズ（4択問題20問）

### 問題1
IDSの基本的な機能として最も適切なものは次のうちどれか？

- A) ネットワークトラフィックを監視し、異常を検出してアラートを発生させる
- B) 検出した攻撃を自動的にブロックする
- C) ファイアウォールの代替として動作する
- D) ウイルスを駆除する

<details>
<summary>解答</summary>
<strong>正解: A</strong><br>
正解はAです。IDSは「Intrusion Detection System（侵入検知システム）」の略で、その主要な機能は監視と検出、そしてアラートの発生です。<br>
<br>
Bが間違いの理由：攻撃を自動的にブロックするのはIPS（侵入防止システム）の機能です<br>
Cが間違いの理由：IDSはファイアウォールと併用されるもので、代替ではありません<br>
Dが間違いの理由：ウイルス駆除はアンチウイルスソフトの機能です<br>
<br>
【補足】実務では、IDSは「検出専門」として、誤検知による業務影響を避けながら脅威を発見する役割を担います。
</details>

### 問題2
NIDSとHIDSの違いについて、正しい説明は次のうちどれか？

- A) NIDSはネットワーク全体を監視し、HIDSは個別のホストを監視する
- B) NIDSは無料で、HIDSは有料である
- C) NIDSは古い技術で、HIDSが新しい技術である
- D) NIDSはWindows専用、HIDSはLinux専用である

<details>
<summary>解答</summary>
<strong>正解: A</strong><br>
正解はAです。NIDS（Network IDS）はネットワーク上の特定ポイントでトラフィックを監視し、HIDS（Host IDS）は個別のサーバーやPCにインストールして監視します。<br>
<br>
Bが間違いの理由：両方とも商用製品とオープンソース製品が存在します<br>
Cが間違いの理由：両方とも現在も使用される技術で、用途により使い分けます<br>
Dが間違いの理由：両方ともOS非依存で、様々なプラットフォームで動作します<br>
<br>
【補足】実務では、重要なシステムにはNIDSとHIDSを併用し、多層防御を実現することが一般的です。
</details>

### 問題3
ある企業で、Webサーバーへの1分間に100回のログイン試行を検出した。この攻撃を検出するのに最も適したIDS/IPSの検出手法は？

- A) シグネチャベース検出
- B) アノマリベース検出
- C) ヒューリスティック検出
- D) ファイルハッシュ検出

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。短時間での大量ログイン試行は、通常の動作パターンから逸脱した「異常な振る舞い」であり、アノマリベース検出が最適です。<br>
<br>
Aが間違いの理由：シグネチャベースは既知の攻撃パターンとの照合であり、量的な異常検知には不向きです<br>
Cが間違いの理由：ヒューリスティック検出は主にマルウェア検出で使用される手法です<br>
Dが間違いの理由：ファイルハッシュ検出はファイルの改ざん検知に使用され、ログイン試行とは無関係です<br>
<br>
【補足】実際の設定では、「1分間に5回以上のログイン失敗」などの閾値を設定し、ブルートフォース攻撃を検出します。
</details>

### 問題4
IPSをネットワークに導入する際の配置方法として正しいものは？

- A) ネットワークの外部に並列（パラレル）に配置
- B) ネットワーク経路上に直列（インライン）に配置
- C) 各PCのデスクトップ上に配置
- D) クラウド上にのみ配置

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。IPSは攻撃を自動的にブロックするため、すべてのトラフィックが通過するようにインライン配置する必要があります。<br>
<br>
Aが間違いの理由：パラレル配置では通信をブロックできず、IDSとしての動作になってしまいます<br>
Cが間違いの理由：IPSはネットワーク機器であり、デスクトップ上には配置しません<br>
Dが間違いの理由：オンプレミス環境では物理的な配置が必要です<br>
<br>
【補足】インライン配置は単一障害点となるため、実務では冗長構成（アクティブ-スタンバイ）を取ることが重要です。
</details>

### 問題5
IDS/IPSのシグネチャ更新頻度として、一般的に推奨されるものは？

- A) 年に1回
- B) 月に1回
- C) 毎日
- D) 5年に1回

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
正解はCです。新しい脅威は日々発見されるため、シグネチャは毎日更新することが推奨されます。多くの製品では自動更新機能を提供しています。<br>
<br>
Aが間違いの理由：年1回では新しい脅威に対応できず、セキュリティリスクが高まります<br>
Bが間違いの理由：月1回でも頻度が不十分で、ゼロデイ攻撃などに対応できません<br>
Dが間違いの理由：5年は論外で、ほとんどの攻撃を検出できなくなります<br>
<br>
【補足】重要なシステムでは、緊急度の高い脅威については臨時更新を行うこともあります。
</details>

### 問題6
ホスト型IPS（HIPS）が監視する項目として適切でないものは？

- A) ファイルシステムへのアクセス
- B) レジストリの変更（Windows環境）
- C) 他のネットワークセグメントの通信
- D) プロセスの起動と終了

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
正解はCです。HIPSは個別のホスト上で動作するため、他のネットワークセグメントの通信は監視できません。これはNIPSの役割です。<br>
<br>
Aが正しい理由：ファイルの作成、変更、削除を監視し、不正な改ざんを検出します<br>
Bが正しい理由：Windowsではレジストリの不正な変更を監視します<br>
Dが正しい理由：マルウェアの起動など、不審なプロセスを検出します<br>
<br>
【補足】HIPSは「内部からの脅威」や「エンドポイントでの異常」検出に特に有効です。
</details>

### 問題7
IDS/IPSにおける「False Positive」の説明として正しいものは？

- A) 実際の攻撃を見逃すこと
- B) 正常な通信を攻撃として誤検知すること
- C) システムが停止すること
- D) ログが記録されないこと

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。False Positive（誤検知）は、正常な通信や動作を攻撃として誤って検出することを指します。<br>
<br>
Aが間違いの理由：攻撃を見逃すのはFalse Negative（検知漏れ）です<br>
Cが間違いの理由：システム停止は誤検知の結果として起こりうる影響ですが、定義ではありません<br>
Dが間違いの理由：ログの記録失敗は別の問題で、誤検知とは関係ありません<br>
<br>
【補足】実務では、False Positiveを減らすためのチューニングに多くの時間を費やします。特にIPS環境では業務影響が大きいため重要です。
</details>

### 問題8
企業がIDS導入後、最初の1ヶ月で行うべき作業として最も重要なものは？

- A) すぐに全ての検知ルールを有効化する
- B) ベースラインの確立とチューニング
- C) 他のセキュリティ製品を全て撤去する
- D) アラートを全て無視する

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。導入初期は正常な通信パターンを学習し（ベースライン確立）、誤検知を減らすためのチューニングが最重要です。<br>
<br>
Aが間違いの理由：全ルール有効化は大量の誤検知を生み、運用が破綻します<br>
Cが間違いの理由：IDS/IPSは多層防御の一部であり、他製品との併用が前提です<br>
Dが間違いの理由：アラートの分析は必須で、無視しては導入の意味がありません<br>
<br>
【補足】一般的に、最初の2-4週間は「検知のみモード」で運用し、誤検知を特定してホワイトリスト化していきます。
</details>

### 問題9
次のうち、アノマリベース検出の課題として最も適切なものは？

- A) シグネチャの更新が必要
- B) 既知の攻撃しか検出できない
- C) 正常な動作の定義が困難で誤検知が多い
- D) 導入コストが安すぎる

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
正解はCです。アノマリベース検出は「正常」の定義が環境により異なり、また時間と共に変化するため、適切な閾値設定が困難で誤検知が発生しやすいです。<br>
<br>
Aが間違いの理由：シグネチャ更新はシグネチャベース検出の特徴です<br>
Bが間違いの理由：アノマリベースは未知の攻撃も検出可能なことが利点です<br>
Dが間違いの理由：コストが安いことは課題ではなく、また実際は高度な分析のため高コストになりがちです<br>
<br>
【補足】機械学習の進歩により、アノマリ検出の精度は向上していますが、定期的な再学習は依然として必要です。
</details>

### 問題10

- B) 段階的にIDSモードからIPSモードへ移行する
- C) 冗長構成を取らない
- D) メンテナンス時はIPSを撤去する

<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。まずIDSモード（検知のみ）で誤検知を把握し、チューニング後に段階的にIPSモード（ブロック）へ移行することで、業務影響を最小化できます。<br>
<br>
Aが間違いの理由：誤検知による業務停止のリスクが非常に高くなります<br>
Cが間違いの理由：冗長構成は可用性確保の基本で、単一障害点を避けるために必須です<br>
Dが間違いの理由：メンテナンス時こそバイパス機能や冗長構成で保護を継続すべきです<br>
<br>
【補足】実務では「モニターモード→一部ブロック→全面ブロック」と3段階以上で移行することも多いです。
</details>

## 9. 専門用語集

このスライドで使用された技術用語について、アルファベット順・50音順で解説します。

### アルファベット

**AI (Artificial Intelligence)**
- **読み方**: エーアイ（人工知能）
- **意味**: IDS/IPSにおいて、機械学習を用いて未知の攻撃パターンを検出したり、誤検知を削減したりする技術
- **関連用語**: 機械学習、ディープラーニング、異常検知

**DDoS (Distributed Denial of Service)**
- **読み方**: ディードス
- **意味**: 複数のコンピュータから同時に大量のトラフィックを送信し、サービスを停止させる攻撃
- **関連用語**: DoS攻撃、ボットネット、帯域幅攻撃

**DMZ (DeMilitarized Zone)**
- **読み方**: ディーエムゼット（非武装地帯）
- **意味**: インターネットと内部ネットワークの間に設置される中間的なネットワークセグメント
- **関連用語**: ファイアウォール、ネットワークセグメンテーション

**EDR (Endpoint Detection and Response)**
- **読み方**: イーディーアール
- **意味**: エンドポイント（PC、サーバー等）での脅威を検出し、対応する技術
- **関連用語**: HIDS、エンドポイントセキュリティ

**EVE JSON**
- **読み方**: イブ ジェイソン
- **意味**: Suricataで使用される統一的なJSON形式のログフォーマット
- **関連用語**: Suricata、ログ管理、SIEM連携

**False Negative**
- **読み方**: フォールス ネガティブ
- **意味**: 実際の攻撃を正常と判断して見逃してしまうこと（検知漏れ）
- **関連用語**: False Positive、検知率、誤検知

**False Positive**
- **読み方**: フォールス ポジティブ
- **意味**: 正常な通信や動作を攻撃として誤って検出すること（誤検知）
- **関連用語**: False Negative、チューニング、ホワイトリスト

**FIM (File Integrity Monitoring)**
- **読み方**: エフアイエム
- **意味**: ファイルの完全性を監視し、不正な変更を検出する機能
- **関連用語**: HIDS、改ざん検知、ハッシュ値

**HIDS (Host-based Intrusion Detection System)**
- **読み方**: エイチアイディーエス
- **意味**: 個別のホスト（サーバー、PC）にインストールして動作する侵入検知システム
- **関連用語**: HIPS、NIDS、エンドポイントセキュリティ

**HIPS (Host-based Intrusion Prevention System)**
- **読み方**: ヒップス
- **意味**: 個別のホストで動作し、検出した脅威を自動的にブロックする侵入防止システム
- **関連用語**: HIDS、NIPS、ホストセキュリティ

**HTTP/HTTPS**
- **読み方**: エイチティーティーピー/エイチティーティーピーエス
- **意味**: Web通信プロトコル。HTTPSは暗号化された安全な通信
- **関連用語**: SSL/TLS、Webアプリケーション、暗号化通信

**IDS (Intrusion Detection System)**
- **読み方**: アイディーエス
- **意味**: ネットワークやシステムへの侵入を検知し、管理者に通知するシステム
- **関連用語**: IPS、NIDS、HIDS

**IoT (Internet of Things)**
- **読み方**: アイオーティー
- **意味**: インターネットに接続された様々な機器。セキュリティ管理が課題
- **関連用語**: OT、エッジコンピューティング、IoTセキュリティ

**IPS (Intrusion Prevention System)**
- **読み方**: アイピーエス
- **意味**: 侵入を検知し、自動的に防御アクションを実行するシステム
- **関連用語**: IDS、NIPS、HIPS

**NDR (Network Detection and Response)**
- **読み方**: エヌディーアール
- **意味**: ネットワークトラフィックを分析し、脅威を検出・対応する技術
- **関連用語**: NIDS、ネットワークフォレンジック

**NGIPS (Next Generation IPS)**
- **読み方**: エヌジーアイピーエス
- **意味**: アプリケーション識別、ユーザー認識、高度なマルウェア対策を統合した次世代IPS
- **関連用語**: IPS、アプリケーション制御、統合脅威管理

**NIDS (Network-based Intrusion Detection System)**
- **読み方**: エヌアイディーエス
- **意味**: ネットワーク上で動作する侵入検知システム
- **関連用語**: NIPS、ネットワークセキュリティ、パケット分析

**NIPS (Network-based Intrusion Prevention System)**
- **読み方**: ニップス
- **意味**: ネットワーク上で動作し、脅威を自動的にブロックする侵入防止システム
- **関連用語**: NIDS、インライン配置、ネットワークセキュリティ

**OT (Operational Technology)**
- **読み方**: オーティー
- **意味**: 工場や重要インフラで使用される制御システム技術
- **関連用語**: SCADA、産業用制御システム、IoT

**PCI DSS**
- **読み方**: ピーシーアイ ディーエスエス
- **意味**: クレジットカード業界のセキュリティ基準。IDS/IPS導入を要求
- **関連用語**: コンプライアンス、規制要件、監査

**ROI (Return on Investment)**
- **読み方**: アールオーアイ
- **意味**: 投資対効果。セキュリティ投資の効果測定指標
- **関連用語**: コスト効果分析、ビジネスケース

**SCADA (Supervisory Control and Data Acquisition)**
- **読み方**: スカーダ
- **意味**: 産業用制御システムの監視制御とデータ収集システム
- **関連用語**: OT、重要インフラ、産業用セキュリティ

**SIEM (Security Information and Event Management)**
- **読み方**: シーム
- **意味**: 複数のセキュリティ機器からログを収集し、相関分析を行うシステム
- **関連用語**: ログ管理、相関分析、SOC

**Snort**
- **読み方**: スノート
- **意味**: オープンソースのネットワーク型IDS/IPS。広く使用されている
- **関連用語**: Suricata、オープンソースIDS、シグネチャ

**SOAR (Security Orchestration, Automation and Response)**
- **読み方**: ソアー
- **意味**: セキュリティ運用の自動化・オーケストレーションツール
- **関連用語**: 自動化、インシデント対応、運用効率化

**SOC (Security Operation Center)**
- **読み方**: ソック
- **意味**: セキュリティ監視・分析・対応を行う専門組織
- **関連用語**: SIEM、インシデント対応、24時間監視

**SQL Injection**
- **読み方**: エスキューエル インジェクション
- **意味**: Webアプリケーションの脆弱性を悪用し、不正なSQL文を実行させる攻撃
- **関連用語**: Webアプリケーション攻撃、入力検証、WAF

**SSL/TLS**
- **読み方**: エスエスエル/ティーエルエス
- **意味**: インターネット上での暗号化通信プロトコル
- **関連用語**: HTTPS、暗号化、証明書

**Suricata**
- **読み方**: スリカタ
- **意味**: 高性能なオープンソースIDS/IPS/NSMエンジン
- **関連用語**: Snort、EVE JSON、マルチスレッド

**XDR (Extended Detection and Response)**
- **読み方**: エックスディーアール
- **意味**: エンドポイント、ネットワーク、クラウドなど複数の層で脅威を検出・対応
- **関連用語**: EDR、NDR、統合セキュリティ

### か行

- **読み方**: かそうぱっち
