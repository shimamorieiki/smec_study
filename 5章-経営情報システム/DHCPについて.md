# DHCPについて

## 概要
DHCP（Dynamic Host Configuration Protocol）は、ネットワーク上のデバイスに対して自動的にIPアドレスやその他のネットワーク設定情報を割り当てるプロトコルです。手動でのIPアドレス設定が不要となり、大規模なネットワーク管理を効率化する重要な技術です。

## 1. 基本概念・仕組み

### DHCPの核となる概念
- **定義**: ネットワーク上のホストに対して、IPアドレスをはじめとするネットワーク設定情報を動的に割り当てるプロトコル
- **動作原理**: クライアント・サーバモデルに基づき、4段階のメッセージ交換（DORA）により設定情報を配布
- **特徴**: 
  - IPアドレスの自動割り当て
  - 一元管理によるネットワーク設定の簡素化
  - IPアドレスの再利用による効率的なアドレス管理

### 従来の静的IP設定との関係
- **従来技術との違い**: 
  - 静的設定：管理者が各デバイスに手動でIPアドレスを設定
  - DHCP：サーバが自動的にIPアドレスを割り当て
- **改善点**: 
  - 設定ミスの削減
  - 管理工数の大幅削減
  - IPアドレスの効率的な利用
- **限界**: 
  - サーバ障害時のリスク
  - セキュリティ上の脆弱性の可能性
  - ブロードキャストドメインに限定

## 2. DHCPの動作プロセス（DORA）

### DHCPメッセージ交換の流れ
DHCPは4つの基本メッセージで構成される「DORA」プロセスで動作します。

### 1. DHCP Discover（発見）
**特徴:**
- クライアントがDHCPサーバを探すブロードキャストメッセージ
- 送信元：0.0.0.0、宛先：255.255.255.255
- UDPポート68（クライアント）からポート67（サーバ）へ送信

**メッセージ内容:**
```
Message Type: DHCPDISCOVER
Client MAC Address: xx:xx:xx:xx:xx:xx
Transaction ID: 0x12345678
Requested IP Address: (optional)
Parameter Request List: Subnet Mask, Router, DNS, etc.
```

### 2. DHCP Offer（提供）
**特徴:**
- DHCPサーバがクライアントに利用可能なIPアドレスを提示
- 通常はブロードキャストで返信（クライアントがまだIPアドレスを持たないため）
- 複数のDHCPサーバから複数のOfferを受信する可能性あり

**📊 具体的な設定例**
**例: 企業ネットワークでのDHCP Offer**
- 提供IPアドレス: 192.168.1.100
- サブネットマスク: 255.255.255.0
- デフォルトゲートウェイ: 192.168.1.1
- DNSサーバ: 192.168.1.10, 192.168.1.11
- リース期間: 86400秒（24時間）

💡 **実際の現場では**: 複数のDHCPサーバがある環境では、クライアントは最初に受信したOfferを選択することが多い

### 3. DHCP Request（要求）
**特徴:**
- クライアントが特定のDHCPサーバのOfferを受け入れる意思表示
- ブロードキャストで送信（他のDHCPサーバに選択を通知）
- 選択したサーバのIDを含む

### 4. DHCP Acknowledge（確認）
**特徴:**
- DHCPサーバがIPアドレスの割り当てを最終確認
- リース期間と全ての設定情報を含む
- この後、クライアントは割り当てられたIPアドレスを使用開始

## 3. DHCPの種類・分類

### アドレス割り当て方式による分類

### 動的割り当て（Dynamic Allocation）
**特徴:**
- アドレスプールから自動的にIPアドレスを割り当て
- リース期間終了後、アドレスはプールに返却
- 最も一般的な割り当て方式

**算出方法:**
```
利用可能アドレス数 = (終了IPアドレス - 開始IPアドレス + 1) - 除外アドレス数
```

**📊 具体的な計算例**
**例: 小規模オフィスのアドレスプール設計**
- ネットワーク: 192.168.1.0/24
- DHCPプール範囲: 192.168.1.100 - 192.168.1.200
- 除外アドレス: なし

**ステップ1: 利用可能アドレス数の計算**
```
利用可能アドレス数 = (200 - 100 + 1) = 101個
```

**ステップ2: 同時接続デバイス数の見積もり**
```
PC: 30台
スマートフォン: 50台
プリンタ・その他: 10台
合計: 90台（利用率: 89%）
```

**結果: 適切なプール設計（10%の余裕を確保）**

### 自動割り当て（Automatic Allocation）
**特徴:**
- 一度割り当てたIPアドレスを恒久的に保持
- リース期間が無期限
- デバイスの入れ替えが少ない環境に適している

### 手動割り当て（Manual Allocation / DHCP Reservation）
**特徴:**
- MACアドレスとIPアドレスを事前に紐付け
- 特定のデバイスに常に同じIPアドレスを割り当て
- サーバやプリンタなど固定IPが必要な機器に使用

**設定例:**
```
host printer01 {
    hardware ethernet 00:11:22:33:44:55;
    fixed-address 192.168.1.20;
}
```

## 4. 詳細仕様・パラメータ

### 重要なDHCPオプション

#### オプション1: サブネットマスク（Option 1）
- **意味**: ネットワーク部とホスト部を識別するためのマスク
- **設定範囲**: 32ビットのマスク値
- **影響**: 通信可能な範囲を決定
- **推奨値**: ネットワーク設計に応じて適切に設定

#### オプション3: デフォルトゲートウェイ（Option 3）
- **意味**: 外部ネットワークへの出口となるルータのIPアドレス
- **設定範囲**: 1つ以上のIPアドレス（優先順位付き）
- **影響**: インターネット接続の可否を決定
- **推奨値**: 冗長性を考慮し複数設定することも可能

#### オプション6: DNSサーバ（Option 6）
- **意味**: 名前解決を行うDNSサーバのIPアドレス
- **設定範囲**: 1つ以上のIPアドレス（優先順位付き）
- **影響**: ドメイン名でのアクセス可否を決定
- **推奨値**: プライマリとセカンダリの2つ以上を設定

#### オプション51: IPアドレスリース期間（Option 51）
- **意味**: IPアドレスの有効期間（秒単位）
- **設定範囲**: 0〜4294967295秒
- **影響**: アドレスの再利用頻度とネットワークトラフィック
- **推奨値**: 
  - オフィス環境: 24時間（86400秒）
  - 公共Wi-Fi: 1〜2時間（3600〜7200秒）

## 5. 実装例・設定例

### 基本的なDHCPサーバ設定（ISC DHCP Server）
```bash
# /etc/dhcp/dhcpd.conf

# グローバル設定
default-lease-time 86400;    # デフォルトリース期間: 24時間
max-lease-time 172800;       # 最大リース期間: 48時間
authoritative;               # 権威サーバとして動作

# サブネット定義
subnet 192.168.1.0 netmask 255.255.255.0 {
    # アドレスプール
    range 192.168.1.100 192.168.1.200;
    
    # ネットワーク設定
    option routers 192.168.1.1;
    option domain-name-servers 192.168.1.10, 8.8.8.8;
    option domain-name "example.local";
    
    # 固定割り当て
    host fileserver {
        hardware ethernet 00:11:22:33:44:55;
        fixed-address 192.168.1.20;
    }
}
```

### Windows Server DHCPの設定例
```powershell
# PowerShellでのDHCPスコープ作成
Add-DhcpServerv4Scope -Name "Office Network" `
    -StartRange 192.168.1.100 `
    -EndRange 192.168.1.200 `
    -SubnetMask 255.255.255.0 `
    -State Active

# オプションの設定
Set-DhcpServerv4OptionValue -ScopeId 192.168.1.0 `
    -Router 192.168.1.1 `
    -DnsServer 192.168.1.10, 192.168.1.11 `
    -DnsDomain "example.local"

# 予約の作成
Add-DhcpServerv4Reservation -ScopeId 192.168.1.0 `
    -IPAddress 192.168.1.20 `
    -ClientId "00-11-22-33-44-55" `
    -Description "File Server"
```

## 6. メリット・デメリット

### メリット

**1. 管理の効率化**
- **理由**: 手動設定が不要になり、一元管理が可能
- **効果**: 管理者の作業時間を80%以上削減
- **具体例**: 100台のPCへの設定が数時間から数分に短縮

**2. IPアドレスの効率的利用**
- **理由**: 使用していないアドレスを自動的に回収・再利用
- **効果**: 必要なIPアドレス数を30-50%削減可能
- **具体例**: 200個のアドレスで300台のデバイスを運用

**3. 設定ミスの削減**
- **理由**: 自動設定により人的ミスを排除
- **効果**: ネットワークトラブルの70%以上を削減
- **具体例**: IPアドレス重複やサブネットマスクの設定ミスを防止

### デメリット

**1. 単一障害点（SPOF）のリスク**
- **理由**: DHCPサーバ障害時に新規接続ができない
- **影響**: ネットワーク全体のサービス停止の可能性
- **対策**: DHCPサーバの冗長化（フェイルオーバー構成）

**2. セキュリティリスク**
- **理由**: 不正なDHCPサーバによる中間者攻撃の可能性
- **影響**: 通信の盗聴や改ざんのリスク
- **対策**: DHCP Snooping、802.1X認証の導入

**3. ブロードキャストトラフィック**
- **理由**: DHCP Discoverがブロードキャストで送信される
- **影響**: 大規模ネットワークでの帯域圧迫
- **対策**: DHCPリレーエージェントの活用、VLANの適切な設計

## 7. 選択・導入の指針

### DHCP導入判断フローチャート

1. **デバイス数は10台以上か？** 
   - Yes → DHCPの導入を推奨
   - No → 次の判断へ

2. **デバイスの入れ替えが頻繁か？**
   - Yes → DHCPの導入を強く推奨
   - No → 静的IPアドレスも選択肢

3. **ゲストアクセスを提供するか？**
   - Yes → DHCP必須（ゲスト用VLAN併用推奨）
   - No → 運用方針に応じて判断

### 設計時の考慮事項

| 観点 | 小規模（〜50台） | 中規模（50〜500台） | 大規模（500台〜） |
|------|-----------------|-------------------|------------------|
| サーバ構成 | シングル構成 | Active-Standby | Active-Active |
| リース期間 | 24〜48時間 | 8〜24時間 | 2〜8時間 |
| アドレスプール | 20%余裕 | 30%余裕 | 40%余裕 |
| 監視レベル | 基本監視 | 詳細監視 | リアルタイム監視 |

## 9. 理解度確認クイズ（4択問題20問）

### 問題1
DHCPの正式名称として正しいものはどれか？

- A) Dynamic Host Configuration Protocol
- B) Domain Host Configuration Protocol
- C) Dynamic Hardware Configuration Protocol
- D) Domain Hardware Configuration Protocol

<details>
<summary>解答</summary>
<strong>正解: A</strong><br>
DHCPは「Dynamic Host Configuration Protocol」の略です。動的にホストの設定情報を配布するプロトコルという意味を持ちます。<br>
<br>
Bが間違いの理由：Domainではなく、Dynamic（動的）が正しい<br>
Cが間違いの理由：Hardwareではなく、Host（ホスト）が正しい<br>
Dが間違いの理由：DomainとHardwareの両方が間違い<br>
<br>
【補足】Dynamicは「動的」を意味し、IPアドレスを自動的に割り当てる機能を表しています。
</details>

### 問題2
DHCPのメッセージ交換プロセス「DORA」の正しい順序はどれか？

- A) Discover → Offer → Request → Acknowledge
- B) Discover → Request → Offer → Acknowledge
- C) Offer → Discover → Request → Acknowledge
- D) Request → Discover → Offer → Acknowledge

<details>
<summary>解答</summary>
<strong>正解: A</strong><br>
DHCPの基本的なメッセージ交換は「DORA」と呼ばれ、以下の順序で行われます：<br>
1. Discover（発見）：クライアントがDHCPサーバを探す<br>
2. Offer（提供）：サーバがIPアドレスを提示<br>
3. Request（要求）：クライアントが特定のOfferを選択<br>
4. Acknowledge（確認）：サーバが割り当てを確定<br>
<br>
B、C、Dが間違いの理由：メッセージの順序が論理的に成立しない（例：サーバを発見する前にOfferを受けることはできない）<br>
<br>
【補足】この順序は必ず守られ、各段階でエラーが発生した場合は最初からやり直しになります。
</details>

### 問題3
DHCPサーバが使用するUDPポート番号はどれか？

- A) 53
- B) 67
- C) 68
- D) 80

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
DHCPサーバはUDPポート67を使用します。<br>
<br>
Aが間違いの理由：ポート53はDNSサーバが使用<br>
Cが間違いの理由：ポート68はDHCPクライアントが使用<br>
Dが間違いの理由：ポート80はHTTP（Webサーバ）が使用<br>
<br>
【補足】DHCPはサーバが67番、クライアントが68番と、異なるポートを使用する珍しいプロトコルです。
</details>

### 問題4
192.168.1.0/24のネットワークで、DHCPプールを192.168.1.100〜192.168.1.150に設定した場合、割り当て可能なIPアドレス数はいくつか？

- A) 50個
- B) 51個
- C) 52個
- D) 49個

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
計算式：終了アドレス - 開始アドレス + 1 = 150 - 100 + 1 = 51個<br>
<br>
開始アドレス（192.168.1.100）と終了アドレス（192.168.1.150）の両方を含むため、+1する必要があります。<br>
<br>
Aが間違いの理由：終了アドレスを含めていない計算（150-100=50）<br>
Cが間違いの理由：計算ミス<br>
Dが間違いの理由：計算ミス<br>
<br>
【補足】実務では、この中から故障対応用に数個を予約しておくことが一般的です。
</details>

### 問題5
DHCPのリース期間として、一般的なオフィス環境で推奨される時間はどれか？

- A) 1時間
- B) 24時間
- C) 1週間
- D) 無期限

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
一般的なオフィス環境では24時間（86400秒）のリース期間が推奨されます。<br>
<br>
Aが間違いの理由：1時間は短すぎてDHCPトラフィックが増加<br>
Cが間違いの理由：1週間は長すぎてIPアドレスの効率的な利用ができない<br>
Dが間違いの理由：無期限はIPアドレスの枯渇リスクがある<br>
<br>
【補足】公共Wi-Fiでは1〜2時間、固定的な環境では48時間〜1週間など、用途に応じて調整します。
</details>

### 問題6
DHCPの割り当て方式のうち、MACアドレスとIPアドレスを事前に紐付ける方式はどれか？

- A) 動的割り当て（Dynamic Allocation）
- B) 自動割り当て（Automatic Allocation）
- C) 手動割り当て（Manual Allocation）
- D) 静的割り当て（Static Allocation）

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
手動割り当て（Manual Allocation）またはDHCP予約と呼ばれ、特定のMACアドレスに対して常に同じIPアドレスを割り当てます。<br>
<br>
Aが間違いの理由：動的割り当ては、プールから空いているアドレスを自動選択<br>
Bが間違いの理由：自動割り当ては、一度割り当てたアドレスを恒久的に保持するが、事前の紐付けはしない<br>
Dが間違いの理由：静的割り当てという用語はDHCPの正式な分類には存在しない<br>
<br>
【補足】サーバやプリンタなど、IPアドレスが変わると困る機器に使用されます。
</details>

### 問題9
大規模ネットワークでDHCPのブロードキャストトラフィックを削減する技術はどれか？

- A) DHCP Snooping
- B) DHCP Relay Agent
- C) DHCP Failover
- D) DHCP Filtering

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
DHCP Relay Agent（DHCPリレーエージェント）は、異なるネットワークセグメント間でDHCPメッセージを中継し、ブロードキャストをユニキャストに変換します。<br>
<br>
Aが間違いの理由：DHCP Snoopingはセキュリティ機能<br>
Cが間違いの理由：DHCP Failoverは冗長化機能<br>

<br>
【補足】これにより、DHCPサーバを各セグメントに配置する必要がなくなります。

## 10. 専門用語集

このドキュメントで使用された専門用語について、アルファベット順・50音順で解説します。

### アルファベット

**ACK (Acknowledge)**
- **読み方**: アック
- **意味**: DHCPプロセスの最終段階で、サーバがIPアドレスの割り当てを確認するメッセージ
- **関連用語**: DHCP、DORA

**BOOTP (Bootstrap Protocol)**
- **読み方**: ブートピー
- **意味**: DHCPの前身となったプロトコル。静的なアドレス割り当てのみをサポート
- **関連用語**: DHCP、TFTP

**DHCP (Dynamic Host Configuration Protocol)**
- **読み方**: ディーエイチシーピー
- **意味**: ネットワーク機器に対して動的にIPアドレスやネットワーク設定を割り当てるプロトコル
- **関連用語**: IP、UDP、BOOTP

**DHCP Relay Agent**
- **読み方**: ディーエイチシーピー リレーエージェント
- **意味**: 異なるネットワークセグメント間でDHCPメッセージを中継する機能
- **関連用語**: DHCP、ルータ、VLAN

**DHCP Snooping**
- **読み方**: ディーエイチシーピー スヌーピング
- **意味**: 不正なDHCPサーバからネットワークを保護するセキュリティ機能
- **関連用語**: セキュリティ、スイッチ、DHCP

**DHCPv6**
- **読み方**: ディーエイチシーピーブイシックス
- **意味**: IPv6環境で使用されるDHCPプロトコル
- **関連用語**: IPv6、SLAAC、プレフィックス委任

**DISCOVER**
- **読み方**: ディスカバー
- **意味**: クライアントがDHCPサーバを探すために送信する最初のメッセージ
- **関連用語**: DHCP、DORA、ブロードキャスト

**DNS (Domain Name System)**
- **読み方**: ディーエヌエス
- **意味**: ドメイン名をIPアドレスに変換するシステム
- **関連用語**: IPアドレス、ドメイン名

**DORA**
- **読み方**: ドーラ
- **意味**: DHCPの4つの基本メッセージ（Discover、Offer、Request、Acknowledge）の頭文字
- **関連用語**: DHCP、メッセージ交換

**IPAM (IP Address Management)**
- **読み方**: アイパム
- **意味**: IPアドレス、DNS、DHCPを統合的に管理するシステム
- **関連用語**: DHCP、DNS、SDN

**MAC Address**
- **読み方**: マックアドレス
- **意味**: ネットワーク機器の物理アドレス。48ビットの一意な識別子
- **関連用語**: Ethernet、ハードウェアアドレス

**MCLT (Maximum Client Lead Time)**
- **読み方**: エムシーエルティー
- **意味**: DHCPフェイルオーバーで、パートナーサーバなしでリースを延長できる最大時間
- **関連用語**: フェイルオーバー、冗長化

**NAK (Negative Acknowledge)**
- **読み方**: ナック
- **意味**: DHCPサーバがリクエストを拒否する際に送信するメッセージ
- **関連用語**: DHCP、エラー処理

**OFFER**
- **読み方**: オファー
- **意味**: DHCPサーバがクライアントに対してIPアドレスを提示するメッセージ
- **関連用語**: DHCP、DORA

**REQUEST**
- **読み方**: リクエスト
- **意味**: クライアントが特定のDHCPサーバのOfferを受け入れる意思を示すメッセージ
- **関連用語**: DHCP、DORA

**RFC (Request for Comments)**
- **読み方**: アールエフシー
- **意味**: インターネット技術の標準を定めた文書。DHCPはRFC 2131で定義
- **関連用語**: 標準化、IETF

**SLAAC (Stateless Address Autoconfiguration)**
- **読み方**: スラック
- **意味**: IPv6でルータ広告を使用してアドレスを自動設定する方式
- **関連用語**: IPv6、DHCPv6、RA

**UDP (User Datagram Protocol)**
- **読み方**: ユーディーピー
- **意味**: DHCPが使用するトランスポート層プロトコル
- **関連用語**: TCP/IP、ポート番号

**VLAN (Virtual Local Area Network)**
- **読み方**: ブイラン
- **意味**: 物理的な接続に依存しない論理的なネットワークセグメント
- **関連用語**: スイッチ、ネットワークセグメント

### あ行

**アドレスプール**
- **読み方**: あどれすぷーる
- **意味**: DHCPサーバが割り当て可能なIPアドレスの範囲
- **業界での使われ方**: 「プールに空きがない」などと表現
- **関連用語**: スコープ、レンジ

**オプション（DHCPオプション）**
- **読み方**: おぷしょん
- **意味**: IPアドレス以外の追加設定情報を配布するための仕組み
- **業界での使われ方**: 「オプション3でゲートウェイを配布」など
- **関連用語**: パラメータ、設定値

### か行

**クライアント**
- **読み方**: くらいあんと
- **意味**: DHCPサーバからIPアドレスを取得する側の機器
- **業界での使われ方**: エンドユーザーのPC、スマートフォンなど
- **関連用語**: サーバ、ホスト

**ゲートウェイ**
- **読み方**: げーとうぇい
- **意味**: 異なるネットワーク間の出入り口となるルータ
- **業界での使われ方**: 「デフォルトゲートウェイ」として設定
- **関連用語**: ルータ、デフォルトルート

### さ行

**サブネットマスク**
- **読み方**: さぶねっとますく
- **意味**: IPアドレスのネットワーク部とホスト部を区別するためのマスク値
- **業界での使われ方**: 「/24」のようなCIDR表記でも表現
- **関連用語**: ネットマスク、CIDR

**スコープ**
- **読み方**: すこーぷ
- **意味**: DHCPサーバで管理する特定のネットワーク範囲の設定単位
- **業界での使われ方**: 「スコープを作成する」「スコープオプション」など
- **関連用語**: アドレスプール、サブネット

**静的マッピング**
- **読み方**: せいてきまっぴんぐ
- **意味**: 特定のMACアドレスに対して固定的にIPアドレスを割り当てる設定
- **業界での使われ方**: 「予約」「固定割り当て」とも呼ばれる
- **関連用語**: DHCP予約、手動割り当て

### た行

**動的割り当て**
- **読み方**: どうてきわりあて
- **意味**: アドレスプールから自動的にIPアドレスを選択して割り当てる方式
- **業界での使われ方**: 最も一般的なDHCPの利用方法
- **関連用語**: 自動割り当て、手動割り当て

### は行

**フェイルオーバー**
- **読み方**: ふぇいるおーばー
- **意味**: プライマリサーバ障害時にセカンダリサーバが処理を引き継ぐ仕組み
- **業界での使われ方**: 「フェイルオーバー構成」「フェイルオーバー関係」
- **関連用語**: 冗長化、高可用性

**ブロードキャスト**
- **読み方**: ぶろーどきゃすと
- **意味**: ネットワーク内の全ての機器に対して送信される通信
- **業界での使われ方**: DHCPのDiscoverメッセージで使用
- **関連用語**: マルチキャスト、ユニキャスト

**プレフィックス委任**
- **読み方**: ぷれふぃっくすいにん
- **意味**: DHCPv6でルータに対してIPv6プレフィックスを配布する機能
- **業界での使われ方**: ISPが顧客にプレフィックスを自動配布する際に使用
- **関連用語**: DHCPv6、PD

### ま行

**メッセージタイプ**
- **読み方**: めっせーじたいぷ
- **意味**: DHCPメッセージの種類を示す識別子
- **業界での使われ方**: DISCOVER、OFFER、REQUEST、ACKなど
- **関連用語**: DHCPメッセージ、オプション53

### ら行

**リース期間**
- **読み方**: りーすきかん
- **意味**: クライアントがIPアドレスを使用できる有効期間
- **業界での使われ方**: 「リースの更新」「リース切れ」など
- **関連用語**: リース時間、更新、再バインド

**リレーエージェント**
- **読み方**: りれーえーじぇんと
- **意味**: 異なるサブネット間でDHCPメッセージを中継する機能
- **業界での使われ方**: ルータやL3スイッチに実装されることが多い
- **関連用語**: DHCPリレー、ヘルパーアドレス

**ルータ広告（RA）**
- **読み方**: るーたこうこく
- **意味**: IPv6ルータが定期的に送信するネットワーク情報の通知
- **業界での使われ方**: SLAACと組み合わせて使用
- **関連用語**: IPv6、SLAAC、ICMPv6
