# ミラーリングとデュプレキシングについて

## 概要
データの可用性と信頼性を確保するために、システムの冗長化技術は不可欠です。ミラーリングとデュプレキシングは、いずれもRAID（Redundant Array of Independent Disks）技術の一種として、データの複製を保持することで障害時のデータ損失を防ぐ仕組みです。本資料では、これら2つの技術の詳細な仕組み、違い、適用場面について解説します。

## 1. 基本概念・仕組み

### ミラーリング（Mirroring）
- **定義**: 2台以上のディスクに同じデータを同時に書き込む技術。RAID 1として知られる
- **動作原理**: 1つのディスクコントローラが複数のディスクに対して同一のデータを並列に書き込む
- **特徴**: 
  - シンプルな実装で高い信頼性を実現
  - ディスク容量の利用効率は50%（2台構成の場合）
  - 読み込み性能の向上が可能（複数ディスクから並列読み込み）

### デュプレキシング（Duplexing）
- **定義**: ミラーリングに加えて、ディスクコントローラも二重化した技術
- **動作原理**: 各ディスクに独立したコントローラを割り当て、完全な冗長性を実現
- **特徴**: 
  - ミラーリングよりも高い可用性を実現
  - コントローラ障害にも対応可能
  - コストが高くなる傾向がある

### 両技術の関係
- **共通点**: データの複製を保持し、ディスク障害からデータを保護
- **相違点**: コントローラの冗長化の有無
- **進化**: デュプレキシングはミラーリングの拡張版として位置づけられる

## 2. 種類・分類

### 分類軸
ミラーリングとデュプレキシングは、以下の観点から分類されます：
- 冗長化のレベル（データのみ vs データ＋コントローラ）
- 実装方式（ハードウェア vs ソフトウェア）
- 同期方式（同期 vs 非同期）

### ミラーリング: RAID 1
**特徴:**
- 最小2台のディスクで構成
- 1台のコントローラで制御
- データは完全に同一のコピーを保持

**算出方法:**
```
利用可能容量 = ディスク容量 × ディスク数 ÷ 2
読み込み性能 = 単体ディスク性能 × 最大2倍
書き込み性能 = 単体ディスク性能と同等
```

**📊 具体的な計算例**
**例: Webサーバーのデータベース用ストレージ**
- ディスク容量: 2TB × 2台
- IOPS性能: 10,000 IOPS/ディスク

**ステップ1: 利用可能容量の計算**
```
利用可能容量 = 2TB × 2 ÷ 2 = 2TB
```

**ステップ2: 性能の算出**
```
読み込み性能 = 10,000 IOPS × 1.8（実効値） = 18,000 IOPS
書き込み性能 = 10,000 IOPS × 1.0 = 10,000 IOPS
```

**結果: 2TBの利用可能容量で、読み込み18,000 IOPS、書き込み10,000 IOPSの性能**

💡 **実際の現場では**: データベースサーバーなど、読み込み処理が多いシステムで有効。書き込みが多い場合は、SSDの採用やキャッシュの活用を検討します。

### デュプレキシング: 拡張RAID 1
**特徴:**
- 最小2台のディスクと2台のコントローラで構成
- 各ディスクに専用コントローラを割り当て
- コントローラレベルでの冗長性を確保

**算出方法:**
```
利用可能容量 = ディスク容量 × ディスク数 ÷ 2
可用性 = 1 - (ディスク故障率 × コントローラ故障率)
コスト = (ディスク単価 × 2) + (コントローラ単価 × 2)
```

**📊 具体的な計算例**
**例: 金融機関の基幹システム**
- ディスク容量: 4TB × 2台
- ディスク故障率: 年間2%
- コントローラ故障率: 年間0.5%

**ステップ1: 利用可能容量の計算**
```
利用可能容量 = 4TB × 2 ÷ 2 = 4TB
```

**ステップ2: 可用性の計算（ミラーリングとの比較）**
```
ミラーリング可用性 = 1 - (0.02 × 0.02) = 0.9996（99.96%）
デュプレキシング可用性 = 1 - (0.02 × 0.005 × 0.02 × 0.005) = 0.99999999（99.999999%）
```

**結果: デュプレキシングにより、ほぼ100%の可用性を実現**

💡 **実際の現場では**: 24時間365日の稼働が求められる金融システムや医療システムで採用。初期コストは高いが、ダウンタイムによる損失を考慮すると費用対効果が高い。

## 3. 詳細仕様・パラメータ

### 重要なパラメータ群

#### ディスク同期方式の詳細
- **意味**: データをディスクに書き込む際の同期タイミング
- **設定範囲**: 同期（Synchronous）/ 非同期（Asynchronous）
- **影響**: パフォーマンスと整合性のトレードオフ
- **推奨値**: 
  - 同期: 金融・医療などクリティカルなシステム
  - 非同期: 一般的なWebサービス、開発環境

#### リビルド時間の詳細
- **意味**: 障害発生後、新しいディスクにデータを復元する時間
- **計算式**: リビルド時間 = ディスク容量 ÷ リビルド速度
- **影響**: リビルド中は冗長性が失われるため、短いほど良い
- **推奨値**: 
  - 1TB以下: 2-4時間
  - 4TB以上: 8-16時間（速度優先設定推奨）

#### キャッシュサイズの詳細
- **意味**: コントローラ上のキャッシュメモリ容量
- **設定範囲**: 256MB～8GB（一般的な範囲）
- **影響**: 書き込み性能の向上、バースト転送への対応
- **推奨値**: 
  - 小規模システム: 512MB～1GB
  - 大規模システム: 2GB～8GB

## 4. 実装例・適用事例

### 基本実装（Linux環境でのソフトウェアRAID）

#### ミラーリング（RAID 1）の実装
```bash
# mdadmを使用したRAID 1の作成
mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc

# RAIDアレイの状態確認
cat /proc/mdstat

# ファイルシステムの作成
mkfs.ext4 /dev/md0

# マウント
mount /dev/md0 /data
```

#### 監視スクリプトの例
```bash
#!/bin/bash
# RAID監視スクリプト

RAID_DEVICE="/dev/md0"
ALERT_EMAIL="admin@example.com"

# RAIDステータスチェック
STATUS=$(mdadm --detail $RAID_DEVICE | grep "State :" | awk '{print $3}')

if [ "$STATUS" != "clean" ] && [ "$STATUS" != "active" ]; then
    # アラート送信
    echo "RAID degraded on $(hostname)" | mail -s "RAID Alert" $ALERT_EMAIL
    
    # 詳細ログ記録
    mdadm --detail $RAID_DEVICE >> /var/log/raid_alert.log
fi
```

### 応用実装（エンタープライズ環境）

### 実際の適用事例

#### 事例1: 大手ECサイト（楽天市場相当規模）
- **課題**: 年末年始のアクセス集中時でもデータベースの可用性を確保
- **適用方法**: 
  - 商品マスタDB: ミラーリング（RAID 1）
  - 決済処理DB: デュプレキシング
  - 画像ストレージ: RAID 5（コスト重視）
- **結果**: 
  - ダウンタイム: 年間5分以下を達成
  - 読み込み性能: 1.7倍向上
- **効果**: 
  - 売上機会損失を最小化
  - 顧客満足度の向上

#### 事例2: 地方銀行の勘定系システム
- **課題**: 法規制要件（99.999%の可用性）を満たす必要
- **適用方法**: 
  - 全ての重要データにデュプレキシングを適用
  - 3重化構成（本番、DR、バックアップ）
  - リアルタイム同期レプリケーション
- **結果**: 
  - 可用性: 99.9999%（シックスナイン）達成
  - RPO（目標復旧時点）: 0秒
  - RTO（目標復旧時間）: 30秒以内
- **効果**: 
  - 監督官庁の要件を完全にクリア
  - 顧客の信頼性向上

## 5. メリット・デメリット

### メリット

**1. 高い可用性**
- **理由**: データの複製により、単一障害点を排除
- **効果**: 
  - ミラーリング: 99.96%以上の可用性
  - デュプレキシング: 99.999%以上の可用性
- **具体例**: ディスク1台が故障しても、サービス継続可能

**2. 読み込み性能の向上**
- **理由**: 複数のディスクから並列にデータを読み込み可能
- **効果**: 理論上最大2倍、実効値で1.5～1.8倍の性能向上
- **具体例**: データベースの検索処理が高速化

**3. 簡単な管理**
- **理由**: 複雑なパリティ計算が不要
- **効果**: 管理者の負担軽減、運用ミスの削減
- **具体例**: RAID 5と比較して、リビルド処理がシンプル

### デメリット

**1. ストレージ効率の低さ**
- **理由**: データを完全に複製するため、容量の50%しか利用できない
- **影響**: ストレージコストが2倍になる
- **対策**: 重要度に応じてRAIDレベルを使い分ける

**2. 書き込み性能の制限**
- **理由**: 全てのディスクに同じデータを書き込む必要がある
- **影響**: 書き込み集約的なワークロードでボトルネックになる可能性
- **対策**: 
  - 高速なSSDの採用
  - ライトバックキャッシュの活用
  - 非同期モードの検討（データ整合性とのトレードオフ）

**3. 初期コストの高さ（特にデュプレキシング）**
- **理由**: ディスクとコントローラの両方を二重化する必要
- **影響**: 
  - ミラーリング: 通常の2倍のディスクコスト
  - デュプレキシング: 2倍のディスク＋2倍のコントローラコスト
- **対策**: 
  - TCO（総所有コスト）での評価
  - ダウンタイムコストとの比較検討

## 6. 選択・導入の指針

### 技術選択の基準
| 観点 | ミラーリング | デュプレキシング | RAID 5 | RAID 6 |
|------|-------------|---------------|---------|---------|
| 可用性 | ◎ | ◎+ | ○ | ◎ |
| 読込性能 | ◎ | ◎ | ○ | △ |
| 書込性能 | ○ | ○ | △ | × |
| 容量効率 | × | × | ◎ | ○ |
| コスト | △ | × | ○ | △ |
| 管理容易性 | ◎ | ○ | △ | × |

### 適用判断フローチャート

1. **可用性要件は99.999%以上必要か？**
   - Yes → デュプレキシングを推奨
   - No → 次の判断へ

2. **ストレージ容量効率を重視するか？**
   - Yes → RAID 5/6を検討
   - No → 次の判断へ

3. **読み込み性能が重要か？**
   - Yes → ミラーリングを推奨
   - No → 次の判断へ

4. **予算に制約があるか？**
   - Yes → ミラーリング（ソフトウェアRAID）
   - No → デュプレキシング（ハードウェアRAID）

### 業界別推奨構成

#### 金融業界
- **推奨**: デュプレキシング＋遠隔地レプリケーション
- **理由**: 規制要件、ゼロダウンタイム要求
- **構成例**: 本番サイト（デュプレキシング）→ DRサイト（デュプレキシング）

#### EC・Web サービス
- **推奨**: ミラーリング＋CDN
- **理由**: コストと性能のバランス
- **構成例**: DB（ミラーリング）、静的コンテンツ（RAID 5）

#### 製造業（IoT/エッジ）
- **推奨**: ミラーリング（小規模）
- **理由**: 設置スペース、電力制約
- **構成例**: エッジサーバー（2台構成のミラーリング）

## 7. 最新動向・今後の展望

### 現在の課題
- **大容量化への対応**: 10TB以上のディスクでのリビルド時間増大
- **SSDの普及**: 従来のHDD前提の設計見直し
- **クラウド化**: オンプレミスRAIDからクラウドストレージへの移行

### 研究動向
- **AI活用**: 障害予測による予防的ディスク交換
- **新しいRAIDレベル**: RAID 7、RAID-DPなどの登場
- **ソフトウェア定義ストレージ**: より柔軟な冗長性の実現

### 将来予測
- **2025年まで**: NVMe SSDによる超高速ミラーリングの一般化
- **2030年まで**: 量子ストレージ技術による新しい冗長化手法
- **長期展望**: 自己修復型ストレージシステムの実現

### 関連技術
- **レプリケーション技術**: 地理的に離れた場所へのデータ複製
- **スナップショット**: ある時点のデータ状態を保存
- **イレイジャーコーディング**: より効率的なデータ保護手法

## 8. 理解度確認クイズ（4択問題20問）

### 問題1
ミラーリングとデュプレキシングの最も重要な違いは何ですか？

- A) ディスクの台数が異なる
- B) コントローラの冗長化の有無
- C) データの圧縮方式が異なる
- D) 対応するOSが異なる

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
ミラーリングはディスクのみを冗長化しますが、デュプレキシングはディスクに加えてコントローラも冗長化します。これにより、コントローラ障害にも対応できる高い可用性を実現します。<br>
<br>
Aが間違いの理由：両方とも最低2台のディスクを使用します<br>
Cが間違いの理由：どちらもデータ圧縮とは無関係です<br>
Dが間違いの理由：OS依存性はありません
</details>

### 問題2
RAID 1（ミラーリング）で4TBのディスク2台を使用した場合、利用可能な容量はどれですか？

- A) 8TB
- B) 4TB
- C) 2TB
- D) 6TB

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
RAID 1では、データを完全に複製するため、利用可能容量は単一ディスクの容量と同じになります。計算式：4TB × 2台 ÷ 2 = 4TB<br>
<br>
Aが間違いの理由：これは単純な合計容量で、冗長性を考慮していません<br>
Cが間違いの理由：容量が半分になるわけではありません<br>
Dが間違いの理由：RAID 1では75%の容量は使用できません
</details>

### 問題3
ミラーリングにおいて、読み込み性能が向上する理由は何ですか？

- A) データが圧縮されているため
- B) 複数のディスクから並列に読み込めるため
- C) キャッシュメモリが大きいため
- D) CPUの処理が高速化するため

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
ミラーリングでは、同じデータが複数のディスクに存在するため、読み込み要求を複数のディスクに分散できます。これにより、理論上最大2倍（実効値1.5-1.8倍）の読み込み性能向上が可能です。<br>
<br>
Aが間違いの理由：ミラーリングはデータ圧縮技術ではありません<br>
Cが間違いの理由：キャッシュはミラーリング固有の機能ではありません<br>
Dが間違いの理由：CPU処理とは直接関係ありません
</details>

デュプレキシングが特に推奨される環境はどれですか？

- A) 個人用PCのバックアップ
- B) 開発環境のテストサーバー
- C) 金融機関の基幹システム
- D) 一時的なデータ保存

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
金融機関の基幹システムは99.999%以上の可用性が求められ、コントローラ障害も含めた完全な冗長性が必要です。デュプレキシングはこの要件を満たす最適な選択肢です。<br>
<br>
Aが間違いの理由：個人用途にはコストが高すぎます<br>
Bが間違いの理由：開発環境には過剰な投資です<br>
Dが間違いの理由：一時データには冗長性は不要です
</details>

### 問題5
ソフトウェアRAIDとハードウェアRAIDの主な違いは何ですか？

- A) 対応するディスク容量の上限
- B) RAID処理を行う場所（CPU vs 専用チップ）
- C) データの暗号化方式
- D) 使用できるファイルシステム

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
ソフトウェアRAIDはOSとCPUでRAID処理を行い、ハードウェアRAIDは専用のRAIDコントローラチップで処理します。ハードウェアRAIDの方が高性能ですが、コストも高くなります。<br>
<br>
Aが間違いの理由：容量上限は実装に依存し、本質的な違いではありません<br>
Cが間違いの理由：暗号化はRAIDとは独立した機能です<br>
Dが間違いの理由：ファイルシステムはRAIDの上位層で決定されます
</details>

### 問題6
RAID 1のディスクが1台故障した場合の適切な対応はどれですか？

- A) システムを即座に停止する
- B) 故障ディスクを交換し、リビルドを実行する
- C) 残りのディスクのデータをバックアップしてから交換
- D) RAID構成を解除して単体ディスクとして使用

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
RAID 1では1台のディスク故障時もシステムは稼働継続できます。故障ディスクを新しいディスクに交換し、自動または手動でリビルドを実行することで冗長性を回復します。<br>
<br>
Aが間違いの理由：RAID 1の利点である可用性を無駄にしています<br>
Cが間違いの理由：既に冗長性があるため追加バックアップは不要です<br>
Dが間違いの理由：冗長性を失い、次の障害でデータ損失のリスクがあります
</details>

### 問題7
リビルド中のRAID 1アレイの状態として正しいものはどれですか？

- A) 完全に停止している
- B) 読み書きは可能だが冗長性がない
- C) 読み込みのみ可能
- D) 性能は低下するが冗長性は維持される

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
リビルド中は正常なディスクでサービスを継続できますが、データの複製が1つしかないため冗長性は一時的に失われます。この期間中に残りのディスクが故障するとデータ損失につながります。<br>
<br>
Aが間違いの理由：RAID 1はリビルド中も稼働を継続します<br>
Cが間違いの理由：読み書き両方が可能です<br>
Dが間違いの理由：冗長性は回復するまで失われています
</details>

### 問題8
ミラーリングの書き込み性能が読み込み性能より低い理由は何ですか？

## 9. 専門用語集

このスライドで使用された専門用語について、アルファベット順・50音順で解説します。

### アルファベット

**ECC (Error Correcting Code)**
- **読み方**: イーシーシー
- **意味**: データの誤りを検出し、自動的に訂正する符号。メモリやストレージで使用され、データの信頼性を向上させる
- **関連用語**: パリティ、チェックサム

**IOPS (Input/Output Operations Per Second)**
- **読み方**: アイオーピーエス
- **意味**: ストレージデバイスが1秒間に処理できる入出力操作の数。ランダムアクセス性能の指標として使用される
- **関連用語**: スループット、レイテンシ

**MTBF (Mean Time Between Failures)**
- **読み方**: エムティービーエフ
- **意味**: 平均故障間隔。システムや部品が故障するまでの平均稼働時間を示す信頼性指標
- **関連用語**: MTTR、可用性

**MTTR (Mean Time To Repair)**
- **読み方**: エムティーティーアール
- **意味**: 平均修復時間。故障が発生してから修復が完了するまでの平均時間
- **関連用語**: MTBF、RTO

**NVMe (Non-Volatile Memory Express)**
- **読み方**: エヌブイエムイー
- **意味**: SSD専用に設計された高速インターフェース規格。PCIe経由で接続し、従来のSATAより大幅に高速
- **関連用語**: SSD、PCIe、SATA

**RAID (Redundant Array of Independent Disks)**
- **読み方**: レイド
- **意味**: 複数のディスクを組み合わせて、性能向上や冗長性を実現する技術の総称
- **関連用語**: ミラーリング、ストライピング、パリティ

**RPO (Recovery Point Objective)**
- **読み方**: アールピーオー
- **意味**: 目標復旧時点。災害発生時に、どの時点までのデータを復旧するかの目標値
- **関連用語**: RTO、バックアップ、レプリケーション

**RTO (Recovery Time Objective)**
- **読み方**: アールティーオー
- **意味**: 目標復旧時間。災害発生からシステム復旧までの目標時間
- **関連用語**: RPO、MTTR、災害復旧

**SAN (Storage Area Network)**
- **読み方**: サン
- **意味**: ストレージ専用のネットワーク。サーバーとストレージを高速に接続し、柔軟な構成を可能にする
- **関連用語**: NAS、DAS、ファイバーチャネル

**SSD (Solid State Drive)**
- **読み方**: エスエスディー
- **意味**: フラッシュメモリを使用した記憶装置。可動部品がなく、HDDより高速で耐衝撃性に優れる
- **関連用語**: HDD、NVMe、フラッシュメモリ

**TCO (Total Cost of Ownership)**
- **読み方**: ティーシーオー
- **意味**: 総所有コスト。初期投資だけでなく、運用・保守・廃棄までを含めた総コスト
- **関連用語**: ROI、初期コスト、運用コスト

### あ行

**イレイジャーコーディング**
- **読み方**: いれいじゃーこーでぃんぐ
- **意味**: データを複数の断片に分割し、冗長性を持たせる符号化技術。一部の断片が失われても元のデータを復元可能
- **関連用語**: RAID、分散ストレージ

**ウェアレベリング**
- **読み方**: うぇあれべりんぐ
- **意味**: SSDにおいて、書き込み回数を各メモリセルに均等に分散させる技術。SSDの寿命を延ばす効果がある
- **関連用語**: SSD、書き込み寿命、NAND型フラッシュ

### か行

**可用性（Availability）**
- **読み方**: かようせい
- **意味**: システムが正常に稼働している時間の割合。99.999%（ファイブナイン）など、パーセンテージで表現される
- **関連用語**: 稼働率、ダウンタイム、冗長性

**キャッシュメモリ**
- **読み方**: きゃっしゅめもり
- **意味**: 頻繁にアクセスされるデータを一時的に保存する高速メモリ。ディスクアクセスを減らし、性能を向上させる
- **関連用語**: ライトバック、ライトスルー、バッファ

**クォーラム（Quorum）**
- **読み方**: くぉーらむ
- **意味**: 分散システムにおいて、正常な動作を保証するために必要な最小ノード数。スプリットブレイン防止に使用
- **関連用語**: スプリットブレイン、クラスタ、投票

### さ行

**冗長性（Redundancy）**
- **読み方**: じょうちょうせい
- **意味**: システムの一部が故障しても全体が機能を維持できるよう、予備や複製を用意すること
- **関連用語**: 可用性、フォールトトレランス、RAID

**ストライピング**
- **読み方**: すとらいぴんぐ
- **意味**: データを複数のディスクに分散して書き込む技術。RAID 0で使用され、性能向上を実現
- **関連用語**: RAID 0、並列処理、スループット

**スナップショット**
- **読み方**: すなっぷしょっと
- **意味**: ある時点のデータの状態を保存する機能。バックアップや開発環境の複製に使用
- **関連用語**: バックアップ、ポイントインタイムリカバリ

**スプリットブレイン**
- **読み方**: すぷりっとぶれいん
- **意味**: ネットワーク分断により、クラスタの各ノードが独立して動作し、データの不整合が発生する状態
- **関連用語**: クラスタ、クォーラム、フェンシング

**スループット**
- **読み方**: するーぷっと
- **意味**: 単位時間あたりのデータ転送量。MB/秒やGB/秒で表現され、連続転送性能の指標
- **関連用語**: IOPS、帯域幅、転送速度

### た行

**ダウンタイム**
- **読み方**: だうんたいむ
- **意味**: システムが停止している時間。計画停止と計画外停止に分類される
- **関連用語**: 可用性、稼働率、メンテナンスウィンドウ

**デグレード**
- **読み方**: でぐれーど
- **意味**: RAIDアレイの一部が故障し、冗長性が失われた状態。この状態でも動作は継続するが、追加の故障でデータ損失のリスクがある
- **関連用語**: RAID、リビルド、故障

### な行

**熱暴走**
- **読み方**: ねつぼうそう
- **意味**: 電子機器が過熱により正常に動作しなくなる現象。適切な冷却が必要
- **関連用語**: 冷却、データセンター、温度監視

### は行

**パリティ**
- **読み方**: ぱりてぃ
- **意味**: データの誤り検出・訂正のための冗長ビット。RAID 5/6で使用され、ディスク故障時のデータ復元に利用
- **関連用語**: RAID 5、RAID 6、XOR演算

**ファイバーチャネル**
- **読み方**: ふぁいばーちゃねる
- **意味**: 高速なストレージネットワーク接続規格。主にSAN環境で使用される
- **関連用語**: SAN、iSCSI、ストレージネットワーク

**フェイルオーバー**
- **読み方**: ふぇいるおーばー
- **意味**: 主系システムが故障した際に、自動的に待機系システムに切り替わる機能
- **関連用語**: クラスタ、高可用性、フェイルバック

**ホットスペア**
- **読み方**: ほっとすぺあ
- **意味**: RAIDアレイで故障に備えて待機している予備ディスク。故障時に自動的にリビルドが開始される
- **関連用語**: RAID、リビルド、予備ディスク

**ホットスワップ**
- **読み方**: ほっとすわっぷ
- **意味**: システムを停止せずに部品（主にディスク）を交換できる機能
- **関連用語**: 活性交換、可用性、保守性

### ま行

**ミラーリング**
- **読み方**: みらーりんぐ
- **意味**: 同じデータを複数のディスクに同時に書き込む技術。RAID 1の基本技術
- **関連用語**: RAID 1、冗長性、デュプレキシング

### ら行

**ライトバック**
- **読み方**: らいとばっく
- **意味**: データをキャッシュに書き込んだ時点で完了とし、後でディスクに書き込むキャッシュ方式。高速だが電源断でデータ損失リスクあり
- **関連用語**: ライトスルー、キャッシュ、バッテリーバックアップ

**ライトスルー**
- **読み方**: らいとするー
- **意味**: データをディスクに物理的に書き込むまで完了としないキャッシュ方式。安全だが性能は低下
- **関連用語**: ライトバック、キャッシュ、データ整合性

**リビルド**
- **読み方**: りびるど
- **意味**: RAIDアレイで故障したディスクを交換後、データを再構築するプロセス
- **関連用語**: RAID、復旧、冗長性

**レイテンシ**
- **読み方**: れいてんし
- **意味**: データの要求から応答までの遅延時間。ミリ秒やマイクロ秒で測定される
- **関連用語**: 応答時間、IOPS、性能

**レプリケーション**
- **読み方**: れぷりけーしょん
- **意味**: データを別の場所に複製する技術。災害対策やロードバランシングに使用
- **関連用語**: 同期複製、非同期複製、災害復旧

### わ行

**ワークロード**
- **読み方**: わーくろーど
- **意味**: システムが処理する作業の種類や量。読み込み中心、書き込み中心などの特性がある
- **関連用語**: IOPS、スループット、性能要件
