# CSMA/CA・CSMA/CDについて

## 概要

CSMA（Carrier Sense Multiple Access）は、複数のデバイスが同じ通信媒体を共有する際の媒体アクセス制御方式です。CSMA/CA（Collision Avoidance：衝突回避）とCSMA/CD（Collision Detection：衝突検出）は、このCSMAの代表的な2つの実装方式で、それぞれ無線LANと有線LANで使用されています。

## 1. 基本概念・仕組み

### CSMAの基本原理
- **定義**: 送信前に媒体の使用状況を確認（キャリアセンス）してから送信を行う方式
- **動作原理**: 媒体が空いていることを確認してからデータを送信
- **特徴**: 複数のノードが効率的に通信媒体を共有可能

### CSMA/CDの仕組み
- **定義**: 衝突検出型のCSMA方式で、主に有線イーサネットで使用
- **動作原理**: 
  1. キャリアセンス：送信前に回線の使用状況を確認
  2. データ送信：回線が空いていれば送信開始
  3. 衝突検出：送信中も常に衝突を監視
  4. JAM信号：衝突検出時にJAM信号を送信して全ノードに通知
  5. バックオフ：ランダムな時間待機後、再送信を試行
- **特徴**: リアルタイムで衝突を検出し、即座に対処可能

### CSMA/CAの仕組み
- **定義**: 衝突回避型のCSMA方式で、主に無線LAN（Wi-Fi）で使用
- **動作原理**:
  1. キャリアセンス：物理的キャリアセンスと仮想的キャリアセンスの併用
  2. IFS（Inter Frame Space）：フレーム間隔による優先制御
  3. ランダムバックオフ：送信前にランダムな待機時間を設定
  4. RTS/CTS：隠れ端末問題への対処（オプション）
  5. ACK確認：受信確認による信頼性確保
- **特徴**: 無線環境では衝突検出が困難なため、事前に衝突を回避

## 2. 種類・分類

### 分類軸
CSMA方式は、衝突への対処方法により以下のように分類されます：

### CSMA/CD: 衝突検出方式
**特徴:**
- 有線環境での使用を前提
- 送信と同時に衝突検出が可能
- 衝突時は即座に送信を中止
- 10BASE-T、100BASE-TX等で採用

**算出方法:**
```
最小フレーム長 = 2 × 伝送遅延時間 × ビットレート
```

**📊 具体的な計算例**
**例: 100BASE-TXでの最小フレーム長計算**
- 前提条件1: 最大ケーブル長 = 100m
- 前提条件2: 信号伝搬速度 = 2×10^8 m/s
- 前提条件3: ビットレート = 100Mbps

**ステップ1: 往復伝送遅延時間の計算**
```
往復遅延 = 2 × 100m ÷ (2×10^8 m/s) = 1μs
```

**ステップ2: 最小フレーム長の計算**
```
最小フレーム長 = 1μs × 100Mbps = 100ビット
（実際は余裕を見て512ビット = 64バイトに設定）
```

**結果: 最小フレーム長は64バイト**

💡 **実際の現場では**: ギガビットイーサネットではキャリアエクステンションにより512バイトまで拡張

### CSMA/CA: 衝突回避方式
**特徴:**
- 無線環境での使用を前提
- 事前の待機時間により衝突を回避
- IFSとバックオフによる優先制御
- IEEE 802.11（Wi-Fi）で採用

**IFS（Inter Frame Space）の種類:**
```
SIFS（Short IFS）: 10μs - 最高優先度（ACK、CTS等）
PIFS（PCF IFS）: SIFS + 1スロット時間 - PCFモード用
DIFS（DCF IFS）: SIFS + 2スロット時間 - 通常データ
EIFS（Extended IFS）: エラー時の拡張待機時間
```

**📊 具体的な計算例**
**例: IEEE 802.11gでのバックオフ時間計算**
- 前提条件1: コンテンションウィンドウ（CW）= 31
- 前提条件2: スロット時間 = 9μs
- 前提条件3: DIFS = 28μs

**ステップ1: ランダムバックオフ値の選択**
```
バックオフ値 = Random(0, CW) = 例：15
```

**ステップ2: 総待機時間の計算**
```
総待機時間 = DIFS + (バックオフ値 × スロット時間)
           = 28μs + (15 × 9μs)
           = 28μs + 135μs = 163μs
```

**結果: 送信前に163μs待機**

💡 **実際の現場では**: 衝突が続くとCWが指数的に増加（31→63→127...）

## 3. 詳細仕様・パラメータ

### CSMA/CDの重要パラメータ
#### スロット時間（Slot Time）
- **意味**: 最悪条件での往復伝送遅延時間
- **設定範囲**: ネットワーク規模により決定
- **影響**: 最小フレーム長を決定
- **推奨値**: 10BASE-T: 51.2μs、100BASE-TX: 5.12μs

#### JAM信号
- **意味**: 衝突を全ノードに通知する特殊信号
- **設定範囲**: 32ビット（通常は0と1の交互パターン）
- **影響**: 全ノードが送信を中止
- **推奨値**: 標準仕様に準拠

### CSMA/CAの重要パラメータ
#### コンテンションウィンドウ（CW）
- **意味**: バックオフ時間を決めるランダム値の範囲
- **設定範囲**: CWmin（15〜31）～ CWmax（1023）
- **影響**: 衝突確率とスループット
- **推奨値**: 初期値CWmin=31（802.11b/g）

#### RTS閾値
- **意味**: RTS/CTSを使用するフレームサイズの閾値
- **設定範囲**: 0〜2347バイト
- **影響**: オーバーヘッドと隠れ端末問題の対処
- **推奨値**: 2347バイト（実質的に無効化）

## 4. 実装例・適用事例

### 基本実装（簡略化したCSMA/CDアルゴリズム）
```python
# CSMA/CDの基本動作
def csma_cd_transmit(data):
    while True:
        # 1. キャリアセンス
        if is_channel_idle():
            # 2. 送信開始
            start_transmission(data)
            
            # 3. 衝突検出
            while transmitting:
                if collision_detected():
                    # 4. JAM信号送信
                    send_jam_signal()
                    # 5. バックオフ
                    backoff_time = calculate_backoff()
                    wait(backoff_time)
                    break
            else:
                # 送信成功
                return True
        else:
            # チャネルビジー時は待機
            wait_until_idle()
```

### 応用実装（CSMA/CAアルゴリズム）
```python
# CSMA/CAの基本動作
def csma_ca_transmit(data):
    retries = 0
    cw = CW_MIN
    
    while retries < MAX_RETRIES:
        # 1. キャリアセンス（物理＋仮想）
        if is_channel_idle_for(DIFS):
            # 2. バックオフ
            backoff_slots = random.randint(0, cw)
            
            for slot in range(backoff_slots):
                wait(SLOT_TIME)
                if not is_channel_idle():
                    # チャネルビジー時は中断
                    break
            else:
                # 3. 送信
                if len(data) > RTS_THRESHOLD:
                    # RTS/CTS交換
                    if send_rts_receive_cts():
                        send_data(data)
                else:
                    send_data(data)
                
                # 4. ACK待機
                if wait_for_ack(ACK_TIMEOUT):
                    return True
        
        # 再送処理
        retries += 1
        cw = min(cw * 2, CW_MAX)
    
    return False  # 送信失敗
```

### 実際の適用事例
#### 事例1: 企業内有線LAN（CSMA/CD）
- **課題**: 100台のPCを接続する社内ネットワーク構築
- **適用方法**: 100BASE-TXスイッチによるスター型構成
- **結果**: 各ポートで全二重通信により衝突ドメインを分離
- **効果**: 理論値に近い実効速度を実現

#### 事例2: 公衆Wi-Fiサービス（CSMA/CA）
- **課題**: 駅構内で500人同時接続のWi-Fi提供
- **適用方法**: 
  - IEEE 802.11acアクセスポイントを複数設置
  - チャネルボンディングで帯域確保
  - エアタイムフェアネスによる公平性確保
- **結果**: 平均30Mbpsの通信速度を維持
- **効果**: 快適なインターネット接続環境を提供

## 5. メリット・デメリット

### CSMA/CDのメリット
**1. シンプルな実装**
- **理由**: 衝突検出が電気的に簡単
- **効果**: 低コストでの実装が可能
- **具体例**: 初期のイーサネットカードは安価に製造可能

**2. 低遅延**
- **理由**: 衝突を即座に検出して対処
- **効果**: 無駄な送信時間を最小化
- **具体例**: 10μs以内に衝突を検出し送信中止

### CSMA/CDのデメリット
**1. 無線環境での使用不可**
- **理由**: 送信中は受信不可（半二重通信）
- **影響**: 衝突検出が物理的に困難
- **対策**: CSMA/CAの採用

**2. 高負荷時の性能劣化**
- **理由**: 衝突頻度の増加
- **影響**: スループットが急激に低下
- **対策**: スイッチによる衝突ドメイン分離

### CSMA/CAのメリット
**1. 無線環境での動作**
- **理由**: 事前の衝突回避メカニズム
- **効果**: 無線LANでの安定通信
- **具体例**: Wi-Fiの世界的普及

**2. QoS対応**
- **理由**: IFSによる優先制御が可能
- **効果**: 音声・映像の優先伝送
- **具体例**: VoIPやビデオ会議の品質確保

### CSMA/CAのデメリット
**1. オーバーヘッドが大きい**
- **理由**: IFS、バックオフ、ACK等の待機時間
- **影響**: 実効速度が理論値の50-70%程度
- **対策**: フレームアグリゲーション技術の採用

**2. 隠れ端末問題**
- **理由**: 全端末が互いを検出できない
- **影響**: 衝突回避が機能しない場合がある
- **対策**: RTS/CTSメカニズムの使用

## 6. 選択・導入の指針

### 技術選択の基準
| 観点 | CSMA/CD | CSMA/CA | 備考 |
|------|---------|---------|------|
| 通信媒体 | 有線 | 無線 | 物理層の特性による |
| 実装コスト | ◎ | ○ | CSMA/CDがシンプル |
| 遅延特性 | ◎ | △ | オーバーヘッドの差 |
| スケーラビリティ | ○ | ○ | 両方とも中規模まで |
| QoS対応 | △ | ◎ | CSMA/CAが優位 |

### 適用判断フローチャート
1. **通信媒体は？** 
   - 有線 → CSMA/CD（ただし現代では全二重が主流）
   - 無線 → CSMA/CAへ

2. **リアルタイム性は必要？**
   - Yes → CSMA/CAでQoS設定
   - No → 標準設定で使用

3. **端末数は？**
   - 〜50台 → 単一衝突ドメインでも可
   - 50台〜 → スイッチ/APで分割推奨

## 8. 理解度確認クイズ（4択問題20問）

### 問題1
CSMA/CDにおいて、衝突を検出した際に送信される信号は何か？

- A) ACK信号
- B) JAM信号
- C) RTS信号
- D) CTS信号

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBのJAM信号です。CSMA/CDでは、衝突を検出したノードがJAM信号（通常32ビットの特殊パターン）を送信することで、ネットワーク上の全ノードに衝突の発生を通知します。<br>
<br>
Aが間違いの理由：ACK信号は正常な受信確認に使用される<br>
Cが間違いの理由：RTS信号はCSMA/CAで使用される送信要求信号<br>
Dが間違いの理由：CTS信号はCSMA/CAで使用される送信許可信号<br>
<br>
【補足】実務では、JAM信号により全ノードが即座に送信を中止し、バックオフ処理に入ります。
</details>

### 問題2
CSMA/CAにおいて、通常のデータフレーム送信前に使用されるIFSは？

- A) SIFS
- B) PIFS
- C) DIFS
- D) EIFS

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
正解はCのDIFS（DCF Inter Frame Space）です。通常のデータフレーム送信では、DIFSの時間だけチャネルがアイドル状態であることを確認してから送信を開始します。<br>
<br>
Aが間違いの理由：SIFSは最高優先度でACKやCTS等の制御フレームに使用<br>
Bが間違いの理由：PIFSはPCFモードでの優先アクセスに使用<br>
Dが間違いの理由：EIFSはエラーフレーム受信後の拡張待機時間<br>
<br>
【補足】IFSの長さはSIFS < PIFS < DIFS < EIFSの順で、短いほど優先度が高くなります。
</details>

### 問題3
100BASE-TXで最小フレーム長が64バイトに設定されている主な理由は？

- A) プロトコルヘッダのサイズに合わせるため
- B) 衝突検出を確実に行うため
- C) 伝送効率を最大化するため
- D) メモリ管理を簡単にするため

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。最小フレーム長は、ネットワーク上の最遠端ノード間の往復伝送遅延時間（ラウンドトリップタイム）の間、送信を継続できる長さに設定されています。これにより、送信中に発生した衝突を確実に検出できます。<br>
<br>
Aが間違いの理由：ヘッダサイズは14バイトで、64バイトとは無関係<br>
Cが間違いの理由：むしろ短いフレームは効率を下げる<br>
Dが間違いの理由：メモリ管理とは直接関係ない<br>
<br>
【補足】ギガビットイーサネットでは、キャリアエクステンションにより実質512バイトまで拡張されています。
</details>

### 問題4
CSMA/CAでバックオフ時間を計算する際、コンテンションウィンドウが31、選択されたランダム値が20、スロット時間が9μsの場合、バックオフ時間は？

- A) 180μs
- B) 279μs
- C) 31μs
- D) 20μs

<details>
<summary>解答</summary>
<strong>正解: A</strong><br>
バックオフ時間 = ランダム値 × スロット時間 = 20 × 9μs = 180μs<br>
<br>
Bが間違いの理由：31 × 9 = 279はCWの最大値での計算<br>
Cが間違いの理由：CWの値そのものではない<br>
Dが間違いの理由：ランダム値そのものではなく、スロット時間を掛ける必要がある<br>
<br>
【補足】実際の送信前には、この180μsに加えてDIFS（通常28μs）の待機も必要です。
</details>

### 問題5
隠れ端末問題を解決するためにCSMA/CAで使用される仕組みは？

- A) JAM信号
- B) キャリアエクステンション
- C) RTS/CTS
- D) フレームアグリゲーション

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
正解はCのRTS/CTS（Request To Send/Clear To Send）です。送信端末がRTSを送信し、アクセスポイントがCTSで応答することで、隠れ端末にも通信の存在を通知できます。<br>
<br>
Aが間違いの理由：JAM信号はCSMA/CDで使用される衝突通知信号<br>
Bが間違いの理由：ギガビットイーサネットでの最小フレーム長拡張技術<br>
Dが間違いの理由：複数フレームをまとめて送信する効率化技術<br>
<br>
【補足】RTS/CTSはオーバーヘッドが大きいため、通常は大きなフレームのみで使用されます。
</details>

### 問題6
CSMA/CDとCSMA/CAの主な違いとして正しいものは？

- A) CSMA/CDは無線、CSMA/CAは有線で使用
- B) CSMA/CDは衝突を検出、CSMA/CAは衝突を回避
- C) CSMA/CDは全二重、CSMA/CAは半二重で動作
- D) CSMA/CDは高速、CSMA/CAは低速通信用

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。CSMA/CD（Collision Detection）は衝突を検出して対処し、CSMA/CA（Collision Avoidance）は事前に衝突を回避する方式です。<br>
<br>
Aが間違いの理由：逆で、CSMA/CDは有線、CSMA/CAは無線で使用<br>
Cが間違いの理由：両方とも基本的に半二重で動作（現代の有線は全二重が主流）<br>
Dが間違いの理由：速度は規格により異なり、方式自体の制限ではない<br>
<br>
【補足】無線では送信中の受信が困難なため、衝突検出ではなく回避方式を採用しています。
</details>

### 問題7
IEEE 802.11で定義されているIFSの長さの関係として正しいものは？

- A) SIFS > PIFS > DIFS > EIFS
- B) EIFS > DIFS > PIFS > SIFS
- C) DIFS > SIFS > PIFS > EIFS
- D) PIFS > SIFS > EIFS > DIFS

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。IFSの長さはEIFS > DIFS > PIFS > SIFSの順になっており、短いほど優先度が高くなります。<br>
<br>
Aが間違いの理由：完全に逆の順序<br>
Cが間違いの理由：SIFSが最短でなければならない<br>
Dが間違いの理由：順序が正しくない<br>
<br>
【補足】SIFSは約10μs、PIFSはSIFS+1スロット時間、DIFSはSIFS+2スロット時間となっています。
</details>

### 問題8
CSMA/CDにおいて、連続して衝突が発生した場合のバックオフアルゴリズムは？

- A) 線形バックオフ
- B) 指数バックオフ
- C) 固定バックオフ
- D) ランダムバックオフ

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBの指数バックオフ（Exponential Backoff）です。衝突が繰り返されるたびに、待機時間の選択範囲が2倍に増加します（例：0-1→0-3→0-7→0-15...）。<br>
<br>
Aが間違いの理由：待機時間が一定量ずつ増加する方式ではない<br>
Cが間違いの理由：衝突回数に関わらず同じ待機時間では効果的でない<br>
Dが間違いの理由：ランダム性はあるが、範囲が指数的に増加する<br>
<br>
【補足】通常10回目の衝突で最大値（1023スロット）に達し、16回失敗すると送信を諦めます。
</details>

### 問題9
Wi-Fi（IEEE 802.11g）で、あるノードがDIFS待機後、バックオフカウンタが5の状態で他のノードの送信を検出した場合の動作は？

- A) バックオフカウンタをリセットして最初からやり直す
- B) バックオフカウンタを5のまま保持し、次回は5から再開
- C) 送信を強行する
- D) エラーとして上位層に通知

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。CSMA/CAでは、バックオフ中に他の送信を検出した場合、カウンタを凍結（フリーズ）し、チャネルが再び空いた後、残りのカウント値から再開します。<br>
<br>
Aが間違いの理由：毎回リセットすると、優先度の概念が失われる<br>
Cが間違いの理由：衝突回避の原則に反する<br>
Dが間違いの理由：正常な動作であり、エラーではない<br>
<br>
【補足】この仕組みにより、長く待っているノードほど送信機会を得やすくなります。
</details>

### 問題10
CSMA/CDが現在の有線LANであまり使用されなくなった主な理由は？

- A) 処理が複雑すぎるため
- B) スイッチングハブの普及により全二重通信が主流になったため
- C) 特許の問題があったため
- D) 無線LANに移行したため

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。スイッチングハブの普及により、各ポートが独立した衝突ドメインとなり、全二重通信が可能になったため、衝突検出の仕組みが不要になりました。<br>
<br>
Aが間違いの理由：CSMA/CDは比較的シンプルな仕組み<br>
Cが間違いの理由：特許問題は主要な要因ではない<br>
Dが間違いの理由：有線LANは依然として広く使用されている<br>
<br>
【補足】現在のギガビットイーサネットでは、オートネゴシエーションにより全二重モードで動作します。
</details>

### 問題11
RTS/CTSを使用する場合の通信手順として正しいものは？

- A) RTS → データ → CTS → ACK
- B) CTS → RTS → データ → ACK
- C) RTS → CTS → データ → ACK
- D) データ → RTS → CTS → ACK

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
正解はCです。送信端末がRTS（送信要求）を送信→アクセスポイントがCTS（送信許可）で応答→データ送信→ACK（受信確認）の順序で通信が行われます。<br>
<br>
Aが間違いの理由：CTSはRTSの応答として送信される<br>
Bが間違いの理由：RTSが最初に送信される<br>
Dが間違いの理由：RTS/CTSはデータ送信前の手順<br>
<br>
【補足】RTS/CTSには送信予定時間（Duration）が含まれ、周囲のノードはこの時間NAV（Network Allocation Vector）を設定します。
</details>

### 問題12
CSMA/CAでコンテンションウィンドウが連続して増加し、CWmaxに達した後、送信が成功した場合の動作は？

- A) CWmaxのまま維持
- B) CWminにリセット
- C) 徐々に減少
- D) CWmax/2に設定

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
正解はBです。送信が成功すると、コンテンションウィンドウは初期値（CWmin）にリセットされます。これにより、ネットワークが空いている時は小さな待機時間で効率的に動作します。<br>
<br>
Aが間違いの理由：成功後もCWmaxでは効率が悪い<br>
Cが間違いの理由：段階的な減少ではなく、即座にリセット<br>
Dが間違いの理由：半分ではなく、最小値に戻る<br>
<br>
【補足】IEEE 802.11では、CWminは通常15または31、CWmaxは1023に設定されています。
</details>

### 問題13
10BASE-Tネットワークで、最大ケーブル長100m、信号伝搬速度2×10^8 m/sの場合、スロット時間として適切な値は？

- A) 0.5μs
- B) 1μs
- C) 5.12μs
- D) 51.2μs

<details>
<summary>解答</summary>
<strong>正解: D</strong><br>
10BASE-Tの標準スロット時間は51.2μs（512ビット時間）です。これは最悪条件での往復遅延時間に十分な余裕を持たせた値です。<br>
計算：往復遅延 = 2 × 100m ÷ (2×10^8 m/s) = 1μs<br>
512ビット ÷ 10Mbps = 51.2μs<br>
<br>
Aが間違いの理由：片道遅延時間で、往復ではない<br>
Bが間違いの理由：理論上の最小往復遅延で、余裕がない<br>
Cが間違いの理由：100BASE-TXのスロット時間<br>
<br>
【補足】実際のネットワークでは、リピータやハブの遅延も考慮する必要があります。
</details>

### 問題14

- B) 222μs
- C) 278μs
- D) 1500μs

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
送信時間 = フレームサイズ ÷ 伝送速度<br>
= (1500バイト × 8ビット) ÷ 54Mbps<br>
= 12,000ビット ÷ 54×10^6 bps<br>
= 222μs<br>
<br>
Aが間違いの理由：DIFSの時間と混同<br>
Cが間違いの理由：計算誤り<br>
Dが間違いの理由：バイト数をそのまま時間としている<br>
<br>
【補足】実際の送信では、これにPHYヘッダ、IFS、ACK待機時間等が加わります。
</details>

### 問題15

- B) 仮想的キャリアセンスのみ

### 問題16

## 9. 専門用語集

このスライドで使用された技術用語について、アルファベット順・50音順で解説します。

### アルファベット

**ACK (Acknowledgment)**
- **読み方**: アック、アクノリッジメント
- **意味**: データフレームを正常に受信したことを送信元に通知する確認応答フレーム。CSMA/CAでは、データ受信後SIFS時間待機してACKを返信する。
- **関連用語**: NAK、SIFS、フレーム

**AP (Access Point)**
- **読み方**: エーピー、アクセスポイント
- **意味**: 無線LANにおいて、無線端末と有線ネットワークを中継する機器。複数の無線端末からの通信を調整する役割も持つ。
- **関連用語**: 無線LAN、SSID、ビーコン

**CCA (Clear Channel Assessment)**
- **読み方**: シーシーエー
- **意味**: チャネルが使用中かどうかを判断する機能。物理層で信号強度を測定し、閾値以上の信号を検出した場合はチャネルビジーと判断する。
- **関連用語**: キャリアセンス、ED、閾値

**CSMA/CA (Carrier Sense Multiple Access with Collision Avoidance)**
- **読み方**: シーエスエムエー・シーエー
- **意味**: 搬送波感知多重アクセス/衝突回避方式。主に無線LANで使用される媒体アクセス制御方式で、事前の待機により衝突を回避する。
- **関連用語**: IEEE 802.11、Wi-Fi、IFS

**CSMA/CD (Carrier Sense Multiple Access with Collision Detection)**
- **読み方**: シーエスエムエー・シーディー
- **意味**: 搬送波感知多重アクセス/衝突検出方式。主に有線イーサネットで使用される媒体アクセス制御方式で、衝突を検出して対処する。
- **関連用語**: イーサネット、JAM信号、半二重

**CTS (Clear To Send)**
- **読み方**: シーティーエス
- **意味**: 送信許可フレーム。RTSを受信したアクセスポイントが、送信を許可する際に返信する制御フレーム。
- **関連用語**: RTS、隠れ端末問題、NAV

**CW (Contention Window)**
- **読み方**: シーダブリュー、コンテンションウィンドウ
- **意味**: バックオフ時間を決定するためのランダム値の選択範囲。衝突や送信失敗により指数的に増加する。
- **関連用語**: バックオフ、CWmin、CWmax

**DCF (Distributed Coordination Function)**
- **読み方**: ディーシーエフ
- **意味**: IEEE 802.11の基本的なアクセス方式。各端末が自律分散的にチャネルアクセスを制御する。
- **関連用語**: PCF、EDCA、コンテンション

**DIFS (DCF Inter Frame Space)**
- **読み方**: ディフス
- **意味**: 通常のデータフレーム送信前に待機する時間。SIFS + 2スロット時間で定義される。
- **関連用語**: SIFS、PIFS、EIFS、IFS

**ED (Energy Detect)**
- **読み方**: イーディー、エナジーディテクト
- **意味**: 受信信号の電力レベルを測定してチャネルの使用状況を判断する方式。Wi-Fiフレーム以外の信号も検出可能。
- **関連用語**: CCA、閾値、キャリアセンス

**EDCA (Enhanced Distributed Channel Access)**
- **読み方**: イーディーシーエー
- **意味**: QoSをサポートする拡張DCF。音声、映像、ベストエフォート、バックグラウンドの4つのアクセスカテゴリを定義。
- **関連用語**: QoS、AC、AIFS

**EIFS (Extended Inter Frame Space)**
- **読み方**: イーアイエフエス
- **意味**: エラーフレーム受信後に使用される拡張フレーム間隔。他の端末の再送機会を確保するために長い待機時間を設定。
- **関連用語**: IFS、エラー、再送

**IEEE 802.11**
- **読み方**: アイトリプルイー・ハチマルニ・テン・イチイチ
- **意味**: 無線LANの国際標準規格。物理層とMAC層を定義し、a/b/g/n/ac/ax等の拡張規格がある。
- **関連用語**: Wi-Fi、無線LAN、標準化

**IEEE 802.3**
- **読み方**: アイトリプルイー・ハチマルニ・テン・サン
- **意味**: 有線イーサネットの国際標準規格。CSMA/CDを含む各種イーサネット技術を定義。
- **関連用語**: イーサネット、CSMA/CD、標準化

**IFS (Inter Frame Space)**
- **読み方**: アイエフエス
- **意味**: フレーム間隔。フレーム送信間に設ける待機時間で、優先制御に使用される。
- **関連用語**: SIFS、PIFS、DIFS、EIFS

**JAM信号**
- **読み方**: ジャムしんごう
- **意味**: CSMA/CDで衝突を検出した際に送信される特殊な信号パターン。通常32ビットの0と1の交互パターン。
- **関連用語**: 衝突検出、CSMA/CD、強制衝突

**MAC (Media Access Control)**
- **読み方**: マック
- **意味**: 媒体アクセス制御。OSI参照モデルのデータリンク層の下位副層で、物理媒体へのアクセスを制御する。
- **関連用語**: データリンク層、LLC、MACアドレス

**NAV (Network Allocation Vector)**
- **読み方**: ナブ
- **意味**: 仮想的キャリアセンスで使用されるタイマー。他の端末の送信予定時間を記憶し、その間は送信を控える。
- **関連用語**: 仮想的キャリアセンス、Duration、RTS/CTS

**OFDMA (Orthogonal Frequency Division Multiple Access)**
- **読み方**: オーエフディーエムエー
- **意味**: 直交周波数分割多元接続。Wi-Fi 6で採用された技術で、周波数帯域を細分化して複数端末に同時割り当て。
- **関連用語**: Wi-Fi 6、OFDM、リソースユニット

**PCF (Point Coordination Function)**
- **読み方**: ピーシーエフ
- **意味**: アクセスポイントが集中制御する調整機能。コンテンションフリー期間を設けて優先通信を実現。
- **関連用語**: DCF、コンテンションフリー、ポーリング

**PHY (Physical Layer)**
- **読み方**: フィー、フィジカルレイヤー
- **意味**: 物理層。OSI参照モデルの第1層で、ビット列の電気信号への変換や変調を行う。
- **関連用語**: OSI参照モデル、変調、物理媒体

**PIFS (PCF Inter Frame Space)**
- **読み方**: ピフス
- **意味**: PCFモードで使用されるフレーム間隔。SIFS + 1スロット時間で、DIFSより短く優先度が高い。
- **関連用語**: PCF、IFS、優先制御

**QoS (Quality of Service)**
- **読み方**: キューオーエス
- **意味**: サービス品質。音声や映像等のリアルタイム通信に必要な帯域や遅延を保証する仕組み。
- **関連用語**: EDCA、優先制御、遅延

**RTS (Request To Send)**
- **読み方**: アールティーエス
- **意味**: 送信要求フレーム。大きなデータを送信する前に、送信許可を求めるための制御フレーム。
- **関連用語**: CTS、隠れ端末問題、閾値

**SIFS (Short Inter Frame Space)**
- **読み方**: シフス
- **意味**: 最短のフレーム間隔。最高優先度で、ACKやCTS等の制御フレームで使用。通常10μs程度。
- **関連用語**: IFS、ACK、優先度

**SSID (Service Set Identifier)**
- **読み方**: エスエスアイディー
- **意味**: 無線LANのネットワーク識別子。最大32文字の英数字で、アクセスポイントを識別する。
- **関連用語**: アクセスポイント、ビーコン、無線LAN

**Wi-Fi**
- **読み方**: ワイファイ
- **意味**: Wi-Fi Allianceが認定する無線LAN規格の総称。IEEE 802.11規格に基づく相互接続性を保証。
- **関連用語**: IEEE 802.11、無線LAN、Wi-Fi Alliance

### あ行

**アクセスポイント**
- **読み方**: あくせすぽいんと
- **意味**: 無線端末と有線ネットワークを中継する機器。インフラストラクチャモードの中心となる装置。
- **関連用語**: AP、無線LAN、インフラストラクチャモード

**隠れ端末問題（かくれたんまつもんだい）**
- **読み方**: かくれたんまつもんだい
- **意味**: 互いに電波が届かない位置にある端末が、同じアクセスポイントに同時送信して衝突する問題。
- **関連用語**: RTS/CTS、露出端末問題、CSMA/CA

**キャリアエクステンション**
- **読み方**: きゃりあえくすてんしょん
- **意味**: ギガビットイーサネットで最小フレーム長を実質的に拡張する技術。パディングを追加して512バイト相当にする。
- **関連用語**: ギガビットイーサネット、最小フレーム長、CSMA/CD

**キャリアセンス**
- **読み方**: きゃりあせんす
- **意味**: 通信媒体の使用状況を確認する動作。物理的キャリアセンスと仮想的キャリアセンスがある。
- **関連用語**: CSMA、CCA、NAV

**コリジョン**
- **読み方**: こりじょん
- **意味**: 衝突。複数の端末が同時に送信することでデータが破損する現象。
- **関連用語**: 衝突検出、衝突回避、JAM信号

**コンテンション**
- **読み方**: こんてんしょん
- **意味**: 競合。複数の端末が同じリソース（通信媒体）を取り合う状態。
- **関連用語**: コンテンションウィンドウ、競合期間、バックオフ

### さ行

**再送制御（さいそうせいぎょ）**
- **読み方**: さいそうせいぎょ
- **意味**: 送信失敗時に自動的に再送信を行う仕組み。指数バックオフにより待機時間を調整。
- **関連用語**: ACK、タイムアウト、バックオフ

**スイッチングハブ**
- **読み方**: すいっちんぐはぶ
- **意味**: MACアドレスを学習してフレームを適切なポートにのみ転送するレイヤー2スイッチ。
- **関連用語**: 衝突ドメイン、全二重通信、ブリッジ

**スロット時間（すろっとじかん）**
- **読み方**: すろっとじかん
- **意味**: ネットワークの基本時間単位。CSMA/CDでは往復伝送遅延時間、CSMA/CAではバックオフの単位時間。
- **関連用語**: バックオフ、最小フレーム長、遅延

**全二重通信（ぜんにじゅうつうしん）**
- **読み方**: ぜんにじゅうつうしん
- **意味**: 送信と受信を同時に行える通信方式。スイッチングハブ接続時は衝突が発生しないため可能。
- **関連用語**: 半二重通信、スイッチングハブ、衝突

### た行

**遅延（ちえん）**
- **読み方**: ちえん
- **意味**: データが送信されてから受信されるまでの時間。伝搬遅延、処理遅延、キューイング遅延等がある。
- **関連用語**: レイテンシ、ジッタ、QoS

**衝突ドメイン（しょうとつどめいん）**
- **読み方**: しょうとつどめいん
- **意味**: 衝突が発生する可能性がある範囲。スイッチによりポート単位に分割される。
- **関連用語**: ブロードキャストドメイン、コリジョン、スイッチ

**衝突検出（しょうとつけんしゅつ）**
- **読み方**: しょうとつけんしゅつ
- **意味**: 送信中に他の信号との衝突を電気的に検出する機能。CSMA/CDの中核技術。
- **関連用語**: CSMA/CD、JAM信号、電圧レベル

**衝突回避（しょうとつかいひ）**
- **読み方**: しょうとつかいひ
- **意味**: 事前の待機時間設定により衝突を防ぐ方式。CSMA/CAの基本原理。
- **関連用語**: CSMA/CA、IFS、バックオフ

### な行

**ノード**
- **読み方**: のーど
- **意味**: ネットワークに接続された機器の総称。端末、サーバー、ルーター等を含む。
- **関連用語**: 端末、ステーション、ホスト

### は行

**バックオフ**
- **読み方**: ばっくおふ
- **意味**: 送信前または衝突後に待機する仕組み。ランダムな時間待機することで再衝突を防ぐ。
- **関連用語**: 指数バックオフ、コンテンションウィンドウ、スロット時間

**半二重通信（はんにじゅうつうしん）**
- **読み方**: はんにじゅうつうしん
- **意味**: 送信と受信を同時に行えない通信方式。無線LANや共有媒体での基本的な通信形態。
- **関連用語**: 全二重通信、シンプレックス、トランシーバー

**ビーコン**
- **読み方**: びーこん
- **意味**: アクセスポイントが定期的に送信する管理フレーム。SSIDや対応規格等の情報を含む。
- **関連用語**: SSID、管理フレーム、ビーコン間隔

**物理的キャリアセンス（ぶつりてききゃりあせんす）**
- **読み方**: ぶつりてききゃりあせんす
- **意味**: 実際の電波や電気信号を検出してチャネルの使用状況を判断する方式。
- **関連用語**: CCA、ED、仮想的キャリアセンス

**フレーム**
- **読み方**: ふれーむ
- **意味**: データリンク層でのデータ伝送単位。ヘッダ、ペイロード、トレーラで構成される。
- **関連用語**: パケット、セグメント、MTU

**フレームアグリゲーション**
- **読み方**: ふれーむあぐりげーしょん
- **意味**: 複数の小さなフレームを1つの大きなフレームにまとめて送信する技術。オーバーヘッドを削減。
- **関連用語**: A-MPDU、A-MSDU、効率化

**ブロードキャスト**
- **読み方**: ぶろーどきゃすと
- **意味**: ネットワーク内の全端末に同時送信する通信方式。MACアドレスはFF:FF:FF:FF:FF:FF。
- **関連用語**: マルチキャスト、ユニキャスト、ブロードキャストストーム

### ま行

**マルチパス**
- **読み方**: まるちぱす
- **意味**: 電波が反射や回折により複数の経路で到達する現象。無線通信の品質に影響を与える。
- **関連用語**: フェージング、MIMO、ダイバーシティ

**無線LAN（むせんらん）**
- **読み方**: むせんらん
- **意味**: 無線通信を使用するローカルエリアネットワーク。主にIEEE 802.11規格に基づく。
- **関連用語**: Wi-Fi、アクセスポイント、CSMA/CA

### や行

**優先制御（ゆうせんせいぎょ）**
- **読み方**: ゆうせんせいぎょ
- **意味**: 重要な通信を優先的に処理する仕組み。IFSの長さやアクセスカテゴリで実現。
- **関連用語**: QoS、EDCA、IFS

### ら行

**ランダムアクセス**
- **読み方**: らんだむあくせす
- **意味**: 各端末が自律的にチャネルアクセスのタイミングを決める方式。CSMAはその代表例。
- **関連用語**: CSMA、ALOHA、媒体アクセス制御

**レイテンシ**
- **読み方**: れいてんし
- **意味**: 遅延時間。データ送信から受信までの時間や、要求から応答までの時間を指す。
- **関連用語**: 遅延、ジッタ、RTT

**露出端末問題（ろしゅつたんまつもんだい）**
- **読み方**: ろしゅつたんまつもんだい
- **意味**: 実際には干渉しないのに、キャリアセンスにより送信を控えてしまう問題。
- **関連用語**: 隠れ端末問題、空間再利用、キャリアセンス

### わ行

**ワイヤレス**
- **読み方**: わいやれす
- **意味**: 無線の。ケーブルを使用しない通信方式全般を指す。
- **関連用語**: 無線、有線、電波
