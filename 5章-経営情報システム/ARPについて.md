# ARP（Address Resolution Protocol）について

## 概要
ARP（Address Resolution Protocol）は、TCP/IPネットワークにおいて、IPアドレスからMACアドレス（物理アドレス）を取得するためのプロトコルです。OSI参照モデルのレイヤ2（データリンク層）とレイヤ3（ネットワーク層）の間で動作し、同一ネットワークセグメント内での通信を可能にする重要な役割を果たしています。ネットワーク通信において、IPアドレスだけでは実際のデータ送信ができないため、ARPによるアドレス解決が不可欠となっています。

## 1. 基本概念・仕組み

### ARPの必要性
- **定義**: ネットワーク層のIPアドレスとデータリンク層のMACアドレスを対応付けるプロトコル
- **動作原理**: ブロードキャストによる問い合わせと、ユニキャストによる応答
- **特徴**: 
  - 同一ネットワークセグメント内でのみ動作
  - キャッシュ機構により効率化
  - IPv4環境で主に使用（IPv6ではNDPを使用）

### 関連技術との関係
- **従来技術との違い**: 静的なアドレステーブルと異なり、動的にアドレスを解決
- **改善点**: 自動的なアドレス解決により、ネットワーク管理の負担を軽減
- **限界**: 
  - セキュリティ脆弱性（ARPスプーフィング）
  - ブロードキャストトラフィックの増加
  - ルーターを越えたアドレス解決は不可

## 2. ARPの種類・分類

### プロトコルの分類
ARPには用途に応じて複数の種類が存在し、それぞれ異なる機能を提供します。

### 通常のARP（Standard ARP）
**特徴:**
- 最も一般的なARP実装
- IPアドレスからMACアドレスを解決
- リクエスト・リプライの2つのメッセージタイプ

**動作手順:**
```
1. ARP Request（ブロードキャスト）
   送信元: 192.168.1.10 (MAC: AA:BB:CC:DD:EE:FF)
   宛先: Who has 192.168.1.20? Tell 192.168.1.10

2. ARP Reply（ユニキャスト）
   送信元: 192.168.1.20 (MAC: 11:22:33:44:55:66)
   宛先: 192.168.1.20 is at 11:22:33:44:55:66
```

**📊 具体的な計算例**
**例: ARPキャッシュタイムアウトの計算**
- デフォルトタイムアウト: 20分（1200秒）
- 更新間隔: 60秒

**ステップ1: キャッシュ有効期間の計算**
```
残り有効時間 = タイムアウト値 - 経過時間
残り有効時間 = 1200秒 - 300秒 = 900秒
```

**ステップ2: 更新タイミングの判定**
```
更新閾値 = タイムアウト値 × 0.5 = 600秒
300秒 < 600秒 → まだ更新不要
```

**結果: ARPエントリは引き続き有効**

💡 **実際の現場では**: キャッシュタイムアウトは環境に応じて調整され、高可用性が求められる環境では短く設定されることがあります。

### RARP（Reverse ARP）
**特徴:**
- MACアドレスからIPアドレスを解決
- ディスクレスワークステーションで使用
- 現在はDHCPに置き換えられている

**動作原理:**
```
1. RARP Request: "私のMACアドレスは XX:XX:XX:XX:XX:XX です。IPアドレスを教えてください"
2. RARP Reply: "あなたのIPアドレスは 192.168.1.100 です"
```

### Proxy ARP
**特徴:**
- ルーターが他のホストの代わりにARP応答
- サブネット間の透過的な通信を実現
- セキュリティリスクがあるため慎重な設定が必要

**適用シナリオ:**
- 異なるサブネット間でルーティングなしで通信したい場合
- レガシーシステムのサポート
- ネットワーク移行期の一時的な対策

### Gratuitous ARP
**特徴:**
- 自分自身のIPアドレスに対するARP要求
- IPアドレスの重複検出
- ARPキャッシュの更新通知

**使用目的:**
```
1. IPアドレス重複検出
   - 送信: ARP Request (Who has 192.168.1.10? Tell 192.168.1.10)
   - 応答があれば重複と判定

2. ARPキャッシュ更新
   - NICやIPアドレス変更時に送信
   - 他のホストのARPキャッシュを更新
```

## 3. 詳細仕様・パラメータ

### ARPパケットフォーマット
#### ハードウェアタイプ（2バイト）
- **意味**: 使用するハードウェアの種類
- **設定範囲**: 0x0001（Ethernet）が一般的
- **影響**: データリンク層のプロトコルを決定
- **推奨値**: 0x0001

#### プロトコルタイプ（2バイト）
- **意味**: 上位プロトコルの種類
- **設定範囲**: 0x0800（IPv4）が標準
- **影響**: アドレス解決の対象プロトコルを指定
- **推奨値**: 0x0800

#### オペレーションコード（2バイト）
- **意味**: ARPメッセージの種類
- **設定範囲**: 
  - 1: ARP Request
  - 2: ARP Reply
  - 3: RARP Request
  - 4: RARP Reply
- **影響**: 処理の流れを決定
- **推奨値**: 用途に応じて選択

#### アドレス長（各1バイト）
- **ハードウェアアドレス長**: 通常6（MACアドレス）
- **プロトコルアドレス長**: 通常4（IPv4アドレス）

## 4. 実装例・適用事例

### 基本実装（Python）
```python
import socket
import struct
import binascii

def create_arp_request(src_mac, src_ip, dst_ip):
    """ARP要求パケットを作成"""
    # イーサネットヘッダー
    dst_mac = b'\xff\xff\xff\xff\xff\xff'  # ブロードキャスト
    eth_type = b'\x08\x06'  # ARP
    
    # ARPヘッダー
    hw_type = struct.pack('!H', 1)  # Ethernet
    proto_type = struct.pack('!H', 0x0800)  # IPv4
    hw_len = struct.pack('!B', 6)  # MACアドレス長
    proto_len = struct.pack('!B', 4)  # IPアドレス長
    opcode = struct.pack('!H', 1)  # ARP Request
    
    # アドレス部分
    src_mac_bytes = binascii.unhexlify(src_mac.replace(':', ''))
    src_ip_bytes = socket.inet_aton(src_ip)
    dst_mac_bytes = b'\x00\x00\x00\x00\x00\x00'
    dst_ip_bytes = socket.inet_aton(dst_ip)
    
    # パケット組み立て
    arp_packet = (
        dst_mac + src_mac_bytes + eth_type +
        hw_type + proto_type + hw_len + proto_len + opcode +
        src_mac_bytes + src_ip_bytes + dst_mac_bytes + dst_ip_bytes
    )
    
    return arp_packet

# 使用例
packet = create_arp_request('aa:bb:cc:dd:ee:ff', '192.168.1.10', '192.168.1.20')
```

### 応用実装（ARPキャッシュ管理）
```python
import time
import threading

class ARPCache:
    def __init__(self, timeout=1200):  # デフォルト20分
        self.cache = {}
        self.timeout = timeout
        self.lock = threading.Lock()
        
        # バックグラウンドでクリーンアップ
        self.cleanup_thread = threading.Thread(target=self._cleanup_expired)
        self.cleanup_thread.daemon = True
        self.cleanup_thread.start()
    
    def add_entry(self, ip_address, mac_address):
        """ARPエントリを追加"""
        with self.lock:
            self.cache[ip_address] = {
                'mac': mac_address,
                'timestamp': time.time(),
                'static': False
            }
    
    def get_mac(self, ip_address):
        """IPアドレスからMACアドレスを取得"""
        with self.lock:
            entry = self.cache.get(ip_address)
            if entry:
                # タイムアウトチェック
                if not entry['static'] and time.time() - entry['timestamp'] > self.timeout:
                    del self.cache[ip_address]
                    return None
                return entry['mac']
            return None
    
    def add_static_entry(self, ip_address, mac_address):
        """静的ARPエントリを追加"""
        with self.lock:
            self.cache[ip_address] = {
                'mac': mac_address,
                'timestamp': time.time(),
                'static': True
            }
    
    def _cleanup_expired(self):
        """期限切れエントリをクリーンアップ"""
        while True:
            time.sleep(60)  # 1分ごとにチェック
            with self.lock:
                expired_ips = []
                for ip, entry in self.cache.items():
                    if not entry['static'] and time.time() - entry['timestamp'] > self.timeout:
                        expired_ips.append(ip)
                
                for ip in expired_ips:
                    del self.cache[ip]

# 使用例
arp_cache = ARPCache()
arp_cache.add_entry('192.168.1.20', '11:22:33:44:55:66')
arp_cache.add_static_entry('192.168.1.1', 'aa:bb:cc:dd:ee:ff')  # ゲートウェイ

# MACアドレス取得
mac = arp_cache.get_mac('192.168.1.20')
print(f"MAC address: {mac}")
```

### 実際の適用事例

#### 事例1: 大規模データセンターでのARP最適化
- **課題**: 数千台のサーバー間でARPブロードキャストストームが発生
- **適用方法**: 
  - Proxy ARPの無効化
  - 静的ARPエントリの活用
  - ARPキャッシュタイムアウトの延長（20分→2時間）
- **結果**: ブロードキャストトラフィックが80%削減
- **効果**: ネットワーク全体のパフォーマンスが向上

#### 事例2: セキュリティ強化のためのDAI実装
- **課題**: ARPスプーフィング攻撃への対策が必要
- **適用方法**: 
  - Dynamic ARP Inspection（DAI）の導入
  - DHCPスヌーピングとの連携
  - 信頼できるポートの設定
- **結果**: ARP関連のセキュリティインシデントがゼロに
- **効果**: ネットワークの信頼性が大幅に向上

## 5. メリット・デメリット

### メリット
**1. 自動的なアドレス解決**
- **理由**: 手動設定が不要で、動的にMACアドレスを取得
- **効果**: ネットワーク管理の負担を大幅に軽減
- **具体例**: 新しいデバイスをネットワークに接続するだけで通信可能

**2. キャッシュによる効率化**
- **理由**: 一度解決したアドレスをキャッシュに保存
- **効果**: ネットワークトラフィックの削減
- **具体例**: 20分間のキャッシュで、頻繁な通信先へのARP要求を99%削減

**3. シンプルな実装**
- **理由**: プロトコル自体が単純で理解しやすい
- **効果**: トラブルシューティングが容易
- **具体例**: パケットキャプチャで問題を素早く特定可能

### デメリット
**1. セキュリティの脆弱性**
- **理由**: 認証機構がなく、なりすましが可能
- **影響**: ARPスプーフィングによる中間者攻撃のリスク
- **対策**: DAI、静的ARPエントリ、ARPWatchの導入

**2. ブロードキャストトラフィック**
- **理由**: ARP要求はブロードキャストで送信
- **影響**: 大規模ネットワークでは帯域を圧迫
- **対策**: VLANによるブロードキャストドメインの分割

**3. スケーラビリティの限界**
- **理由**: 同一ネットワークセグメント内でのみ動作
- **影響**: 大規模ネットワークでは設計が複雑化
- **対策**: 適切なサブネット設計とルーティングの活用

## 6. 選択・導入の指針

### ARP実装方式の選択基準
| 観点 | 通常のARP | Proxy ARP | 静的ARP | DAI |
|------|-----------|-----------|---------|-----|
| セキュリティ | △ | × | ◎ | ◎ |
| 管理の容易さ | ◎ | ○ | × | △ |
| スケーラビリティ | ○ | △ | × | ○ |
| パフォーマンス | ○ | △ | ◎ | ○ |

### 適用判断フローチャート
1. **セキュリティが最優先か？** 
   - Yes → DAIまたは静的ARPを検討
   - No → 次の判断へ

2. **ネットワーク規模は大きいか？**
   - Yes → VLANによる分割とProxy ARPの無効化
   - No → 通常のARPで問題なし

3. **特殊な要件があるか？**
   - レガシーシステム対応 → Proxy ARPを検討
   - 高可用性要求 → Gratuitous ARPの活用

<summary>解答</summary>

RARPが現在ほとんど使用されない理由として最も適切なものは？

Aが間違いの理由：セキュリティはRARPが使われなくなった主要因ではない<br>
Cが間違いの理由：パフォーマンスの問題はない<br>
Dが間違いの理由：IPv6登場以前からRARPは使われなくなっていた<br>
<br>
【補足】DHCPはIPアドレス、サブネットマスク、デフォルトゲートウェイ、DNSサーバーなど包括的な設定が可能です。

### 問題11

- B) セキュリティとパフォーマンスの向上のため

<summary>解答</summary>

Dが間違いの理由：ARPはIPv4専用でIPv6では使用されない<br>

### 問題13
ARPキャッシュポイズニング攻撃の典型的な手法は？

- D) ARPプロトコルを無効化する

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>

Aが間違いの理由：これはDoS攻撃の一種だが、キャッシュポイズニングではない<br>

Dが間違いの理由：プロトコルの無効化は攻撃手法ではない<br>

【補足】この攻撃により、攻撃者は中間者攻撃（MITM）を実行できるようになります。

- B) ランダムにエントリを削除

【補足】静的エントリは保護され、動的エントリのみがLRUの対象となります。
</details>

## 9. 専門用語集

このスライドで使用された技術用語について、アルファベット順・50音順で解説します。

### アルファベット

**ARP (Address Resolution Protocol)**
- **読み方**: エーアールピー
- **意味**: IPアドレスからMACアドレスを取得するためのプロトコル。OSI参照モデルのレイヤ2とレイヤ3の間で動作し、同一ネットワークセグメント内での通信を可能にする。
- **関連用語**: RARP、NDP、MAC アドレス

**DAI (Dynamic ARP Inspection)**
- **読み方**: ディーエーアイ
- **意味**: ARPパケットを検査し、不正なARP応答を防ぐセキュリティ機能。DHCPスヌーピングと連携して動作し、信頼できるARP応答のみを許可する。
- **関連用語**: DHCPスヌーピング、ARPスプーフィング

**DHCP (Dynamic Host Configuration Protocol)**
- **読み方**: ディーエイチシーピー
- **意味**: ネットワーク機器に対してIPアドレスなどの設定情報を自動的に割り当てるプロトコル。RARPの後継として広く使用されている。
- **関連用語**: RARP、IPアドレス、サブネットマスク

**Gratuitous ARP**
- **読み方**: グラチュイタス・エーアールピー
- **意味**: 自分自身のIPアドレスに対するARP要求。IPアドレスの重複検出やARPキャッシュの更新通知に使用される。
- **関連用語**: ARP、重複検出、キャッシュ更新

**MITM (Man-In-The-Middle)**
- **読み方**: エムアイティーエム、マン・イン・ザ・ミドル
- **意味**: 通信の間に攻撃者が介入し、通信内容を盗聴・改ざんする攻撃手法。ARPスプーフィングによって実現されることがある。
- **関連用語**: ARPスプーフィング、セキュリティ攻撃

**NDP (Neighbor Discovery Protocol)**
- **読み方**: エヌディーピー
- **意味**: IPv6において、ARPの役割を果たすプロトコル。ICMPv6を使用してアドレス解決を行う。
- **関連用語**: IPv6、ICMPv6、ARP

**Proxy ARP**
- **読み方**: プロキシ・エーアールピー
- **意味**: ルーターが他のホストの代わりにARP応答を行う機能。異なるサブネット間の透過的な通信を実現するが、セキュリティリスクがある。
- **関連用語**: ARP、ルーター、サブネット

**RARP (Reverse ARP)**
- **読み方**: アールエーアールピー、リバース・エーアールピー
- **意味**: MACアドレスからIPアドレスを取得するプロトコル。現在はDHCPに置き換えられている。
- **関連用語**: ARP、DHCP、MACアドレス

**SDN (Software Defined Networking)**
- **読み方**: エスディーエヌ
- **意味**: ネットワークの制御機能をソフトウェアで実現する技術。ARPの処理を集中管理することで効率化を図れる。
- **関連用語**: OpenFlow、ネットワーク仮想化

**VLAN (Virtual LAN)**
- **読み方**: ブイラン
- **意味**: 物理的な接続に依存せず、論理的にネットワークを分割する技術。ブロードキャストドメインを分割してARPトラフィックを削減できる。
- **関連用語**: ブロードキャストドメイン、ネットワーク分割

### あ行

**アドレス解決**
- **読み方**: あどれすかいけつ
- **意味**: あるレイヤのアドレスから別のレイヤのアドレスを取得すること。ARPではIPアドレスからMACアドレスを解決する。
- **関連用語**: ARP、IPアドレス、MACアドレス

**エニーキャスト**
- **読み方**: えにーきゃすと
- **意味**: 複数の宛先のうち、最も近い（または最適な）1つに配送する通信方式。ARPでは使用されない。
- **関連用語**: ユニキャスト、ブロードキャスト、マルチキャスト

**オペレーションコード**
- **読み方**: おぺれーしょんこーど
- **意味**: ARPパケット内で、メッセージの種類（Request/Reply）を示す2バイトのフィールド。
- **関連用語**: ARPパケット、Request、Reply

### か行

**キャッシュ**
- **読み方**: きゃっしゅ
- **意味**: 一度解決したアドレス情報を一時的に保存する仕組み。ARPキャッシュにより、繰り返しのARP要求を削減できる。
- **関連用語**: ARPキャッシュ、タイムアウト

**キャッシュポイズニング**
- **読み方**: きゃっしゅぽいずにんぐ
- **意味**: ARPキャッシュに偽の情報を注入する攻撃手法。中間者攻撃の準備として使用される。
- **関連用語**: ARPスプーフィング、セキュリティ攻撃

### さ行

**サブネット**
- **読み方**: さぶねっと
- **意味**: 大きなネットワークを論理的に分割した小さなネットワーク。ARPは同一サブネット内でのみ動作する。
- **関連用語**: ネットワーク、IPアドレス、サブネットマスク

**静的ARP**
- **読み方**: せいてきえーあーるぴー
- **意味**: 手動で設定された固定のARPエントリ。セキュリティ向上とパフォーマンス改善に寄与する。
- **関連用語**: 動的ARP、ARPキャッシュ

### た行

**タイムアウト**
- **読み方**: たいむあうと
- **意味**: ARPキャッシュエントリが有効である時間。通常は20分に設定される。
- **関連用語**: ARPキャッシュ、キャッシュ管理

### な行

**なりすまし**
- **読み方**: なりすまし
- **意味**: 他のホストになりすまして通信を行う攻撃。ARPスプーフィングによって実現される。
- **関連用語**: ARPスプーフィング、セキュリティ攻撃

### は行

**ハードウェアアドレス**
- **読み方**: はーどうぇああどれす
- **意味**: MACアドレスの別名。ネットワークインターフェースカードに固有の物理アドレス。
- **関連用語**: MACアドレス、物理アドレス

**ブロードキャスト**
- **読み方**: ぶろーどきゃすと
- **意味**: 同一ネットワーク内のすべてのホストに同時に送信する通信方式。ARP要求で使用される。
- **関連用語**: ユニキャスト、マルチキャスト

**ブロードキャストストーム**
- **読み方**: ぶろーどきゃすとすとーむ
- **意味**: ブロードキャストパケットが大量に発生し、ネットワークが飽和する現象。
- **関連用語**: ネットワークループ、STP

### ま行

**マルチキャスト**
- **読み方**: まるちきゃすと
- **意味**: 特定のグループに属する複数のホストに送信する通信方式。IPv6のNDPで使用される。
- **関連用語**: ユニキャスト、ブロードキャスト

### や行

**ユニキャスト**
- **読み方**: ゆにきゃすと
- **意味**: 特定の1つのホストに送信する通信方式。ARP応答で使用される。
- **関連用語**: ブロードキャスト、マルチキャスト

### ら行

**レイヤ2（データリンク層）**
- **読み方**: れいやつー
- **意味**: OSI参照モデルの第2層。MACアドレスを使用して同一ネットワーク内の通信を行う。
- **関連用語**: OSI参照モデル、MACアドレス

**レイヤ3（ネットワーク層）**
- **読み方**: れいやすりー
- **意味**: OSI参照モデルの第3層。IPアドレスを使用してネットワーク間の通信を行う。
- **関連用語**: OSI参照モデル、IPアドレス
