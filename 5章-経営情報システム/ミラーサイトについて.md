# ミラーサイトについて

## 概要

ミラーサイトとは、元となるウェブサイト（オリジナルサイト）のコンテンツを複製し、別のサーバーやドメインで公開されるサイトのことです。主に負荷分散、アクセス速度の向上、可用性の確保、地理的な制約の解消などを目的として運用されます。近年では、CDN（Content Delivery Network）技術の発展により、より高度で効率的なミラーリングが可能となっています。

## 1. 基本概念・仕組み

### ミラーサイトの定義
- **定義**: オリジナルサイトの完全または部分的な複製を別の場所で提供するシステム
- **動作原理**: データの同期により、複数の地点から同一コンテンツを配信
- **特徴**: 冗長性、負荷分散、地理的分散、高可用性

### オリジナルサイトとの関係
- **従来のホスティングとの違い**: 単一サーバーではなく、複数サーバーでの分散配信
- **改善点**: レスポンス時間の短縮、耐障害性の向上、帯域幅の効率的利用
- **限界**: 同期の遅延、コスト増加、管理の複雑化

## 2. 種類・分類

### 分類軸
ミラーサイトは、同期方式、コンテンツ範囲、運用目的により分類されます。

### プッシュ型ミラーサイト
**特徴:**
- マスターサーバーから能動的にデータを配信
- リアルタイムに近い同期が可能
- 帯域幅の効率的な利用

**同期方法:**
```
rsync -avz --delete /var/www/html/ mirror-server:/var/www/html/
```

**📊 具体的な計算例**
**例: 100GBのデータを日次で同期する場合**
- 初回同期時間: 100GB ÷ 100Mbps = 約2.2時間
- 差分同期（10%変更）: 10GB ÷ 100Mbps = 約13分

**ステップ1: 初回フルバックアップ**
```
rsync -avz /source/ user@mirror:/destination/
転送データ量: 100GB
所要時間: 2.2時間
```

**ステップ2: 日次差分同期**
```
rsync -avz --delete /source/ user@mirror:/destination/
転送データ量: 10GB（変更分のみ）
所要時間: 13分
```

**結果: 効率的な帯域幅利用と短時間での同期を実現**

💡 **実際の現場では**: cronジョブで自動化し、営業時間外に同期を実行することが一般的です。

### プル型ミラーサイト
**特徴:**
- ミラーサーバーが定期的にマスターからデータを取得
- ミラーサイト側で同期タイミングを制御
- 分散管理が容易

**同期方法:**
```bash
#!/bin/bash
# ミラーサイト側で実行するスクリプト
wget -m -np -nH --cut-dirs=1 https://master-site.com/
```

**📊 具体的な計算例**
**例: 世界5拠点でのプル型ミラーリング**
- 各拠点の同期間隔: 6時間
- マスターサーバーの負荷: 平均20リクエスト/時

**負荷分散効果:**
```
通常時: 1000アクセス/時 → 200アクセス/時×5拠点
ピーク時: 5000アクセス/時 → 1000アクセス/時×5拠点
```

### リアルタイムミラーサイト
**特徴:**
- データベースレプリケーション技術を使用
- ほぼゼロ遅延での同期
- 高い一貫性の維持

**実装技術:**
```sql
-- MySQLレプリケーション設定例
CHANGE MASTER TO
  MASTER_HOST='master.example.com',
  MASTER_USER='replication',
  MASTER_PASSWORD='password',
  MASTER_LOG_FILE='mysql-bin.000001',
  MASTER_LOG_POS=0;
```

## 3. 詳細仕様・パラメータ

### 重要なパラメータ群

#### 同期間隔の詳細
- **意味**: データ同期を実行する頻度
- **設定範囲**: 1分〜24時間（一般的には15分〜6時間）
- **影響**: 短い間隔は最新性向上、長い間隔は負荷軽減
- **推奨値**: トラフィック量と更新頻度により決定

#### 帯域幅制限の詳細
- **意味**: 同期時に使用する最大帯域幅
- **設定範囲**: 1Mbps〜無制限
- **影響**: ネットワークの他のサービスへの影響を制御
- **推奨値**: 利用可能帯域の30-50%

#### キャッシュ有効期限の詳細
- **意味**: ミラーサイトでコンテンツを保持する期間
- **設定範囲**: 1分〜30日
- **影響**: 短期間は最新性確保、長期間は負荷軽減
- **推奨値**: 静的コンテンツ7日、動的コンテンツ1時間

## 4. 実装例・適用事例

### 基本実装
```bash
#!/bin/bash
# 基本的なミラーサイト同期スクリプト

# 設定
SOURCE_DIR="/var/www/original/"
MIRROR_DIR="/var/www/mirror/"
LOG_FILE="/var/log/mirror_sync.log"

# 同期実行
echo "$(date): 同期開始" >> $LOG_FILE
rsync -avz --delete $SOURCE_DIR $MIRROR_DIR >> $LOG_FILE 2>&1
echo "$(date): 同期完了" >> $LOG_FILE
```

### 応用実装
```python
# 高度なミラーサイト管理システム
import subprocess
import time
import logging
from datetime import datetime

class MirrorSiteManager:
    def __init__(self, source, destinations):
        self.source = source
        self.destinations = destinations
        self.setup_logging()
    
    def setup_logging(self):
        logging.basicConfig(
            filename='mirror_sync.log',
            level=logging.INFO,
            format='%(asctime)s - %(levelname)s - %(message)s'
        )
    
    def sync_to_mirror(self, destination):
        """特定のミラーサイトへの同期"""
        cmd = [
            'rsync', '-avz', '--delete',
            '--bwlimit=5000',  # 5MB/s制限
            self.source,
            destination
        ]
        
        try:
            start_time = time.time()
            result = subprocess.run(cmd, capture_output=True, text=True)
            elapsed_time = time.time() - start_time
            
            if result.returncode == 0:
                logging.info(f"同期成功: {destination} ({elapsed_time:.2f}秒)")
                return True
            else:
                logging.error(f"同期失敗: {destination} - {result.stderr}")
                return False
        except Exception as e:
            logging.error(f"例外発生: {destination} - {str(e)}")
            return False
    
    def sync_all(self):
        """全ミラーサイトへの同期"""
        results = {}
        for dest in self.destinations:
            results[dest] = self.sync_to_mirror(dest)
        return results

# 使用例
manager = MirrorSiteManager(
    source="/var/www/main/",
    destinations=[
        "mirror1.example.com:/var/www/",
        "mirror2.example.com:/var/www/",
        "mirror3.example.com:/var/www/"
    ]
)

# 定期実行
while True:
    results = manager.sync_all()
    time.sleep(3600)  # 1時間ごとに同期
```

## 5. メリット・デメリット

### メリット

**1. 負荷分散**
- **理由**: アクセスを複数サーバーに分散
- **効果**: サーバー負荷50-80%削減
- **具体例**: 1サーバー1000req/s → 5サーバー各200req/s

**2. 高可用性**
- **理由**: 単一障害点の排除
- **効果**: 稼働率99.9%以上の実現
- **具体例**: メインサーバー障害時も他のミラーで継続運用

**3. アクセス速度向上**
- **理由**: 地理的に近いサーバーからの配信
- **効果**: レイテンシ50-90%削減
- **具体例**: 東京→NY 200ms → 東京→東京 10ms

### デメリット

**1. 同期の遅延**
- **理由**: データ転送と処理に時間が必要
- **影響**: リアルタイム性が求められるサービスでは問題
- **対策**: リアルタイム同期技術の採用、重要データの優先同期

**2. コスト増加**
- **理由**: 複数サーバーの運用・管理費用
- **影響**: 初期投資および運用コストが2-5倍
- **対策**: クラウドサービスの活用、段階的な導入

**3. 管理の複雑化**
- **理由**: 複数システムの監視・メンテナンス
- **影響**: 運用チームの負担増加
- **対策**: 自動化ツールの導入、統合管理システムの構築

## 9. 専門用語集

このドキュメントで使用された技術用語について、アルファベット順・50音順で解説します。

### アルファベット

**CDN (Content Delivery Network)**
- **読み方**: シーディーエヌ
- **意味**: コンテンツを地理的に分散したサーバーにキャッシュし、ユーザーに最も近いサーバーから配信する仕組み
- **関連用語**: エッジサーバー、キャッシュサーバー、ミラーサイト

**cron**
- **読み方**: クーロン、クロン
- **意味**: Unix系OSで定期的にコマンドやスクリプトを自動実行するためのデーモンプロセス
- **関連用語**: cronジョブ、crontab、スケジューラー

**GeoDNS**
- **読み方**: ジオディーエヌエス
- **意味**: アクセス元の地理的位置に基づいてDNS応答を変更し、最適なサーバーに誘導する技術
- **関連用語**: DNS、ロードバランサー、地理的負荷分散

**IPFS (InterPlanetary File System)**
- **読み方**: アイピーエフエス
- **意味**: 分散型のファイルシステムで、P2P技術を使用してデータを分散保存・共有する仕組み
- **関連用語**: 分散ストレージ、P2P、ブロックチェーン

**rsync**
- **読み方**: アールシンク
- **意味**: ファイルやディレクトリを効率的に同期するためのUnixユーティリティ。差分転送により高速
- **関連用語**: 同期、バックアップ、ミラーリング

**wget**
- **読み方**: ダブリューゲット
- **意味**: WebサーバーからファイルをダウンロードするためのコマンドラインツールHTTP、HTTPS、FTPに対応
- **関連用語**: curl、HTTP、ダウンロード

### あ行

**エッジコンピューティング**
- **読み方**: えっじこんぴゅーてぃんぐ
- **意味**: データ処理をクラウドではなく、データ発生源に近い場所（エッジ）で行う分散コンピューティング手法
- **関連用語**: クラウドコンピューティング、IoT、分散処理

**エッジサーバー**
- **読み方**: えっじさーばー
- **意味**: ネットワークの端（エッジ）に配置され、ユーザーに近い位置でコンテンツを配信するサーバー
- **関連用語**: CDN、キャッシュサーバー、ミラーサイト

### か行

**可用性（Availability）**
- **読み方**: かようせい
- **意味**: システムが正常に稼働し続ける能力。通常は稼働率（%）で表現される
- **関連用語**: 稼働率、SLA、冗長性

**キャッシュ**
- **読み方**: きゃっしゅ
- **意味**: 頻繁にアクセスされるデータを高速な記憶装置に一時的に保存する仕組み
- **関連用語**: キャッシュサーバー、TTL、有効期限

**クラスタリング**
- **読み方**: くらすたりんぐ
- **意味**: 複数のコンピュータを連携させて一つのシステムとして動作させる技術
- **関連用語**: 負荷分散、高可用性、フェイルオーバー

### さ行

**冗長性（Redundancy）**
- **読み方**: じょうちょうせい
- **意味**: システムの信頼性向上のため、同じ機能を持つ要素を複数用意すること
- **関連用語**: バックアップ、フェイルオーバー、可用性

**スケーラビリティ**
- **読み方**: すけーらびりてぃ
- **意味**: システムの規模や負荷の変化に対して、柔軟に対応できる能力
- **関連用語**: 拡張性、負荷分散、クラスタリング

**同期（Synchronization）**
- **読み方**: どうき
- **意味**: 複数のシステム間でデータの一貫性を保つように更新を行うこと
- **関連用語**: レプリケーション、ミラーリング、一貫性

### た行

**帯域幅（Bandwidth）**
- **読み方**: たいいきはば
- **意味**: ネットワークで単位時間あたりに転送できるデータ量。通常bpsで表現
- **関連用語**: スループット、転送速度、ネットワーク容量

**ダウンタイム**
- **読み方**: だうんたいむ
- **意味**: システムが停止して利用できない時間
- **関連用語**: 稼働率、可用性、メンテナンス

### は行

**バイナリログ**
- **読み方**: ばいなりろぐ
- **意味**: データベースへの変更操作を記録したログファイル。レプリケーションで使用
- **関連用語**: レプリケーション、トランザクションログ、MySQL

**フェイルオーバー**
- **読み方**: ふぇいるおーばー
- **意味**: システム障害時に自動的に予備システムに切り替える仕組み
- **関連用語**: 冗長性、高可用性、クラスタリング

**負荷分散（Load Balancing）**
- **読み方**: ふかぶんさん
- **意味**: 複数のサーバーにトラフィックを分配して処理能力を向上させる技術
- **関連用語**: ロードバランサー、クラスタリング、スケーラビリティ

**プロトコルオーバーヘッド**
- **読み方**: ぷろとこるおーばーへっど
- **意味**: 通信プロトコルが付加する制御情報により発生する追加的なデータ量
- **関連用語**: 転送効率、帯域幅、ペイロード

### ま行

**ミラーリング**
- **読み方**: みらーりんぐ
- **意味**: データやシステムの完全な複製を作成・維持する技術
- **関連用語**: レプリケーション、バックアップ、同期

### ら行

**レイテンシ（Latency）**
- **読み方**: れいてんし
- **意味**: データ転送における遅延時間。通常ミリ秒（ms）で表現
- **関連用語**: 応答時間、RTT、ネットワーク遅延

**レプリケーション**
- **読み方**: れぷりけーしょん
- **意味**: データベースやファイルの複製を作成し、複数の場所で同じデータを保持する技術
- **関連用語**: マスター・スレーブ、同期、ミラーリング

**ロードバランサー**
- **読み方**: ろーどばらんさー
- **意味**: 複数のサーバーへトラフィックを分配する装置またはソフトウェア
- **関連用語**: 負荷分散、トラフィック制御、可用性
