# モデリング技法について

## 概要
モデリング技法は、複雑なシステムやプロセス、データ構造を視覚的に表現し、理解しやすくするための手法群です。ソフトウェア開発、業務分析、システム設計などの分野で広く活用されており、ステークホルダー間のコミュニケーションを円滑にし、システムの設計品質を向上させる重要な役割を果たしています。本資料では、代表的な18種類のモデリング技法について、その特徴、識別キーワード、適用場面を詳しく解説します。

## 1. モデリング技法の基本概念と体系

### モデリングの本質
- **定義**: 現実世界の事象やシステムを抽象化し、図や記号を使って表現する手法
- **目的**: 複雑性の管理、コミュニケーションの向上、設計の可視化、品質の向上
- **特徴**: 標準化された記法、段階的詳細化、多視点からの表現

### モデリング技法の分類軸
- **対象による分類**: データモデリング、プロセスモデリング、振る舞いモデリング、構造モデリング
- **抽象度による分類**: 概念モデル、論理モデル、物理モデル
- **用途による分類**: 要求分析、設計、実装、保守

## 2. 各モデリング技法の詳細

### DFD (Data Flow Diagram) - データフローダイアグラム

**特徴:**
- システム内のデータの流れを表現
- プロセス、データストア、外部エンティティ、データフローの4要素で構成
- 階層的な詳細化が可能（レベル0、レベル1、レベル2...）

**識別キーワード:**
- 「データの流れ」「プロセス間のデータ」「データストア」
- 「外部エンティティ」「コンテキストダイアグラム」
- 「バブル」「データの変換」

**記法要素:**
```
○ または □ : プロセス（データの処理・変換）
→ : データフロー（データの流れ）
＝ : データストア（データの保管場所）
□ : 外部エンティティ（システム外部の要素）
```

**適用場面:**
- 業務分析の初期段階
- 既存システムの現状分析
- データ中心のシステム設計
- システム間インターフェースの設計

**📊 具体例：ECサイトの注文処理DFD**
```
[顧客] → 注文情報 → (注文受付処理) → 注文データ → ＝注文DB＝
                           ↓
                      在庫確認要求
                           ↓
                    (在庫確認処理) ← 在庫データ ← ＝在庫DB＝
```

### E-R図 (Entity-Relationship Diagram) - 実体関連図

**特徴:**
- データの静的な構造を表現
- エンティティ（実体）、アトリビュート（属性）、リレーションシップ（関連）で構成
- カーディナリティ（多重度）を明確に表現

**識別キーワード:**
- 「エンティティ」「属性」「主キー」「外部キー」
- 「1対多」「多対多」「カーディナリティ」
- 「正規化」「リレーションシップ」

**記法要素:**
```
□ : エンティティ
◇ : リレーションシップ
○ : 属性
● : 主キー属性
─ : 関連線
1, N, M : カーディナリティ
```

**適用場面:**
- データベース設計
- 概念データモデリング
- 業務で扱うデータの整理
- システム統合時のデータマッピング

**📊 具体例：図書館管理システムのE-R図**
```
[会員]──1──借りる──N──[図書]
  │                      │
  └─属性：会員ID(PK)      └─属性：図書ID(PK)
      氏名                    書名
      住所                    著者
      電話番号                ISBN
```

### UML (Unified Modeling Language) - 統一モデリング言語

UMLは14種類の図から構成される包括的なモデリング言語です。

#### 1. ユースケース図 (Use Case Diagram)

**特徴:**
- システムの機能要求を利用者視点で表現
- アクター、ユースケース、システム境界で構成
- 機能の包含関係、拡張関係を表現可能

**識別キーワード:**
- 「アクター」「ユースケース」「システム境界」
- 「<<include>>」「<<extend>>」「汎化」
- 「主アクター」「副アクター」

**適用場面:**
- 要求定義フェーズ
- システムスコープの明確化
- ステークホルダーとの合意形成

**📊 具体例：ATMシステムのユースケース図**
```
        ATMシステム
   ┌─────────────────┐
   │   [現金引出し]   │
顧客┤                 ├→銀行システム
   │ <<include>>↓    │
   │   [認証]        │
   └─────────────────┘
```

#### 2. クラス図 (Class Diagram)

**特徴:**
- システムの静的構造を表現
- クラス、属性、操作、関連で構成
- 継承、集約、コンポジションなどの関係を表現

**識別キーワード:**
- 「クラス」「属性」「メソッド」「継承」
- 「集約」「コンポジション」「多重度」
- 「抽象クラス」「インターフェース」

**適用場面:**
- オブジェクト指向設計
- データモデル設計
- APIの構造設計
- フレームワーク設計

**📊 具体例：従業員管理システムのクラス図**
```
┌──────────────┐
│   従業員      │
├──────────────┤
│-employeeId    │
│-name          │
│-salary        │
├──────────────┤
│+getSalary()   │
│+setSalary()   │
└──────────────┘
        △
        │ 継承
┌───────┴──────┐
│   正社員      │    管理職
└───────────────┘
```

#### 3. オブジェクト図 (Object Diagram)

**特徴:**
- 特定時点でのオブジェクトの状態を表現
- クラス図のインスタンスレベルの表現
- 具体的な値を持つ

**識別キーワード:**
- 「インスタンス」「オブジェクト」「具体値」
- 「スナップショット」「実行時の状態」

**適用場面:**
- 複雑な構造の例示
- テストケースの設計
- システムの動作確認

#### 4. シーケンス図 (Sequence Diagram)

**特徴:**
- オブジェクト間の時系列的な相互作用を表現
- ライフライン、メッセージ、活性区間で構成
- 条件分岐、繰り返しも表現可能

**識別キーワード:**
- 「ライフライン」「メッセージ」「同期/非同期」
- 「alt」「loop」「opt」「活性区間」
- 「戻り値」「自己呼び出し」

**適用場面:**
- 詳細設計
- API呼び出しの設計
- エラー処理の設計
- 統合テストシナリオ

**📊 具体例：ログイン処理のシーケンス図**
```
ユーザー    画面      認証サービス    DB
  │         │            │          │
  │ ログイン  │            │          │
  ├────────→│            │          │
  │         │ 認証要求     │          │
  │         ├───────────→│          │
  │         │            │ 照会      │
  │         │            ├─────────→│
  │         │            │ 結果      │
  │         │            │←─────────┤
  │         │ 認証結果     │          │
  │         │←───────────┤          │
  │ 結果表示  │            │          │
  │←────────┤            │          │
```

#### 5. コミュニケーション図 (Communication Diagram)

**特徴:**
- オブジェクト間のメッセージ交換を構造的に表現
- シーケンス図と同じ情報を異なる視点で表現
- メッセージに番号付けして順序を示す

**識別キーワード:**
- 「メッセージ番号」「オブジェクト構造」
- 「コラボレーション」「相互作用」

**適用場面:**
- オブジェクト構造の理解
- メッセージフローの概要把握

#### 6. ステートマシン図 (State Machine Diagram)

**特徴:**
- オブジェクトの状態遷移を表現
- 状態、遷移、イベント、アクションで構成
- 階層的な状態表現が可能

**識別キーワード:**
- 「状態」「遷移」「イベント」「ガード条件」
- 「初期状態」「終了状態」「複合状態」
- 「entry/exit/do」

**適用場面:**
- 状態管理が重要なオブジェクトの設計
- ワークフロー設計
- プロトコル設計
- 組込みシステム設計

**📊 具体例：注文の状態遷移**
```
[初期] → [受付済] --承認--> [処理中] --発送--> [配送中] --到着--> [完了]
             ↓                  ↓
           キャンセル         在庫なし
             ↓                  ↓
          [キャンセル]      [保留中]
```

#### 7. アクティビティ図 (Activity Diagram)

**特徴:**
- プロセスやワークフローを表現
- アクティビティ、制御フロー、判断、並行処理を表現
- スイムレーンで責任範囲を明確化

**識別キーワード:**
- 「アクティビティ」「判断ノード」「フォーク/ジョイン」
- 「スイムレーン」「開始/終了ノード」
- 「オブジェクトフロー」

**適用場面:**
- ビジネスプロセス設計
- アルゴリズムの可視化
- ユースケースの詳細化
- 並行処理の設計

#### 8. コンポーネント図 (Component Diagram)

**特徴:**
- システムの物理的な構成要素を表現
- コンポーネント、インターフェース、依存関係を表現
- 実装ビューを提供

**識別キーワード:**
- 「コンポーネント」「インターフェース」「ポート」
- 「提供/要求インターフェース」「依存関係」

**適用場面:**
- システムアーキテクチャ設計
- モジュール分割設計
- 再利用可能部品の設計

#### 9. コンポジット構造図 (Composite Structure Diagram)

**特徴:**
- クラスの内部構造を詳細に表現
- パート、ポート、コネクタで構成
- 実行時の構造を表現

**識別キーワード:**
- 「パート」「ポート」「コネクタ」
- 「コラボレーション」「内部構造」

**適用場面:**
- 複雑なクラスの内部設計
- アーキテクチャパターンの表現

#### 10. パッケージ図 (Package Diagram)

**特徴:**
- モデル要素のグループ化と依存関係を表現
- 名前空間の管理
- 大規模システムの構造化

**識別キーワード:**
- 「パッケージ」「インポート」「マージ」
- 「名前空間」「依存関係」

**適用場面:**
- 大規模システムの構造設計
- ライブラリ構成の設計
- レイヤーアーキテクチャの表現

#### 11. デプロイメント図 (Deployment Diagram)

**特徴:**
- システムの物理的な配置を表現
- ノード、成果物、通信経路で構成
- ハードウェアとソフトウェアの配置関係

**識別キーワード:**
- 「ノード」「成果物」「デプロイ」
- 「実行環境」「デバイス」「通信」

**適用場面:**
- インフラストラクチャ設計
- システム配置計画
- 性能・セキュリティ設計

#### 12. プロファイル図 (Profile Diagram)

**特徴:**
- UMLの拡張メカニズムを定義
- ステレオタイプ、タグ付き値、制約を定義
- ドメイン固有の概念を表現

**識別キーワード:**
- 「ステレオタイプ」「タグ付き値」「制約」
- 「メタモデル」「プロファイル」

**適用場面:**
- ドメイン固有言語の定義
- 開発標準の定義

#### 13. タイミング図 (Timing Diagram)

**特徴:**
- オブジェクトの状態変化を時間軸で表現
- タイミング制約を明確に表現
- リアルタイムシステムに適用

**識別キーワード:**
- 「タイムライン」「状態変化」「タイミング制約」
- 「持続時間」「イベント発生時刻」

**適用場面:**
- リアルタイムシステム設計
- 組込みシステム設計
- パフォーマンス要件の表現

#### 14. インタラクション概要図 (Interaction Overview Diagram)

**特徴:**
- 複数の相互作用図を統合
- アクティビティ図の記法で相互作用を整理
- 制御フローで相互作用を結合

**識別キーワード:**
- 「相互作用」「制御フロー」「参照」
- 「インタラクション使用」

**適用場面:**
- 複雑な相互作用の整理
- シナリオの統合表現

### 状態遷移図 (State Transition Diagram)

**特徴:**
- 有限状態機械の表現
- 状態と遷移条件を明確に定義
- UMLのステートマシン図より単純

**識別キーワード:**
- 「状態」「遷移」「トリガー」
- 「初期状態」「最終状態」

**適用場面:**
- 簡単な状態管理
- 画面遷移設計
- プロトコル設計

### BPMN (Business Process Model and Notation)

**特徴:**
- ビジネスプロセスの標準記法
- フロー、イベント、ゲートウェイ、アクティビティで構成
- 実行可能なプロセス定義が可能

**識別キーワード:**
- 「プール」「レーン」「タスク」「イベント」
- 「ゲートウェイ」「メッセージフロー」「シーケンスフロー」
- 「開始/中間/終了イベント」

**記法要素:**
```
○ : 開始イベント
◎ : 中間イベント
● : 終了イベント
□ : タスク/アクティビティ
◇ : ゲートウェイ（分岐）
→ : シーケンスフロー
⇢ : メッセージフロー
```

**適用場面:**
- ビジネスプロセス改善（BPR）
- ワークフロー自動化
- 業務手順書の作成
- プロセス監視・分析

**📊 具体例：受注処理プロセス**
```
○ → [受注受付] → ◇ → [在庫確認] → [出荷指示] → ●
                  ↓
              [在庫なし通知] → ●
```

### EPC (Event-driven Process Chain)

**特徴:**
- イベント駆動のプロセス表現
- イベント、ファンクション、論理演算子で構成
- ドイツSAP社のARISで採用

**識別キーワード:**
- 「イベント」「ファンクション」「XOR/AND/OR」
- 「組織単位」「情報オブジェクト」
- 「プロセスパス」

**記法要素:**
```
⬡ : イベント（六角形）
□ : ファンクション
◇ : 論理演算子（XOR/AND/OR）
```

**適用場面:**
- ERP導入時の業務分析
- 業務プロセスの詳細設計
- イベント駆動アーキテクチャ

### ペトリネット図 (Petri Net Diagram)

**特徴:**
- 並行システムの数学的モデル
- プレース、トランジション、トークンで構成
- 形式的検証が可能

**識別キーワード:**
- 「プレース」「トランジション」「トークン」
- 「発火」「マーキング」「可達性」
- 「デッドロック」「ライブネス」

**記法要素:**
```
○ : プレース（状態を表す）
│ : トランジション（遷移を表す）
● : トークン（リソースを表す）
→ : アーク（流れを表す）
```

**適用場面:**
- 並行システムの設計
- リソース管理の分析
- デッドロック検出
- 製造システムの設計

**📊 具体例：生産ラインのペトリネット**
```
[材料あり]●──→│加工│──→[加工済]──→│検査│──→[完成品]
               ↑                     ↓
           [機械空き]●            [不良品]
```

凡例：◎:最適、○:適している、△:限定的、×:不適

### 特徴による分類

#### データ中心のモデリング
- **E-R図**: データの静的構造と関連
- **クラス図**: オブジェクトの構造と関連
- **DFD**: データの流れと変換

#### プロセス中心のモデリング
- **BPMN**: ビジネスプロセスの詳細
- **EPC**: イベント駆動プロセス
- **アクティビティ図**: ワークフローと並行処理
- **ペトリネット**: 並行プロセスと同期

#### 振る舞い中心のモデリング
- **シーケンス図**: 時系列的な相互作用
- **状態遷移図**: オブジェクトの状態変化
- **タイミング図**: 時間制約のある振る舞い

## 4. 実装例と実践的な活用方法

### 統合的なモデリングアプローチ

実際のプロジェクトでは、複数のモデリング技法を組み合わせて使用します。

**例：ECサイト開発プロジェクト**

1. **要求分析フェーズ**
   - ユースケース図で機能要求を整理
   - アクティビティ図で業務フローを可視化
   - BPMNで詳細な業務プロセスを定義

2. **設計フェーズ**
   - E-R図でデータモデルを設計
   - クラス図でシステム構造を設計
   - シーケンス図で主要な処理フローを設計
   - 状態遷移図で注文状態を管理

3. **実装フェーズ**
   - コンポーネント図でモジュール構成を確認
   - デプロイメント図で配置を計画

### モデリングツールの活用

**主要なモデリングツール:**
- **Enterprise Architect**: 包括的なUMLサポート
- **astah***: 日本語対応の使いやすいツール
- **Visual Paradigm**: BPMNとUMLの統合サポート
- **draw.io**: 無料のWebベースツール
- **PlantUML**: テキストベースのUML生成

## 5. メリット・デメリット

### 共通のメリット
1. **可視化による理解促進**
   - 複雑な構造やプロセスを直感的に理解可能
   - ステークホルダー間の認識共有が容易

2. **標準化による品質向上**
   - 統一された記法による一貫性

BPMNは、ビジネスプロセスの表現に特化した標準記法で、As-Is（現状）とTo-Be（あるべき姿）のプロセスを詳細に記述し、プロセス改善に活用できます。<br>
<br>
Aが間違いの理由：E-R図は、データ構造の表現に使用されます<br>
Cが間違いの理由：クラス図は、システムの構造を表現します<br>
Dが間違いの理由：コンポーネント図は、システムの物理的構成を表現します<br>
<br>
【補足】BPMNでは、プール、レーン、タスク、ゲートウェイなどを使って、組織横断的なプロセスも明確に表現できます。
</details>

### 問題18
大規模システムで、サブシステム間の論理的な依存関係と名前空間の管理を行いたい。使用すべきUML図は？

- A) オブジェクト図
- B) パッケージ図
- C) デプロイメント図
- D) プロファイル図

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
パッケージ図は、モデル要素をグループ化し、パッケージ間の依存関係を表現するのに適しています。大規模システムの論理的な構造化に有効です。<br>
<br>
Aが間違いの理由：オブジェクト図は、特定時点でのインスタンスを表現します<br>
Cが間違いの理由：デプロイメント図は、物理的な配置を表現します<br>
Dが間違いの理由：プロファイル図は、UMLの拡張定義に使用されます<br>
<br>
【補足】パッケージ図では、import、merge、useなどの関係を使って、パッケージ間の依存関係を詳細に定義できます。
</details>

### 問題19
SAP導入プロジェクトで、既存の業務プロセスをイベント駆動で表現し、ERPシステムとの整合性を確認したい。最適なモデリング技法は？

- A) DFD
- B) EPC
- C) ペトリネット図
- D) シーケンス図

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
EPC（Event-driven Process Chain）は、SAP社のARISで採用されているモデリング技法で、イベント駆動のプロセス表現に適しており、ERP導入時の業務分析で広く使用されています。<br>
<br>
Aが間違いの理由：DFDは、データフローの表現に特化しています<br>
Cが間違いの理由：ペトリネット図は、形式的検証には適していますが、ビジネスプロセスの表現には不向きです<br>
Dが間違いの理由：シーケンス図は、オブジェクト間の相互作用を表現します<br>
<br>
【補足】EPCでは、イベント（六角形）とファンクション（四角形）を交互に配置し、プロセスの流れを明確に表現します。
</details>

### 問題20
複数の相互作用図（シーケンス図やコミュニケーション図）を統合して、全体的な処理の流れを俯瞰したい。使用すべきUML図は？

- A) インタラクション概要図
- B) コンポジット構造図
- C) タイミング図
- D) アクティビティ図

<details>
<summary>解答</summary>
<strong>正解: A</strong><br>
インタラクション概要図は、複数の相互作用図を統合し、アクティビティ図の記法を使って全体的な制御フローを表現するのに適しています。<br>
<br>
Bが間違いの理由：コンポジット構造図は、クラスの内部構造を詳細に表現します<br>
Cが間違いの理由：タイミング図は、時間制約のある振る舞いを表現します<br>
Dが間違いの理由：アクティビティ図は、プロセスフローを表現しますが、相互作用図の統合には特化していません<br>
<br>
【補足】インタラクション概要図では、インタラクション使用（interaction use）を使って、他の相互作用図を参照し、複雑なシナリオを整理できます。
</details>

## 9. 専門用語集

### アルファベット

**API (Application Programming Interface)**
- **読み方**: エーピーアイ
- **意味**: プログラム間でデータや機能をやり取りするためのインターフェース。モデリングでは、コンポーネント図でインターフェースとして表現される
- **関連用語**: インターフェース、コンポーネント図

**BPMN (Business Process Model and Notation)**
- **読み方**: ビーピーエムエヌ
- **意味**: ビジネスプロセスを表現するための国際標準記法。実行可能なプロセス定義も可能
- **関連用語**: プロセスモデリング、ワークフロー

**DFD (Data Flow Diagram)**
- **読み方**: ディーエフディー、データフローダイアグラム
- **意味**: システム内のデータの流れを表現する図法。構造化分析で使用される
- **関連用語**: 構造化分析、プロセス、データストア

**EPC (Event-driven Process Chain)**
- **読み方**: イーピーシー、イベントドリブンプロセスチェーン
- **意味**: イベント駆動でビジネスプロセスを表現する手法。SAP社のARISで採用
- **関連用語**: ARIS、イベント、ファンクション

**E-R図 (Entity-Relationship Diagram)**
- **読み方**: イーアールず、実体関連図
- **意味**: データの構造と関連を表現する図法。データベース設計で広く使用
- **関連用語**: エンティティ、リレーションシップ、属性

**UML (Unified Modeling Language)**
- **読み方**: ユーエムエル、統一モデリング言語
- **意味**: ソフトウェア開発のための標準的なモデリング言語。14種類の図で構成
- **関連用語**: OMG、オブジェクト指向、モデリング

### あ行

**アーク**
- **読み方**: あーく
- **意味**: ペトリネット図において、プレースとトランジションを結ぶ有向線。トークンの流れを示す
- **関連用語**: ペトリネット、プレース、トランジション

**アクター**
- **読み方**: あくたー
- **意味**: ユースケース図において、システムと相互作用する外部の人や他システムを表す要素
- **関連用語**: ユースケース図、主アクター、副アクター

**アクティビティ**
- **読み方**: あくてぃびてぃ
- **意味**: プロセスやワークフローにおける作業や処理を表す要素。アクティビティ図やBPMNで使用
- **関連用語**: アクティビティ図、タスク、プロセス

**アトリビュート**
- **読み方**: あとりびゅーと
- **意味**: エンティティやクラスが持つ属性。E-R図やクラス図で表現される
- **関連用語**: 属性、エンティティ、クラス

**インスタンス**
- **読み方**: いんすたんす
- **意味**: クラスから生成された具体的なオブジェクト。オブジェクト図で表現される
- **関連用語**: オブジェクト、クラス、実体

**インターフェース**
- **読み方**: いんたーふぇーす
- **意味**: コンポーネントやクラスが提供または要求する機能の定義。実装から分離された仕様
- **関連用語**: コンポーネント図、提供インターフェース、要求インターフェース

**エンティティ**
- **読み方**: えんてぃてぃ
- **意味**: E-R図における実体。データベースではテーブルに対応する概念的な存在
- **関連用語**: E-R図、実体、テーブル

### か行

**カーディナリティ**
- **読み方**: かーでぃなりてぃ
- **意味**: エンティティ間の関連における多重度。1対1、1対多、多対多などを表現
- **関連用語**: 多重度、リレーションシップ、E-R図

**外部エンティティ**
- **読み方**: がいぶえんてぃてぃ
- **意味**: DFDにおいて、システムの外部に存在し、システムとデータをやり取りする要素
- **関連用語**: DFD、システム境界、データフロー

**活性区間**
- **読み方**: かっせいくかん
- **意味**: シーケンス図において、オブジェクトがメソッドを実行している期間を表す縦長の四角形
- **関連用語**: シーケンス図、ライフライン、実行仕様

**ガード条件**
- **読み方**: がーどじょうけん
- **意味**: 状態遷移やアクティビティ図において、遷移が発生するための条件式
- **関連用語**: 状態遷移、条件、制約

**クラス**
- **読み方**: くらす
- **意味**: オブジェクト指向における、同じ属性と操作を持つオブジェクトの集合を定義したもの
- **関連用語**: オブジェクト、属性、メソッド

**ゲートウェイ**
- **読み方**: げーとうぇい
- **意味**: BPMNにおいて、プロセスフローの分岐や合流を制御する菱形の要素
- **関連用語**: BPMN、XOR、AND、OR

**コンポーネント**
- **読み方**: こんぽーねんと
- **意味**: システムの物理的または論理的な構成要素。独立して配置・実行可能な単位
- **関連用語**: コンポーネント図、モジュール、インターフェース

### さ行

**シーケンス図**
- **読み方**: しーけんすず
- **意味**: オブジェクト間の時系列的な相互作用を表現するUML図
- **関連用語**: ライフライン、メッセージ、相互作用図

**状態**
- **読み方**: じょうたい
- **意味**: オブジェクトやシステムが特定の時点で持つ条件や状況
- **関連用語**: 状態遷移図、ステートマシン図、遷移

**ステレオタイプ**
- **読み方**: すてれおたいぷ
- **意味**: UMLの要素に新しい意味を付加するための拡張メカニズム。<<>>で表記
- **関連用語**: プロファイル、タグ付き値、制約

**スイムレーン**
- **読み方**: すいむれーん
- **意味**: アクティビティ図やBPMNで、活動の責任範囲を視覚的に区分けする領域
- **関連用語**: プール、レーン、責任分担

### た行

**多重度**
- **読み方**: たじゅうど
- **意味**: 関連の両端で、相手側のインスタンスがいくつ存在できるかを示す数
- **関連用語**: カーディナリティ、関連、クラス図

**データストア**
- **読み方**: でーたすとあ
- **意味**: DFDにおいて、データの保管場所を表す要素。平行線で表現
- **関連用語**: DFD、データフロー、永続化

**データフロー**
- **読み方**: でーたふろー
- **意味**: DFDにおいて、プロセス間やプロセスとデータストア間のデータの流れ
- **関連用語**: DFD、プロセス、矢印

**トークン**
- **読み方**: とーくん
- **意味**: ペトリネット図において、プレース内に存在しリソースや条件の成立を表す印
- **関連用語**: ペトリネット、プレース、発火

**トランジション**
- **読み方**: とらんじしょん
- **意味**: ペトリネット図において、状態の変化や処理を表す要素。縦線や四角形で表現
- **関連用語**: ペトリネット、発火、プレース

**トリガー**
- **読み方**: とりがー
- **意味**: 状態遷移を引き起こすイベントや条件
- **関連用語**: イベント、状態遷移、遷移

### な行

**ノード**
- **読み方**: のーど
- **意味**: デプロイメント図における、ハードウェアやソフトウェアの実行環境を表す要素
- **関連用語**: デプロイメント図、成果物、配置

### は行

**パッケージ**
- **読み方**: ぱっけーじ
- **意味**: UMLにおいて、モデル要素をグループ化するための名前空間
- **関連用語**: パッケージ図、名前空間、依存関係

**発火**
- **読み方**: はっか
- **意味**: ペトリネット図において、トランジションが実行可能になり、トークンが移動すること
- **関連用語**: ペトリネット、トランジション、トークン

**プール**
- **読み方**: ぷーる
- **意味**: BPMNにおいて、プロセスの参加者や組織を表す大きな区画
- **関連用語**: BPMN、レーン、スイムレーン

**プレース**
- **読み方**: ぷれーす
- **意味**: ペトリネット図において、状態や条件を表す円形の要素
- **関連用語**: ペトリネット、トークン、トランジション

**プロセス**
- **読み方**: ぷろせす
- **意味**: DFDやBPMNにおいて、データの処理や変換、業務活動を表す要素
- **関連用語**: DFD、BPMN、処理、アクティビティ

### ま行

**メッセージ**
- **読み方**: めっせーじ
- **意味**: シーケンス図において、オブジェクト間でやり取りされる通信を表す矢印
- **関連用語**: シーケンス図、同期メッセージ、非同期メッセージ

### や行

**ユースケース**
- **読み方**: ゆーすけーす
- **意味**: システムが提供する機能を利用者の視点から表現したもの
- **関連用語**: ユースケース図、アクター、シナリオ

### ら行

**ライフライン**
- **読み方**: らいふらいん
- **意味**: シーケンス図において、オブジェクトの存在期間を表す垂直の破線
- **関連用語**: シーケンス図、オブジェクト、活性区間

**リレーションシップ**
- **読み方**: りれーしょんしっぷ
- **意味**: E-R図において、エンティティ間の関連を表す要素
- **関連用語**: E-R図、関連、関係

**レーン**
- **読み方**: れーん
- **意味**: BPMNのプール内で、役割や部門を区分けする領域
- **関連用語**: BPMN、プール、スイムレーン

### わ行

**ワークフロー**
- **読み方**: わーくふろー
- **意味**: 業務の流れや作業手順を定義したもの。BPMNやアクティビティ図で表現
- **関連用語**: プロセス、BPMN、業務フロー
