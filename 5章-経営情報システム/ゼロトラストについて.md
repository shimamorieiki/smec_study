# ゼロトラストについて

## 概要
ゼロトラストは、「何も信頼しない」という前提に基づくセキュリティモデルです。従来の境界型セキュリティが「内部は安全」という考え方に基づいていたのに対し、ゼロトラストは内部・外部を問わず、すべてのアクセスを検証することを原則とします。2010年にForrester Research社のJohn Kindervag氏によって提唱され、クラウド化やリモートワークの普及により、現代のIT環境において必須のセキュリティアプローチとなっています。

## 1. 基本概念・仕組み

### ゼロトラストの核心原則
- **定義**: 「決して信頼せず、常に検証する」（Never Trust, Always Verify）を基本とするセキュリティフレームワーク
- **動作原理**: すべてのアクセス要求に対して、アイデンティティ、デバイス、ロケーション、リスクレベルなどを継続的に検証
- **特徴**: 最小権限の原則、マイクロセグメンテーション、継続的な監視と検証

### 従来の境界型セキュリティとの関係
- **従来技術との違い**: 境界型は「城と堀」モデルで内部を信頼、ゼロトラストは内外問わず検証
- **改善点**: 内部脅威への対応、クラウド環境への適応、きめ細かなアクセス制御
- **限界**: 導入コストが高い、複雑な実装、レガシーシステムとの統合が困難

## 2. ゼロトラストの実装モデル

### NIST SP 800-207による分類
NISTはゼロトラストアーキテクチャを実装する際の基本的なアプローチを3つに分類しています。

### エンハンスド・アイデンティティ・ガバナンス（EIG）
**特徴:**
- アイデンティティを中心としたアクセス制御
- 強力な認証と認可の仕組み
- 動的なポリシー適用

**実装方法:**
```
1. 多要素認証（MFA）の導入
2. アイデンティティプロバイダー（IdP）の統合
3. 条件付きアクセスポリシーの設定
4. 特権アクセス管理（PAM）の実装
```

**📊 具体的な計算例**
**例: リスクスコアベースのアクセス制御**
- 基本リスクスコア: 50点
- 社内ネットワークからのアクセス: -20点
- 管理対象デバイス: -10点
- 異常な時間帯: +30点
- 初めての場所: +20点

**ステップ1: リスクスコアの計算**
```
総リスクスコア = 50 - 20 - 10 + 30 + 20 = 70点
```

**ステップ2: アクセス判定**
```
70点 > 閾値（60点）→ 追加認証を要求
```

**結果: 多要素認証を要求してアクセスを許可**

💡 **実際の現場では**: リスクスコアは機械学習により動的に調整され、ユーザーの行動パターンに基づいて個別に最適化されます。

### マイクロセグメンテーション
**特徴:**
- ネットワークを細かく分割
- 東西トラフィックの制御
- アプリケーション単位での隔離

**実装方法:**
```
1. ソフトウェア定義境界（SDP）の構築
2. マイクロセグメンテーションプラットフォームの導入
3. アプリケーション依存関係のマッピング
4. セグメント間のポリシー定義
```

### ネットワークインフラストラクチャとSDP
**特徴:**
- ソフトウェア定義境界による動的な接続
- デバイスとリソース間の暗号化通信
- ネットワークの可視性向上

**実装方法:**
```
1. SDPコントローラーの設置
2. SDPゲートウェイの配置
3. クライアントエージェントの展開
4. 動的なトンネル確立
```

## 3. ゼロトラストの主要コンポーネント

### 必須コンポーネント
#### ポリシーエンジン（PE）
- **意味**: アクセス判定を行う中核コンポーネント
- **機能**: リスク評価、ポリシー適用、判定結果の出力
- **連携**: PDP、PIPと密接に連携
- **推奨実装**: クラウドベースのポリシーエンジン

#### ポリシー決定ポイント（PDP）
- **意味**: PEの判定を実行に移すコンポーネント
- **機能**: アクセス許可/拒否の実施
- **配置**: 各リソースの近くに配置
- **推奨構成**: 分散型PDP

#### ポリシー情報ポイント（PIP）
- **意味**: 判定に必要な情報を収集・提供
- **データソース**: SIEM、脅威インテリジェンス、資産管理
- **更新頻度**: リアルタイムまたは準リアルタイム
- **推奨統合**: API経由での自動連携

## 4. 実装例・適用事例

### 基本実装（中小企業向け）
```python
# ゼロトラスト認証の基本実装例
import jwt
import datetime
from typing import Dict, Optional

class ZeroTrustAuthenticator:
    def __init__(self, secret_key: str):
        self.secret_key = secret_key
        self.risk_threshold = 60
    
    def calculate_risk_score(self, context: Dict) -> int:
        """コンテキストに基づくリスクスコアの計算"""
        score = 50  # 基本スコア
        
        # デバイスの信頼性
        if context.get('managed_device'):
            score -= 20
        else:
            score += 20
            
        # 場所の評価
        if context.get('location') in ['office', 'home']:
            score -= 10
        else:
            score += 15
            
        # 時間帯の評価
        current_hour = datetime.datetime.now().hour
        if 9 <= current_hour <= 18:
            score -= 5
        else:
            score += 10
            
        return max(0, min(100, score))
    
    def generate_token(self, user_id: str, context: Dict) -> Optional[str]:
        """リスク評価に基づくトークン生成"""
        risk_score = self.calculate_risk_score(context)
        
        if risk_score > self.risk_threshold:
            # 高リスクの場合は追加認証が必要
            return None
            
        payload = {
            'user_id': user_id,
            'risk_score': risk_score,
            'exp': datetime.datetime.utcnow() + datetime.timedelta(hours=1)
        }
        
        return jwt.encode(payload, self.secret_key, algorithm='HS256')
```

### 応用実装（エンタープライズ向け）
```python
# エンタープライズ向けゼロトラストアーキテクチャ
from typing import List, Dict, Tuple
import asyncio
from dataclasses import dataclass
from enum import Enum

class AccessDecision(Enum):
    ALLOW = "allow"
    DENY = "deny"
    CHALLENGE = "challenge"

@dataclass
class AccessContext:
    user_id: str
    device_id: str
    resource_id: str
    location: str
    timestamp: datetime.datetime
    request_metadata: Dict

class EnterpriseZeroTrustEngine:
    def __init__(self):
        self.policy_engine = PolicyEngine()
        self.risk_engine = RiskEngine()
        self.identity_provider = IdentityProvider()
        self.device_trust_service = DeviceTrustService()
        
    async def evaluate_access_request(self, context: AccessContext) -> Tuple[AccessDecision, Dict]:
        """包括的なアクセス評価"""
        # 並列で各種評価を実行
        tasks = [
            self.identity_provider.verify_identity(context.user_id),
            self.device_trust_service.assess_device(context.device_id),
            self.risk_engine.calculate_risk(context),
            self.policy_engine.evaluate_policies(context)
        ]
        
        results = await asyncio.gather(*tasks)
        
        identity_valid, device_trust, risk_score, policy_result = results
        
        # 総合判定
        if not identity_valid:
            return AccessDecision.DENY, {"reason": "Invalid identity"}
            
        if device_trust < 0.5:
            return AccessDecision.CHALLENGE, {"reason": "Untrusted device", "mfa_required": True}
            
        if risk_score > 80:
            return AccessDecision.DENY, {"reason": "High risk score"}
            
        if not policy_result['compliant']:
            return AccessDecision.DENY, {"reason": "Policy violation", "violated_policies": policy_result['violations']}
            
        return AccessDecision.ALLOW, {"session_duration": 3600, "permissions": policy_result['permissions']}
```

## 5. メリット・デメリット

### メリット
**1. 高度なセキュリティ**
- **理由**: すべてのアクセスを検証することで、内部脅威も含めて対応可能
- **効果**: セキュリティインシデントの大幅な削減
- **具体例**: ラテラルムーブメント（横方向の移動）攻撃を防止

**2. 柔軟な働き方への対応**
- **理由**: 場所やデバイスに依存しないセキュアなアクセス
- **効果**: リモートワークやBYODの安全な実現
- **具体例**: VPN不要でクラウドアプリケーションへの安全なアクセス

**3. コンプライアンス対応の向上**
- **理由**: きめ細かなアクセス制御とログ記録
- **効果**: 監査要件への対応が容易
- **具体例**: GDPR、SOC2などの要件を満たす詳細なアクセスログ

### デメリット
**1. 導入の複雑性**
- **理由**: 既存インフラの大幅な変更が必要
- **影響**: 導入期間の長期化とコスト増大
- **対策**: 段階的な導入計画とPoC（概念実証）の実施

**2. 初期投資の高さ**
- **理由**: 複数のソリューションの統合が必要
- **影響**: ROI実現までに時間がかかる
- **対策**: クラウドベースのSaaSソリューションの活用

**3. ユーザー体験への影響**
- **理由**: 頻繁な認証要求
- **影響**: 生産性の低下の可能性
- **対策**: リスクベース認証とSSO（シングルサインオン）の活用

### 問題1
ゼロトラストの基本原則として最も適切なものはどれか？

- A) 内部ネットワークは基本的に信頼し、外部からのアクセスのみ検証する
- B) 一度認証したユーザーは、セッション中は継続的に信頼する
- C) すべてのアクセス要求を検証し、何も信頼しない
- D) VPN接続したデバイスは自動的に信頼する

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
ゼロトラストの基本原則は「Never Trust, Always Verify（決して信頼せず、常に検証する）」です。内部・外部を問わず、すべてのアクセス要求を継続的に検証します。<br>
<br>
Aが間違いの理由：従来の境界型セキュリティの考え方であり、ゼロトラストとは正反対です<br>
Bが間違いの理由：ゼロトラストでは継続的な検証が必要で、一度の認証では不十分です<br>
Dが間違いの理由：VPN接続も含めて、すべての接続を検証対象とします<br>
<br>
【補足】実務では、この原則に基づいて、アクセスごとにユーザー、デバイス、場所、時間などを総合的に評価します。
</details>

【補足】ゼロトラストではVPNの代わりに、SDPやSASEなどの技術を使用して、より細かなアクセス制御を実現します。

### 問題5
ゼロトラストにおける「最小権限の原則」の実装として不適切なものはどれか？

- A) ジャストインタイム（JIT）アクセス
- B) 職務分離（SoD）
- C) すべてのユーザーに管理者権限を付与
- D) 時限的なアクセス許可

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
最小権限の原則では、ユーザーには業務遂行に必要最小限の権限のみを付与します。すべてのユーザーに管理者権限を付与することは、この原則に反します。<br>
<br>
A、B、Dが間違いの理由：これらはすべて最小権限の原則を実現する適切な手法です<br>
- JITアクセス：必要な時だけ権限を付与<br>
- 職務分離：権限を分散してリスクを低減<br>
- 時限的アクセス：一定時間後に自動的に権限を剥奪<br>
<br>
【補足】実務では、通常業務には一般権限を使用し、管理作業が必要な場合のみ一時的に昇格させます。
</details>

### 問題7
ソフトウェア定義境界（SDP）の特徴として正しいものはどれか？

- A) 物理的なファイアウォールで境界を定義する
- B) 認証前にリソースを隠蔽し、認証後に動的に接続を確立する
- C) すべてのトラフィックを中央のプロキシ経由で通信させる
- D) ネットワークセグメントを固定的に分割する

<details>
<summary>解答</summary>
<strong>正解: B</strong><br>
SDPは「ブラッククラウド」アプローチを採用し、認証されるまでリソースを見えなくし、認証後に必要なリソースへの暗号化された接続を動的に確立します。<br>
<br>
Aが間違いの理由：SDPはソフトウェアで定義され、物理的な境界に依存しません<br>
Cが間違いの理由：SDPは分散アーキテクチャで、必ずしも中央集約的ではありません<br>
Dが間違いの理由：SDPは動的で、固定的な分割ではありません<br>
<br>
【補足】SDPは「need to know」原則に基づき、ユーザーが必要なリソースのみを可視化します。
</details>

### 問題8
ゼロトラストにおけるデバイストラストの評価要素として適切でないものはどれか？

- A) デバイスの健全性（パッチ適用状況）
- B) デバイスの所有者（企業所有/個人所有）
- C) デバイスの画面サイズ
- D) セキュリティソフトウェアの状態

<details>
<summary>解答</summary>
<strong>正解: C</strong><br>
画面サイズはデバイスの信頼性評価には関係ありません。セキュリティリスクの判定には影響しない物理的特性です。<br>
<br>
A、B、Dが間違いの理由：これらはすべてデバイスの信頼性を判断する重要な要素です<br>
- パッチ適用状況：既知の脆弱性への対策状況を示す<br>

- デバイス信頼度: 0.6<br>

- 総合スコア: 0.8 × 0.6 × 0.3 = 0.144<br>

## 9. 専門用語集

このドキュメントで使用された専門用語について、アルファベット順・50音順で解説します。

### アルファベット

**API (Application Programming Interface)**
- **読み方**: エーピーアイ
- **意味**: アプリケーション間でデータや機能をやり取りするためのインターフェース。ゼロトラストでは、各コンポーネント間の連携に使用
- **関連用語**: REST API、GraphQL

**BYOD (Bring Your Own Device)**
- **読み方**: ビーワイオーディー
- **意味**: 従業員が個人所有のデバイスを業務に使用すること
- **関連用語**: CYOD、COPE

**CASB (Cloud Access Security Broker)**
- **読み方**: キャスビー
- **意味**: クラウドサービスへのアクセスを仲介し、セキュリティポリシーを適用するソリューション
- **関連用語**: SASE、SWG

**IAM (Identity and Access Management)**
- **読み方**: アイアム
- **意味**: ユーザーのアイデンティティとアクセス権限を管理するシステム
- **関連用語**: IDaaS、PAM

**IDaaS (Identity as a Service)**
- **読み方**: アイダース
- **意味**: クラウドベースで提供されるアイデンティティ管理サービス
- **関連用語**: SSO、MFA

**MFA (Multi-Factor Authentication)**
- **読み方**: エムエフエー
- **意味**: 複数の認証要素を組み合わせた認証方式
- **関連用語**: 2FA、パスワードレス認証

**NIST (National Institute of Standards and Technology)**
- **読み方**: ニスト
- **意味**: 米国国立標準技術研究所。ゼロトラストの標準フレームワークを策定
- **関連用語**: SP 800-207

**PAM (Privileged Access Management)**
- **読み方**: パム
- **意味**: 特権アカウントのアクセスを管理・監視するシステム
- **関連用語**: JIT、最小権限

**PDP (Policy Decision Point)**
- **読み方**: ピーディーピー
- **意味**: ポリシーエンジンの判定を実行するコンポーネント
- **関連用語**: PE、PEP

**PE (Policy Engine)**
- **読み方**: ピーイー
- **意味**: アクセス可否を判定する中核エンジン
- **関連用語**: PDP、PIP

**PEP (Policy Enforcement Point)**
- **読み方**: ペップ
- **意味**: ポリシーを実際に適用する実行ポイント
- **関連用語**: PDP

**PIP (Policy Information Point)**
- **読み方**: ピップ
- **意味**: ポリシー判定に必要な情報を収集・提供するコンポーネント
- **関連用語**: SIEM、脅威インテリジェンス

**SASE (Secure Access Service Edge)**
- **読み方**: サッシー
- **意味**: ネットワークとセキュリティ機能をクラウドで統合提供するアーキテクチャ
- **関連用語**: ZTNA、SD-WAN

**SDP (Software Defined Perimeter)**
- **読み方**: エスディーピー
- **意味**: ソフトウェアで動的に定義されるネットワーク境界
- **関連用語**: ブラッククラウド、ZTNA

**SIEM (Security Information and Event Management)**
- **読み方**: シーム
- **意味**: セキュリティ情報とイベントを統合管理するシステム
- **関連用語**: SOC、XDR

**SSO (Single Sign-On)**
- **読み方**: エスエスオー
- **意味**: 一度の認証で複数のサービスにアクセスできる仕組み
- **関連用語**: SAML、OAuth

**VPN (Virtual Private Network)**
- **読み方**: ブイピーエヌ
- **意味**: 仮想的な専用ネットワーク接続。ゼロトラストでは代替技術への移行が進む
- **関連用語**: リモートアクセス、トンネリング

**XDR (Extended Detection and Response)**
- **読み方**: エックスディーアール
- **意味**: 複数のセキュリティ層にまたがる脅威の検知と対応を統合的に行うシステム
- **関連用語**: EDR、NDR、SIEM

**ZTNA (Zero Trust Network Access)**
- **読み方**: ゼットティーエヌエー
- **意味**: ゼロトラスト原則に基づくネットワークアクセス技術
- **関連用語**: SDP、SASE

- **関連用語**: 職務分離、Need to Know

- **読み方**: さいばーこうげき

- **関連用語**: APT、ランサムウェア

**職務分離**
- **読み方**: しょくむぶんり

- **関連用語**: SoD、内部統制

**脅威インテリジェンス**

- **関連用語**: IOC、TTP

### た行

- **読み方**: たようそにんしょう

- **関連用語**: MFA、2FA

**デバイストラスト**

- **関連用語**: 条件付きアクセス、適応型セキュリティ

### な行

**内部脅威**
- **読み方**: ないぶきょうい
- **意味**: 組織内部からの悪意ある行為や過失によるセキュリティリスク
- **関連用語**: インサイダー脅威、特権悪用

### は行
