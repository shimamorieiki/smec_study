# PERTについて

## 概要
PERT（Program Evaluation and Review Technique）は、プロジェクト管理において作業の所要時間が不確実な場合に、プロジェクトの完了時間を確率的に見積もる手法です。1958年に米国海軍のポラリスミサイル開発プロジェクトで開発され、複雑なプロジェクトのスケジュール管理に広く活用されています。

## 1. 基本概念・仕組み

### PERTの核となる概念
- **定義**: 作業の所要時間を確率分布として扱い、プロジェクトの完了時間を統計的に分析する手法
- **動作原理**: 各作業の楽観値・最可能値・悲観値から期待値と分散を計算し、クリティカルパスの完了時間を確率的に評価
- **特徴**: 不確実性を定量的に扱える、リスク評価が可能、大規模プロジェクトに適している

### 関連技術との関係
- **従来技術との違い**: CPM（Critical Path Method）が確定的な所要時間を扱うのに対し、PERTは確率的に扱う
- **改善点**: 不確実性を考慮したより現実的なスケジュール管理が可能
- **限界**: 見積もりの精度に依存、計算が複雑、小規模プロジェクトではオーバースペック

## 2. 三点見積もりと計算方法

### 三点見積もり
PERTでは各作業について以下の3つの見積もりを行います：

### 楽観値（a）: 最も順調に進んだ場合の所要時間
**特徴:**
- 理想的な条件下での最短時間
- 発生確率は約1%程度
- リスクが全く顕在化しない場合

### 最可能値（m）: 最も可能性の高い所要時間  
**特徴:**
- 通常の条件下での所要時間
- 過去の実績に基づく現実的な値
- 最頻値（モード）に相当

### 悲観値（b）: 最悪の場合の所要時間
**特徴:**
- 想定される問題が発生した場合の時間
- 発生確率は約1%程度
- 通常のリスクが顕在化した場合（災害等は除く）

### PERT期待値の算出方法
```
期待値（te） = (a + 4m + b) / 6
```

### 分散の算出方法
```
分散（σ²） = ((b - a) / 6)²
標準偏差（σ） = (b - a) / 6
```

### 📊 具体的な計算例

**例: Webサイト開発プロジェクトの要件定義作業**
- 楽観値（a）: 5日
- 最可能値（m）: 8日
- 悲観値（b）: 15日

**ステップ1: 期待値の計算**
```
te = (5 + 4×8 + 15) / 6
   = (5 + 32 + 15) / 6
   = 52 / 6
   = 8.67日
```

**ステップ2: 分散と標準偏差の計算**
```
σ² = ((15 - 5) / 6)²
   = (10 / 6)²
   = 1.67²
   = 2.78

σ = 1.67日
```

**結果: 要件定義の期待所要時間は8.67日、標準偏差は1.67日**

💡 **実際の現場では**: 期待値±2σの範囲（5.33日～12.01日）で約95%の確率で完了すると解釈できます。

## 3. クリティカルパスとPERT

### ネットワーク図の作成
#### アクティビティ・オン・ノード（AON）
- **意味**: 作業をノード（節）で表現
- **特徴**: 直感的で理解しやすい
- **使用場面**: 現代のプロジェクト管理ソフトウェアの主流

#### アクティビティ・オン・アロー（AOA）
- **意味**: 作業を矢線で表現
- **特徴**: ダミー作業が必要な場合がある
- **使用場面**: PERTの初期に使用された方式

### クリティカルパスの特定と分析
- **定義**: プロジェクトの最長経路で、遅延が直接プロジェクト全体の遅延につながる
- **特定方法**: 各経路の期待値を合計し、最大となる経路を見つける
- **分散の合計**: クリティカルパス上の各作業の分散を合計して全体の分散を求める

## 4. 実装例・適用事例

### 基本的なPERT計算の実装例
```python
# PERT計算の基本実装
class PERTActivity:
    def __init__(self, name, optimistic, most_likely, pessimistic):
        self.name = name
        self.a = optimistic
        self.m = most_likely
        self.b = pessimistic
        
    def expected_time(self):
        """PERT期待値を計算"""
        return (self.a + 4 * self.m + self.b) / 6
    
    def variance(self):
        """分散を計算"""
        return ((self.b - self.a) / 6) ** 2
    
    def standard_deviation(self):
        """標準偏差を計算"""
        return (self.b - self.a) / 6

# 使用例
activity = PERTActivity("要件定義", 5, 8, 15)
print(f"期待値: {activity.expected_time():.2f}日")
print(f"標準偏差: {activity.standard_deviation():.2f}日")
```

### 実際の適用事例

#### 事例1: 新製品開発プロジェクト（製造業A社）
- **課題**: 開発期間の不確実性が高く、納期遵守率が60%程度
- **適用方法**: 全工程にPERTを適用し、バッファーを科学的に設定
- **結果**: 納期遵守率が85%に向上
- **効果**: クリティカルパスの可視化により、重点管理項目が明確化

#### 事例2: システム刷新プロジェクト（金融機関B社）
- **課題**: 大規模プロジェクトで依存関係が複雑
- **適用方法**: PERTとモンテカルロシミュレーションを組み合わせて分析
- **結果**: 当初計画より3ヶ月のバッファーが必要と判明
- **効果**: リスクを考慮した現実的なスケジュール策定が可能に

## 5. メリット・デメリット

### メリット
**1. 不確実性の定量化**
- **理由**: 三点見積もりにより、楽観的・悲観的なケースを考慮できる
- **効果**: より現実的なスケジュール作成が可能
- **具体例**: 新技術開発など不確実性の高いプロジェクトで威力を発揮

**2. リスク管理の向上**
- **理由**: 分散と標準偏差から完了確率を計算できる
- **効果**: 定量的なリスク評価とバッファー設定が可能
- **具体例**: 90%の確率で完了する期限を科学的に設定できる

**3. 重点管理の明確化**
- **理由**: クリティカルパスが明確になる
- **効果**: リソースの効率的配分が可能
- **具体例**: クリティカルパス上の作業に優秀な人材を配置

### デメリット
**1. 見積もりの主観性**
- **理由**: 三点見積もりは結局人の判断に依存
- **影響**: 見積もり精度が低いと結果の信頼性も低下
- **対策**: 過去データの蓄積と専門家の知見活用

**2. 計算の複雑性**
- **理由**: 大規模プロジェクトでは手計算が困難
- **影響**: 専用ソフトウェアが必要、学習コストが発生
- **対策**: プロジェクト管理ツールの活用

**3. β分布の仮定**
- **理由**: 作業時間がβ分布に従うという仮定が常に正しいとは限らない
- **影響**: 実際の分布と乖離する可能性
- **対策**: モンテカルロシミュレーションなど他手法との併用

## 6. 選択・導入の指針

### PERT適用の判断基準
| 観点 | PERT推奨 | CPM推奨 | ガントチャート推奨 |
|------|-----------|-----------|-------------------|
| プロジェクト規模 | 大規模 | 中～大規模 | 小～中規模 |
| 不確実性 | 高い | 低い | 低い |
| 計算負荷 | 高い | 中程度 | 低い |
| 必要スキル | 高度 | 中程度 | 基礎的 |
| リスク評価 | ◎ | △ | × |

### 適用判断フローチャート
1. **プロジェクトの不確実性は高いか？** 
   - Yes → PERTを検討
   - No → 次の判断へ

2. **作業間の依存関係は複雑か？**
   - Yes → CPMまたはPERTを検討
   - No → ガントチャートで十分

3. **定量的なリスク評価が必要か？**
   - Yes → PERT推奨
   - No → CPM推奨

PERTにおける三点見積もりに含まれないものはどれか？

- A) 楽観値
- B) 最可能値
- C) 平均値
- D) 悲観値

<details>
<summary>解答</summary>
<strong>正解: C) 平均値</strong><br>
PERTの三点見積もりは、楽観値（a）、最可能値（m）、悲観値（b）の3つから構成されます。平均値は含まれません。これらの値から期待値を計算する際に(a+4m+b)/6という加重平均を使用しますが、単純な平均値は三点見積もりの要素ではありません。

### 問題2
PERTの期待値計算式として正しいものはどれか？

- A) (a + m + b) / 3
- B) (a + 4m + b) / 6
- C) (a + 2m + b) / 4
- D) (a + 3m + b) / 5

<details>
<summary>解答</summary>
<strong>正解: B) (a + 4m + b) / 6</strong><br>
PERTでは最可能値（m）に重みを置いた加重平均を使用します。この式はβ分布の期待値を簡略化したもので、最可能値に4倍の重みを付けることで、より現実的な期待値を算出できます。A)は単純平均、C)とD)は誤った重み付けです。
</details>

### 問題20
PERTとアジャイル開発を組み合わせる場合の活用方法として適切なものはどれか？

- A) スプリント内の詳細タスク管理に使用
- B) 全体のリリース計画とマイルストーン設定に使用
- C) 日次のスタンドアップミーティングで使用
- D) ユーザーストーリーの見積もりに使用

<details>
<summary>解答</summary>
<strong>正解: B) 全体のリリース計画とマイルストーン設定に使用</strong><br>
アジャイル開発では詳細な計画より適応的な対応を重視しますが、全体的なリリース計画やマイルストーン設定にはPERTが有効です。スプリント内の詳細管理には適しません。
</details>

## 9. 専門用語集

このスライドで使用された専門用語について、アルファベット順・50音順で解説します。

### アルファベット
**AOA (Activity On Arrow)**
- **読み方**: エーオーエー
- **意味**: 作業を矢線で表現するネットワーク図の表記法。ノードは作業の開始・終了点を表す
- **関連用語**: AON、ネットワーク図、ダミー作業

**AON (Activity On Node)**
- **読み方**: エーオーエヌ
- **意味**: 作業をノード（節）で表現するネットワーク図の表記法。現代の主流方式
- **関連用語**: AOA、ネットワーク図、プレシデンス・ダイアグラム

**CPM (Critical Path Method)**
- **読み方**: シーピーエム
- **意味**: クリティカルパス法。確定的な作業時間を用いてクリティカルパスを特定する手法
- **関連用語**: PERT、クリティカルパス、ネットワーク図

**PERT (Program Evaluation and Review Technique)**
- **読み方**: パート
- **意味**: プログラム評価検討技法。作業時間を確率的に扱いプロジェクト完了時間を分析する手法
- **関連用語**: 三点見積もり、β分布、クリティカルパス

### あ行
**アクティビティ**
- **読み方**: あくてぃびてぃ
- **意味**: プロジェクトを構成する個々の作業や活動のこと
- **関連用語**: タスク、作業、WBS

**余裕時間（よゆうじかん）**
- **読み方**: よゆうじかん
- **意味**: 作業の開始や終了を遅らせても全体工期に影響しない時間。フロートとも呼ばれる
- **関連用語**: トータルフロート、フリーフロート、スラック

### か行
**楽観値（らっかんち）**
- **読み方**: らっかんち
- **意味**: PERTの三点見積もりにおいて、最も順調に進んだ場合の所要時間
- **関連用語**: 最可能値、悲観値、三点見積もり

**期待値（きたいち）**
- **読み方**: きたいち
- **意味**: PERTにおいて、三点見積もりから計算される作業の予想所要時間
- **関連用語**: 加重平均、PERT公式、確率分布

**クリティカルパス**
- **読み方**: くりてぃかるぱす
- **意味**: プロジェクトネットワーク図における最長経路。この経路の遅延は全体工期に直接影響する
- **関連用語**: クリティカルチェーン、最長経路、ボトルネック

### さ行
**最可能値（さいかのうち）**
- **読み方**: さいかのうち
- **意味**: PERTの三点見積もりにおいて、最も発生可能性の高い所要時間
- **関連用語**: 楽観値、悲観値、モード

**最早開始時刻（さいそうかいしじこく）**
- **読み方**: さいそうかいしじこく
- **意味**: ある作業を最も早く開始できる時刻。ES（Earliest Start）とも表記
- **関連用語**: 最早終了時刻、最遅開始時刻、フォワードパス

**最遅開始時刻（さいちかいしじこく）**
- **読み方**: さいちかいしじこく
- **意味**: 全体工期を遅らせずに作業を開始できる最も遅い時刻。LS（Latest Start）とも表記
- **関連用語**: 最遅終了時刻、最早開始時刻、バックワードパス

**三点見積もり（さんてんみつもり）**
- **読み方**: さんてんみつもり
- **意味**: 楽観値、最可能値、悲観値の3つの値で作業時間を見積もる手法
- **関連用語**: PERT、楽観値、最可能値、悲観値

**準クリティカルパス（じゅんくりてぃかるぱす）**
- **読み方**: じゅんくりてぃかるぱす
- **意味**: クリティカルパスに次いで長い経路。わずかな遅延でクリティカルパスになる可能性がある
- **関連用語**: クリティカルパス、ニアクリティカルパス

**スラック**
- **読み方**: すらっく
- **意味**: 作業の余裕時間。トータルフロートと同義で使われることが多い
- **関連用語**: 余裕時間、フロート、バッファー

### た行
**ダミー作業（だみーさぎょう）**
- **読み方**: だみーさぎょう
- **意味**: AOA図で作業間の依存関係を表すために使用される、時間ゼロの仮想的な作業
- **関連用語**: AOA、依存関係、ネットワーク図

### な行
**ネットワーク図（ねっとわーくず）**
- **読み方**: ねっとわーくず
- **意味**: プロジェクトの作業と依存関係を図示したもの。PERT図とも呼ばれる
- **関連用語**: PERT図、AOA、AON、プレシデンス・ダイアグラム

### は行
**悲観値（ひかんち）**
- **読み方**: ひかんち
- **意味**: PERTの三点見積もりにおいて、最悪の場合の所要時間
- **関連用語**: 楽観値、最可能値、三点見積もり

**標準偏差（ひょうじゅんへんさ）**
- **読み方**: ひょうじゅんへんさ
- **意味**: データのばらつきを表す指標。PERTでは(悲観値-楽観値)/6で計算
- **関連用語**: 分散、σ（シグマ）、確率分布

**フォワードパス**
- **読み方**: ふぉわーどぱす
- **意味**: ネットワーク図を前から順に計算し、最早開始・終了時刻を求める手法
- **関連用語**: バックワードパス、最早開始時刻、CPM

**フロート**
- **読み方**: ふろーと
- **意味**: 作業の余裕時間。トータルフロートとフリーフロートがある
- **関連用語**: 余裕時間、スラック、バッファー

**分散（ぶんさん）**
- **読み方**: ぶんさん
- **意味**: データのばらつきを表す指標。標準偏差の2乗。PERTでは((悲観値-楽観値)/6)²
- **関連用語**: 標準偏差、σ²（シグマ二乗）、確率分布

**プレシデンス・ダイアグラム**
- **読み方**: ぷれしでんす・だいあぐらむ
- **意味**: AON方式のネットワーク図。作業間の前後関係を表現する図法
- **関連用語**: AON、PDM、ネットワーク図

**β分布（べーたぶんぷ）**
- **読み方**: べーたぶんぷ
- **意味**: PERTで仮定される作業時間の確率分布。左右非対称で現実的な分布
- **関連用語**: 確率分布、正規分布、三点見積もり

### ま行
**モンテカルロシミュレーション**
- **読み方**: もんてかるろしみゅれーしょん
- **意味**: 乱数を用いて繰り返し計算を行い、確率的な結果を得るシミュレーション手法
- **関連用語**: リスク分析、確率分布、シミュレーション

### ら行
**リスクバッファー**
- **読み方**: りすくばっふぁー
- **意味**: 不確実性に対応するために設定する時間的余裕
- **関連用語**: 予備日、コンティンジェンシー、バッファー

### わ行
**ワークパッケージ**
- **読み方**: わーくぱっけーじ
- **意味**: WBSの最下位レベルの作業単位。PERTの対象となる基本作業単位
- **関連用語**: WBS、アクティビティ、作業分解
